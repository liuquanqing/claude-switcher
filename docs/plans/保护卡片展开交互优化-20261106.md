# 保护卡片展开交互优化

范围：Kimi 负责 TerminalProtectionCard 的展开设置、诊断结果、相关帮助弹层及展开收起入口；Codex 提需求与复核。保留顶部两行摘要、账号卡片和现有业务语义。

重点：API 模式下明确展开的是订阅保护设置；已保存作为轻状态，修改后突出保存；诊断主入口、结果与说明保持关联；暂停/启用后台订阅保护操作的层级清楚。减少重复文案，不通过自动保存、默认开启或把未知显示为通过来简化交互。

验证用虚构数据覆盖未检查、通过、失败、修改后旧结果、检查中与已暂停，中英文布局。检查中快照仅在 `_qa` 生成的模型副本放开 checking 属性，模拟渲染状态，不调用真实网络；其他结果来自 demo checkNow。截图与静态动作绑定审查不等于真实代理故障或原生点击验收。

本轮以虚构数据验证后，按已有本地更新授权准备替换 Preview（构建 20261106.8.8），暂不公证或公开发布。安装结果以本地回执为准，不改当前网络、守卫、账号或真实会话。

## 验证修正

首次截图批次因外层命令未在编译失败时停止，错误调用旧渲染器，整批作废。Kimi 补齐了 settings 的返回语句；渲染脚本编译前移除生成的旧可执行文件，新串行入口 `scripts/render-protection-interactions.sh` 使用 `set -euo pipefail` 并逐项验证退出码，记录源码和渲染器摘要，避免旧图冒充新结果。原生产品未受此测试脚本问题影响，本轮未替换应用。

最终验证：完整编译与 400 项控制器/虚构数据回归通过；最终对齐调整后再次完整编译，严格渲染入口生成七种状态的中英文截图，并记录源码/渲染器摘要。已检查实际启停、保存、诊断与折叠的绑定条件；未做真实账号、网络故障或原生点击验收。
