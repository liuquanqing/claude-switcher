# 1.3.6 刷新闭环与应用更新规划

核验日期：2026-11-02（Asia/Singapore）。本文件为下一候选的范围草案，不是发版承诺、已实现说明或对设备的操作授权。续期指 OAuth 登录凭据续期，不涉及订阅续费。

## 当前判断

对外 latest 为 1.3.5；本机先行试用为 1.3.6 RC1，原版、旧候选及原守卫路径保留。当前恢复模块已有 223 项核心测试和 276 项隔离检查，但本轮新增四项复现说明登录、授权、备份、额度之间还有衔接缺口。因此先修复再考虑正式发布，不能把原有测试数量当作整条流程通过。

建议后续候选标为 **1.3.6 RC2**。分两个可单独验收的 slice：A 为刷新与续期闭环，B 为应用检查更新和下载；都完成后才考虑 1.3.6 正式版。若 B 未完成，不能在更新说明声称具备内置更新。

## 价值

用户完成一次登录或授权后，软件能自行跟进状态与额度；普通查看不反复弹系统密码框；手动刷新给出明确结果。后续版本可直接在应用内发现和下载，减少手动找安装包的成本。

## 目标

### A：刷新、授权与续期闭环（优先）

1. **分清数据含义**：保存身份、官方本地报告、在线核验、登录恢复、备份和额度各有结果。保持已有恢复结果类型，复用本轮证据，不另起一套重复状态机。已识别登录不用反复显示常驻核验警告，也不能凭邮箱或元数据标成在线有效。
2. **事件后及时跟进**：外部登录、同账号新凭据、用户授权完成、通过本软件切换／同步完成后，跟进当前身份与额度，不只等待五分钟定时器。继续本地观察；能静默读到的变化不弹窗，不能读到则明确待授权。普通本地身份变化目标在下一次 15 秒观察内处理；仅凭据代次变化最迟在既有 60 秒静默观察中接续，不承诺超越系统可读性的绝对时限。
3. **刷新只完成一轮事情**：需要恢复时最多启动一次恢复用途的官方 CLI；已有结果直接供身份和额度收尾使用。先读回新采样，若缺失／陈旧且当前身份、网络、限流条件允许，补一次静默只读额度查询；不把“命令成功”当成“额度更新”。正常额度刷新不额外启动无关恢复和多次 auth status。
4. **减少重复授权请求**：本轮同一对象的交互读取结果复用；必要的最终身份／凭据版本比较继续保留，优先非交互读回；用户取消、拒绝、锁屏或条目不可读时停止后续交互步骤，不反复弹框。后台无系统弹窗保证仍为硬边界；需要用户操作先在软件内提示，由用户主动继续。官方 CLI 可能具有独立的系统授权，不承诺用一次 LAContext 合并所有系统窗口，也不强制改成指纹。
5. **续期只交给官方程序**：不直接交换当前账号 refresh token，不复制当前登录到另一个 HOME 去并行续期。现有 CLI 自然续期后，优先采纳新版本并完成备份。若备份或核验失败，续办该步骤，不回滚新登录、不再次消耗刷新凭据。只有明确原生失效才提示 `/login`；网络、401/403 单独出现、429、超时不直接判成永久失效。
6. **合理频率**：活跃额度 5 分钟、闲置 15 分钟，显示计时每分钟；账号／登录事件优先接续。新有效登录解除旧的普通认证失败退避，但所有入口都遵守服务端 Retry-After。连续点击与后台、面板唤醒共享在途任务，已有业务操作槽足够时不引入额外锁或重试层。
7. **辅助命令兼容**：统一本次新建 CLI 辅助进程的退出边界，避免软终止后无限等候；只关闭这次辅助进程，不处理既有终端任务。实际额度子进程清理可能使其只读缓存的开关，分别保留禁用遥测、错误上报和升级的配置，不改用户全局环境或代理。
8. **模式与归属**：API／Magpie／CC Switch 接管时不改第三方配置。额度仅落到 UUID＋组织唯一匹配的订阅卡片。外部自行换号不静默重写另一端；发现桌面与 CLI 不一致时保留已存在的显式同步入口，不把所有已运行任务说成同步。
9. **可诊断但不收集密钥**：仅记录本轮动作类别、凭据对象类别、读取次数、结果码、是否启动官方 CLI、耗时和采样是否前进。不记录 token、密码、原始 CLI 输出、邮箱或会话内容；诊断不能额外触发交互式钥匙串读取。

### B：检查更新与应用内下载

- 原生菜单或设置提供“检查更新”，与账号额度刷新分离。后台最多每天轻量检查一次；发现新版提供版本、说明与下载按钮，不自动打开主面板。检查失败安静保留上次结果，手动检查提供原因。
- GitHub Releases 作为公开版本和附件来源，应用内下载适配本机架构的安装包；不向客户端内置 GitHub token、不要求用户登录 GitHub。
- 默认正式通道；预览通道显式选择。正确比较 `1.3.6-rc.1 < 1.3.6`、`rc.2 < rc.10`，结合单调递增 build，不只看当前 CFBundleShortVersionString。忽略草稿、错误平台、缺失文件与降级版本。
- 用户点击后下载，显示进度、取消、失败重试和文件位置。下载成功不等于可安装；校验附件完整性和预期 Developer ID／Bundle ID，按正式通道要求验证公证。校验失败不打开安装包，不清除安全属性或降低系统设置。
- 本 slice 下载完成后打开 DMG，由用户安装；保留“前往 GitHub”回退。**不在这一轮静默替换或自动重启。** 本机先行试用的未公证包不混入正式更新通道。
- 为后续标准自动更新预留 Sparkle 接入评估：签名 feed／归档、客户端公钥、私钥本机保管、守卫稳定路径与升级兼容、切换器正常退出及回滚。不能直接用完整 bundle 覆盖当前承载守卫的旧包后宣称无影响。

## 非目标

- 不做真实登录、真实账号切换、真实会话迁移、断网故障或急停验收。
- 不静默改钥匙串 ACL、不删除原生凭据、不把自有备份改成明文文件，也不承诺免除所有系统密码提示。
- 不实现自有 OAuth 当前账号续期、不自动轮换非活动账号登录、不复制第三方的直接 token 刷新策略。
- 不重写原有整体 UI；前端仍交用户指定作者，Codex 负责后端、分析和审查。
- 不停守卫、不替换守卫文件、不改代理、网络路由、登录项或已安装应用。
- 不把已有网络前置门禁说成 Claude／CLI 运行中的网络层即时阻断；不扩展到所有 CLI 任务。
- 不在规划阶段创建发布标签、Release、Issue 或 MR。

## 验收

全部先用临时 HOME、假 CLI、模拟钥匙串与注入的网络响应。应给底部生产操作链增加测试注入能力，不能依赖 Demo 分支替代真实分支逻辑。

| 场景 | 可观察通过条件 |
| --- | --- |
| 冷启动已有健康 CLI 登录 | 静默识别，不制造登录失效告警；可读条件下自动接续核验，不要求点刷新才能出现保存身份 |
| 外部 `/login`，同一账号／不同账号 | 正确观察变化；同账号新凭据触发收尾，不同账号废弃旧结果；不自动覆盖桌面或运行任务 |
| 原生 CLI 自然续期 | 采纳新凭据；核验与备份后补查一次额度，不恢复旧备份 |
| 用户点击恢复，官方 CLI 已换凭据 | 本轮只跑一个恢复 CLI，身份、备份结果复用；额度采样推进或明确额度失败，不用缓存时间冒充成功 |
| 官方 CLI 成功但未写／未推进额度缓存 | 在允许条件下补一次静默请求；不能卡在“CLI 好了但额度无声不更新” |
| 额度仅有 weekly、五小时为 null | 保持合法缺省，不伪造比例、窗口或倒计时 |
| 额度新请求失败 | 保留同账号旧数据与原采样时间，显示失败原因；不让较旧 CLI 缓存覆盖新样本 |
| 之前认证失败，随后授权完成 | 旧普通退避不阻挡本轮收尾；如果是 429，仍尊重 Retry-After |
| 取消／拒绝授权、锁屏 | 本轮停止交互请求，无重复提示循环；保留登录、备份、会话和 unknown 状态 |
| 授权前／授权后出口不合格或 unknown | 不启动对应认证请求；不把网络问题标成永久登录失效 |
| 原生明确 invalid_grant／Login expired | 仅此版本暂停自动尝试，明确官方 `/login`；重新登录产生新版本后可接续 |
| 核验失败／备份失败后再次刷新 | 只续办缺失步骤，不重复旋转 token，不抹掉原生新登录 |
| 辅助进程超时且忽略软终止 | 在规定 grace 后退出本次辅助子进程；操作结束可退出界面；既有 CLI／Claude／守卫均不被处理 |
| 手动＋后台＋唤醒同时触发 | 同账号请求去重；没有多轮授权或额度请求叠加；账号变化时丢弃旧轮结果 |
| API／自定义目录／第三方接管 | 来源未确认不写登录；订阅额度不记到错误卡片，不拿 API 余额充当订阅 |
| 更新通道与版本比较 | stable 不接预览；预览到同版本正式版识别为升级；草稿、低版本、缺附件不误报 |
| 下载网络中断、取消、错误文件／签名 | 明确可重试、不打开失败文件、不触发安装或应用退出 |
| 下载并验证成功 | 文件位置、版本和校验证据可回读；仅用户确认后打开 DMG；守卫路径、配置与回执不变 |
| 中英文、长文案与窄窗口 | 状态与按钮不截断；不新增常驻长说明；由指定前端作者实现并以假数据截图验收 |

系统真实授权次数、真实续期、Gatekeeper 首次打开和跨版本原位升级需要用户后续实际反馈或另行授权的安全验收，假数据不代替这些结论。

## 风险与冲突

1. 已安装 RC1 与公开 1.3.5 不同，不能只检查 main 或历史 README。应将修复绑定到新候选和测试产物。
2. 本轮实际系统密码弹窗尚未采样，不能承诺“一次授权永远不弹”。Apple 公证与钥匙串授权是不同层次。
3. 官方 CLI 不提供已验证的全局禁止 macOS 授权弹窗契约；不能为实现“全自动续期”破坏静默优先要求。
4. 项目尚未登记 delivery profile，草案不可机械确认为已冻结交付；测试与真实环境证据仍有边界。本文件不会自行建立确认权威。
5. Github／Sparkle 的自动更新能力不证明本项目守卫兼容；自动安装独立于本次检查与下载。

## 待决

无须用户补充账号、密码、令牌或真实会话。当前草案待确认事项是实现范围与优先级；建议按 A→B。版本号为规划建议，正式 tag 必须在实现与验收后再决定。

## 下一门

确认范围后先把四项复现转成修复目标，再实现最小闭环并做生产入口的可注入回归；通过后增加检查更新／下载，产出指定作者的界面截图和签名候选。测试通过不自动授权安装、守卫交接或正式发布。
