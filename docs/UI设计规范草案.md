# Claude Switcher macOS UI 设计规范（草案）

状态：规范仍为设计草案，未全局实施。仅更新窗口主按钮已尝试显式使用深色文字/图标；实际渲染、各状态对比度与真实辅助功能表现均待验证。适用于当前暖灰深色、Claude 暖橙的菜单栏工具及其独立更新窗口。

本规范首先约束新改动，不要求立刻重绘主界面。账号卡的层级、当前账号暖色描边、额度数字与状态色、卡片内切换交互应予保留。第一处验证范围仅放在“软件更新”窗口；本次只尝试主按钮的深色标签，验证通过前不推广为全局换色。

## 1. 当前“下载更新”按钮判断

**不需要因为疑问就把品牌橙改成蓝色；需要优先验证并可能修正的是按钮文字/图标颜色，而不是橙色底本身。**

- `App/ApplicationUpdateViews.swift:462-475` 使用原生 `.borderedProminent`、`.tint(.claude)` 和 semibold 文字，并在 `Label` 上显式设置 `Color.bg`。橙色表示当前唯一主操作，按钮层级合理，也延续 `App/Views.swift:18` 的品牌色 `#D97757`。
- macOS 的一致性还来自原生控件形状、键盘焦点、按下反馈和布局，不等于所有主按钮必须是蓝色。没有“下载按钮在业内必须是某色”的规则。
- 更新可用与下载中使用橙色；失败状态使用 `#E5B454` 黄色、三角形图标和明确文字，重试仍是主操作。这个分工合理，不能把“下载/重试”误作删除或危险操作。
- 更新窗口主按钮已显式指定 `Color.bg`，但原生 `.borderedProminent` 的实际合成与状态表现不能仅凭源码确认，因此**不能宣称实际按钮文字对比度或真实辅助功能已经通过**。截图可用于观察层级，不能替代取色和真实状态验证。
- 下载按钮使用 `.callout` + semibold，不按 WCAG“大字”处理；其文字目标应为 **4.5:1**，不能只满足 3:1。

本次局部验证保留 `#D97757` 橙底，在 `primaryAction` 的 `Label` 上采用现有 `Color.bg`（`#1C1B19`）深色文字与图标；这对实色的计算对比度为 **5.51:1**。是否可在所有原生状态中稳定实现，仍须后续在更新窗口实测。

## 2. 色彩 tokens 与使用边界

### 2.1 现有实色 token

以下值来自 `App/Views.swift:12-21`，不是另起一套 palette。

| 语义 token | 当前值 | 用途 | 禁止/限制 |
| --- | --- | --- | --- |
| `background` / `bg` | `#1C1B19` | 窗口与弹层底色 | 不作为普通正文色，橙色按钮上的深色标签除外 |
| `surface` / `card` | `#262522` | 卡片、页脚、状态区 | 不以透明度随意叠加到无法追踪的底色 |
| `surfaceRaised` / `cardHi` | `#2D2A26` | 当前账号卡、局部抬升面 | 抬升不代表可点击 |
| `border` / `stroke` | `#3A3833` | 分隔线、卡片描边、中性按钮底 | 低对比度时只作装饰，不能独自承担控件边界或焦点提示 |
| `textPrimary` / `txt` | `#F2EFE8` | 标题、正文、重要数值 | 小字号时不要直接放在橙底上 |
| `textSecondary` / `sub` | `#A39D92` | 辅助说明、时间、纯图标 | 叠加 opacity 后须重新算对比度 |
| `accent` / `claude` | `#D97757` | 品牌、唯一主操作、当前账号标记、进行中的品牌状态 | 不表示警告或删除；同屏不多处争抢主按钮层级 |
| `success` / `good` | `#6CC57C` | 已完成、已验证、充足额度 | 必须同时有文字或图标，不只显示绿色 |
| `warning` / `warn` | `#E5B454` | 可恢复的失败、需注意、额度偏低 | 不用作主按钮品牌色；配三角形或明确说明 |
| `danger` / `bad` | `#E5675A` | 真正破坏性操作、严重错误、额度很低 | 不用于普通下载、重试、取消下载或“退出/Quit” |

`primary` 是按钮角色，不是另一个颜色：更新窗口的主按钮使用 `accent`；危险主操作只有确属破坏性流程时才使用 `danger`，并需确认文案。

### 2.2 disabled token

当前代码主要用整个控件 `.opacity(0.45)` 表达禁用，例如 `App/Views.swift:193-196`，并没有独立 disabled 色值。草案先将其记录为：

- `disabled = enabled 控件整体不透明度 45%`，叠加在原控件及其父背景上；它是状态 token，不是新色相。
- 禁用态按 WCAG 的例外处理，不拿其低对比度数值宣称“正文达标”，也不应让禁用文字承载用户必须阅读的错误原因。
- 禁用必须同时失去 hover/pressed 动作，并保留可识别的形状与标签。不可用原因需要可操作的帮助或邻近说明。
- 后续若改为固定 disabled 前景色，必须按实际父背景逐一测量，不能把 `sub.opacity(0.45)` 当普通辅助正文使用。

## 3. 可执行的对比度目标与源码计算

### 3.1 验收目标

- 普通正文、按钮标签、辅助说明：至少 **4.5:1**。
- 大字（至少 18 pt regular，或至少 14 pt bold）及非文本控件、关键图标、焦点指示：至少 **3:1**。
- disabled 可按 WCAG 例外，但仍须做可用性检查；装饰性分隔线不要求 3:1，前提是不承担识别控件或状态的唯一作用。
- 任何状态都不能只由颜色区分；success/warning/danger 同时提供文字，必要时提供不同图标。
- 以下为 sRGB 相对亮度公式计算，不是屏幕取色或真人验收。实色组合可作为源码层面的数学检查；alpha 合成、原生样式和所有交互状态仍须实机复验。

### 3.2 实色 token 数学对比度

| 前景色 | 对 `bg #1C1B19` | 对 `card #262522` | 对 `cardHi #2D2A26` |
| --- | ---: | ---: | ---: |
| `txt #F2EFE8` | 14.99:1 | 13.35:1 | 12.43:1 |
| `sub #A39D92` | 6.39:1 | 5.69:1 | 5.30:1 |
| `claude #D97757` | 5.51:1 | 4.91:1 | 4.57:1 |
| `good #6CC57C` | 8.13:1 | 7.24:1 | 6.74:1 |
| `warn #E5B454` | 9.01:1 | 8.02:1 | 7.47:1 |
| `bad #E5675A` | 5.26:1 | 4.69:1 | 4.36:1 |
| `stroke #3A3833` | 1.47:1 | 1.31:1 | 1.22:1 |

结论：现有实色正文和状态色在相应暖灰底上大多达到普通文字 4.5:1；`bad` 在 `cardHi` 上只适合已达大字/非文本 3:1 的内容，不应未经验证用于该背景上的小正文。`stroke` 不能单独作为关键控件边界或焦点色。

### 3.3 橙底按钮的候选组合

| 文字/图标色 | 橙色背景 | 计算值 | 判断 |
| --- | --- | ---: | --- |
| `#FFFFFF` | `#D97757` | 3.12:1 | 不满足普通按钮文字 4.5:1 |
| `#F2EFE8` | `#D97757` | 2.72:1 | 不满足普通文字 4.5:1，也不满足 3:1 |
| `#1C1B19` | `#D97757` | 5.51:1 | 候选组合数学达标；实际状态待验 |
| `#000000` | `#D97757` | 6.73:1 | 数学达标，但优先用主题深色 `#1C1B19` 保持暖灰体系 |

这里不认定更新窗口原生按钮此前的实际前景就是白色。上表的意义是：若实测为白色或 `txt`，应修正；`bg` 已从候选进入更新窗口这一项的局部尝试，仍未完成实际验收。

### 3.4 透明度不能省略复算

以下按 sRGB 通道直接 alpha 合成估算并取约数；实际渲染仍待验。

| 源码组合 | 合成后约值 | 对实际父背景 | 普通文字判断 |
| --- | ---: | ---: | --- |
| `sub 86%` / `card` | `#928C82` | 4.60:1 | 仅勉强达到，渲染待验 |
| `sub 86%` / `cardHi` | `#928D83` | 4.33:1 | 不足 4.5:1 |
| `sub 80%` / `card` | `#8A857C` | 4.18:1 | 不足 4.5:1 |
| `sub 80%` / `cardHi` | `#8B867C` | 3.95:1 | 不足 4.5:1 |
| `claude 85%` / `card` | 约 `#BE6B4F` | 3.95:1 | 不足 4.5:1 |

规则：普通信息文字优先使用不透明的 `txt` 或 `sub`；不能用降低 opacity 的方式制造“次要”，再沿用原色名的通过率。

## 4. 字号与字重层级

保留菜单栏工具的紧凑密度，不以“大标题、大留白”重做账号卡。

| 层级 | 草案规格 | 用途与现状 |
| --- | --- | --- |
| 独立窗口标题 | `.title3` semibold | 更新窗口已采用 |
| 主界面身份标题 | 19 pt bold | 当前账号/模式标题已采用，只保留一个视觉中心 |
| 大数值 | 22/28 pt bold，rounded | 账号卡额度数字已采用；可按大字 3:1 检查 |
| 区块/卡片标题 | 12–13 pt semibold | CLI 标题、更新状态、发布说明标题 |
| 正文与普通按钮 | 11–13 pt regular/medium；主按钮 semibold | 更新窗口用 `.callout`，紧凑主界面可保持较小档，但不继续缩小 |
| 辅助说明与元数据 | 10–11 pt regular/medium | 时间、帮助、文件信息；仍需 4.5:1 |
| 极小文字 | 9–9.5 pt 仅限短、非关键元数据 | 不扩展用于关键说明；现有关键重置时间/失败缓存信息应列入局部提升 |

字重规则：正文 regular；标签与次要按钮 medium；标题和主按钮 semibold；bold 只给身份标题和关键数字。不要靠继续加粗补偿低对比度，也不要让所有辅助文字都 semibold。

## 5. 按钮层级

### 5.1 主按钮

- 每个独立窗口、每个当前操作上下文**最多一个实底 accent 主按钮**。
- 更新窗口现有行为符合这一原则：可用时为“下载更新”，失败时为“重试”，就绪时为“打开安装包”；“在 Finder 中显示”为次按钮。
- 使用动词说明下一步，保留图标与文字；主按钮 semibold，普通文字对比度至少 4.5:1。
- 优先保留原生 `.borderedProminent` 的焦点、键盘和按下行为；tint 不应取代状态验证。

### 5.2 次按钮

- 使用 `.bordered` 或中性表面，medium 字重；不与主按钮争夺 accent 实底。
- “取消下载”“在 Finder 中显示”保持次层级。取消下载不自动等于危险操作；若会删除重要数据，应另行明确后果。
- 账号卡的“切换”继续使用中性 `Pill`，当前账号使用状态标记，不把每张卡都变成橙色主按钮。

### 5.3 纯图标按钮

- 只用于高频、低层级、图标含义明确的动作；陌生动作使用文字标签。
- 默认 `sub`，hover 可变为 `txt` 并出现中性底；关键图标对相邻背景至少 3:1。
- 组件契约必须同时包含本地化 `help` 与明确的 `accessibilityLabel`；tooltip 不能代替辅助功能名称。
- 设置继续使用单个 gear，将“检查更新 / 登录时启动 / 语言”收纳在菜单中。**不得回退为三个常驻图标。**

## 6. 圆角、间距与点击面积

- 小按钮/标签圆角：**6–8 pt**；卡片：**12–14 pt**；独立窗口图标容器：约 **12 pt**。现有账号卡 14 pt、更新卡 14 pt、Footer 图标 7 pt 均在此范围。
- 以 **4 pt** 为间距基准；新增布局优先 4/8/12/16/20 pt。紧凑卡片内部可用 8–10 pt，区块间可用 12–14 pt，独立窗口外边距可用 20 pt。保留现有 10/14 pt 节奏，不为“凑网格”重排主界面。
- 纯图标点击区域至少 **28 × 28 pt**，优先 32 × 32 pt；相邻目标间至少 6 pt 或具备等效无重叠间隔。当前 `FooterIcon` 为 28 × 28 pt，是应保留的紧凑基线。
- 主/次按钮目标高度建议至少 **32 pt**，通过 padding/hit area 实现，不只放大图标。原生 regular 的实际高度与点击区域待验。
- 弹层内的 24 pt 关闭按钮只可作为已有紧凑例外列入后续评估，不向外推广；不套用 iOS 的 44 pt 标准破坏 macOS 密度。

## 7. 交互状态

| 状态 | 必须表现 | 验收点 |
| --- | --- | --- |
| 默认 | 层级、标签、图标清楚 | 文字 4.5:1；关键图标/边界 3:1 |
| hover | 中性底或前景增强，不改变布局尺寸 | 不能只让极浅颜色变得更浅；移出后恢复 |
| pressed | 有明确压下/深浅反馈，保持标签可读 | 不只复用 hover；文字与图标重新测对比度 |
| keyboard focus | 保留系统焦点环；自定义控件提供等效清晰焦点 | 焦点指示对相邻背景至少 3:1，不被橙底或裁切吞掉 |
| loading | 显示进度/旋转指示与进行中文案，防止重复提交 | 保持按钮区域稳定；只禁用相关动作，下载时“取消下载”仍可用 |
| disabled | 形状与标签仍在，无 hover/pressed 动作 | 当前 45% opacity 仅作状态候选；不可用原因另可获知 |
| success | `good` + 对勾/完成文字 | 不只变绿；不永久占用主按钮注意力 |
| warning/failure | `warn` + 警告图标 + 可恢复说明 | 重试可为 accent 主按钮；失败本身不伪装成 danger |
| danger | `danger` + 破坏性动作明确文案与确认 | 不因“取消”或“退出”字样自动使用红色 |

当前原生主/次按钮可继承一部分系统状态；`FooterButton`、顶部桌面控件、退出按钮等 `.plain` 自定义按钮在指定源码中主要显式实现了 hover/disabled，pressed 与键盘 focus 没有统一的组件级表达。后续应先验证实际系统行为，再补齐组件契约，而不是凭截图认定键盘一定不可用。

## 8. 中英文、help 与图标标签

- 中文与英文都以完整文案布局，不为保持单行而截断按钮；按钮宽度随内容增长。
- 保留更新窗口 `ViewThatFits` 的横排/纵排回退，以及发布说明标题/GitHub 入口的宽度回退。至少检查最小窗口宽度 500 pt、中文与英文、失败长说明和“Show in Finder + Open Installer”组合。
- help 解释结果、影响或不可用原因，不只是重复按钮名；截断的账号/文件信息应能查看完整内容。
- 所有纯图标按钮同时具备本地化 help 和 accessibility label。带文字按钮的辅助功能名称应与可见动作一致。
- 状态图标与文字颜色一致表达语义：品牌下载用箭头，成功用对勾，警告用三角形；危险操作不使用普通下载箭头冒充。
- 页脚按钮名称固定为 **“退出 / Quit”**，继续使用 `footer.quit`，不是“退出界面”。其中性样式与“已启用的保护继续运行”的 help 保留。

## 9. 现有实现：一致处与具体问题

### 9.1 已经一致、应保留

1. `App/Views.swift:12-21` 已集中定义暖灰与语义色，更新窗口复用这些 token，没有另起蓝色体系。
2. 更新状态色与图标对应清楚：可用/下载为 accent，最新/就绪为 success，失败为 warning（`App/ApplicationUpdateViews.swift:172-187`）。
3. 更新窗口主按钮使用原生 prominent，次按钮使用 bordered；每个阶段只有一个主操作，失败重试没有错误地使用 danger。
4. 更新窗口的 20 pt 外边距、14 pt 卡片圆角、14 pt 卡片内边距和 10–14 pt 区块节奏一致。
5. `FooterIcon` 的 28 pt 点击区域、`sub → txt`、透明底 → 中性 hover 底已经形成可复用模式。
6. 设置 gear 已收纳更新、登录项与语言；底部保留独立“退出/Quit”。不恢复三个常驻设置图标，也不改 Quit 名称。
7. 当前账号卡的 `cardHi`、暖橙细描边、当前标记、额度大数字与中性切换按钮是产品辨识度所在，不做全局扁平化或换色。

### 9.2 源码可明确指出的问题

1. **添加账号主按钮的小字对比度不足。** `App/Views.swift:806-811` 明确使用 10.5 pt semibold、`.white` 文字和 `Color.claude` 实底；`#FFFFFF / #D97757 = 3.12:1`，低于普通文字 4.5:1。这是源码组合问题，但本轮不修改，也不借此全局换色。
2. **部分小字通过 opacity 变次要后跌破目标。** 顶部“当前账号”使用 `claude.opacity(0.85)`、9.5 pt（`App/Views.swift:311-323`），在 `card` 上估算约 3.95:1；用量重置时间使用 `sub.opacity(0.86)`、9 pt（`App/Views.swift:565-568`），在 `cardHi` 上约 4.33:1；缓存/更新时间使用 `sub.opacity(0.8)`（`App/Views.swift:621-639`），在 `card/cardHi` 上约 4.18/3.95:1。后续应优先去掉正文透明衰减或提升字号，而不是整体提亮界面。
3. **`FooterButton` 的辅助功能名称没有统一进入组件契约。** `App/Views.swift:848-860` 只统一接收 icon/help；设置 gear 在外层补了 accessibility label，但指定源码中的目录、复制、刷新调用未见同样的显式标注。实际 VoiceOver 朗读待验，组件接口缺口明确。
4. **自定义按钮状态规格不完整。** hover 与 45% disabled 较一致，但 pressed/focus/loading 没有共享组件级规则。真实键盘与点击表现尚待验，不把“源码未自定义”直接等同于“系统完全无反馈”。
5. **9–9.5 pt 被用于部分实际信息，不只是装饰。** 重置时间、缓存失败原因等需要可读；后续局部调整时应先保证信息完整，再维持卡片高度，而非进一步缩字。

### 9.3 待验，不能写成已通过或真实缺陷

- 更新窗口原生 prominent 按钮的实际前景色、填充色、hover/pressed/focus/disabled 对比度。
- 键盘导航、VoiceOver 名称、help 是否在实际系统中完整呈现，以及真实点击面积。
- 截图中 `_qa/rc2/images/update-available-zh-500.png` 的发布说明滚动区空白属于 ImageRenderer 离屏渲染边界；原生 Host 截图能显示发布说明，**不得将这张空白图记录为真实产品缺陷**。

## 10. 推荐方向、必要备选与推广门槛

### 推荐方向：更新窗口内验证“原生主按钮 + 橙底深字”

- 保留 `#D97757`、原生 prominent 层级、下载箭头及现有多语言布局。
- 候选文字/图标使用 `#1C1B19`，实色计算 5.51:1；不以这张计算表替代实际状态验收。
- 在更新窗口验证默认、hover、pressed、focus、checking/downloading、disabled，以及中文/英文最小宽度。
- 只有实际取色和交互均通过，才考虑把相同规则局部应用到其他 accent 实底按钮；账号卡布局与交互不重做。

### 必要备选：仅当原生 prominent 无法稳定实现可读前景或清晰焦点

在**更新窗口主按钮范围内**使用 `cardHi #2D2A26` 实底、`claude #D97757` 文字/图标与同色清晰边框。文字和边框对该底色的实色计算均为 **4.57:1**，分别覆盖普通文字 4.5:1 与非文本 3:1 的候选目标；hover/pressed/focus 仍须另验。它仍保持暖橙品牌，不因备选而随意换蓝，也不全局替换 macOS 主色。

### 推广前最低验收记录

1. 在原生 Host 窗口对实际渲染色取样，记录默认及所有状态的对比度，而非只记录源码色值。
2. 完整操作一次键盘 focus/激活，并检查 VoiceOver 标签与 help；本轮未执行这些验证。
3. 中文、英文、500 pt 最小宽度及长失败信息均无截断，横排转纵排不覆盖内容。
4. 原生 Host 检查发布说明滚动与内容；ImageRenderer 只作离屏参考，不能把空白滚动区当产品回归。
5. 先评审更新窗口结果，再决定是否形成共享按钮组件或修正其他局部小字；禁止以本草案直接触发全局改色。
