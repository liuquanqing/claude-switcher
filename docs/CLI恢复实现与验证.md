# CLI 旧备份恢复：实现与验证

核验日期：2026-10-31（Asia/Singapore）。用户已授权按规划开发。本文记录本地候选实现，未代表已安装、已发布或真实账号在线恢复通过。范围依据：[规划草案](plans/CLI登录备份与联合切换修复方案.md)。

## 已实现

- 联合切换与“同步 CLI”共用 `CLIBackupRecovery.prepare`。目标旧备份过期且没有可信核验记录时，进入官方 CLI 恢复流程。
- 当前默认 CLI 已是目标时优先保留当前登录；有效备份不续期。已有可信核验记录且含刷新凭据的过期备份，保留原来的 `storedLogin` 路径，由 CLI 后续刷新，界面仍区分待核验。
- 旧备份恢复使用独立原生配置目录，不临时切换默认 CLI。运行本机官方 `claude -p /usage`，不实现或调用第三方 OAuth token 刷新接口。
- 官方输出不是成功凭证：回读实际凭据，再通过现有在线 profile 核验账号及组织，保存目标备份并回读后才进入原联合事务。
- 恢复期间默认登录或目标备份变化时停止，不覆盖其他程序的新登录。
- 凭据轮换后保存失败，保留私有恢复目录及原生凭据；重试优先使用已有结果，不能用旧 seed 覆盖新凭据。
- 工作区以账号、组织、原备份摘要共同定位。旧一轮清理失败不阻断同账号后续新备份，也不自动删除旧恢复材料。
- 初始化中断时，只补齐仍与原 seed 一致的缺失字段；不覆盖未知或已变化的凭据。
- 清理前先把新凭据写回私有文件，再删除本次独立钥匙串项。清理失败不撤销已经核验并保存的备份。
- 工作区 0700、凭据文件 0600，并排除自动备份。该工作区是本机明文原生凭据存储，安全强度不同于只存在钥匙串；失败材料不会被自动清理。
- 联合切换要求目标有 CLI 登录，不再因目标缺失而清空当前默认 CLI。用户仍可显式选择仅切桌面，但不会显示两端已同步。
- 系统钥匙串授权与官方登录续期分开处理，不扩大 ACL，也不承诺应用更新后永不弹密码框。

## 官方 CLI 原生契约检查

使用本机 Claude Code 2.1.314，虚构 HOME、独立配置目录、假 access/refresh token、假 UUID/组织及 `example.test` 邮箱：

1. `auth status`：exit 0，报告 claude.ai，配置目录、邮箱和组织全部匹配夹具。证明隔离文件登录读取与本地报告路径可用，不证明令牌真实有效。
2. 使用完整生产 argv 的 `-p /usage`：设置 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`，只读提前写入的虚构缓存。exit 0、`is_error=false`、返回假数据、`total_cost_usd=0`。证明本版本支持这些参数，`/usage` 是可本地执行的命令。

**未执行真实在线续期。** 未验证服务端是否仍接受用户旧 refresh token，也未用真实钥匙串创建/删除来验证 macOS 原生续期转存。服务名派生依据上游源码；该生产行为仍需候选的用户正常操作验证。不能把上述离线检查写成端到端续期成功。

## 测试结果

- Core：195 项通过。新增恢复用例覆盖旧备份升级并 A→B→A、可信过期备份不强制续期、当前登录优先、无刷新凭据、原生命令失败、身份/组织错配、远端核验失败、并发外部修改、写入/回读失败和清理失败。
- Controller/adapter：186 项通过。新增夹具覆盖作用域钥匙串优先、轮换后保留/重试、非零退出后的恢复、退出 0 但无新凭据、环境变量隔离、模拟 CLI argv/cwd、半初始化、未知变化拒绝、新备份不被旧清理状态阻断、权限/备份排除和超时。
- 最终重复检查发现并修复 `Process.waitUntilExit()` 在异步任务换线程后不返回的问题，改用退出回调；新增连续 8 次快速退出夹具通过。
- 超时只终止本次创建的进程：45 秒后 TERM，5 秒宽限后必要时 KILL。提示可能需要重新登录，不保证保留材料足以恢复服务端已轮换的凭据。测试只杀模拟进程。
- 无真实账号作为测试夹具；没有执行真实账号切换、关停 Desktop、断网、节点切换或守卫故障测试。

## 使用与交付边界

正常使用不要求手填 token。只有缺失或无法恢复的登录才需用户在官方 CLI 完成登录；本轮没有另做账号登录向导或自动替用户走浏览器授权。

已有普通 CLI 任务不会被关闭；“默认登录已同步”不能保证每个自定义 shell、API 模式、项目认证或运行中进程都同步。API/未知来源仍使用原有边界，默认账号的检查不能覆盖这些来源。

本地候选先供审核。原版和 Applications 中现有版本未替换，守卫未停用；未创建 tag、Release 或上传 DMG。真实旧备份恢复若要验证，应由用户在候选中执行一次正常切换并观察结果，不进行故障注入。
