# 会话迁移交互设计

## 本轮收敛范围

- 可点击稿：`docs/prototypes/session-transfer.html`；原生视图：`App/SessionTransferView.swift`。两者沿用同一套“来源 → 目标、搜索、会话清单、底部复制”单页结构，不新增向导、大预览页或独立结果页。
- 新增 `App/SessionTransferLocalization.swift` 提供原生视图本地化；主面板仍使用 `App/Views.swift` 现有 `doc.on.doc` 入口，不重排账号或保护界面。
- 默认中文，提供轻量中英文切换。真实会话标题、项目名、项目路径、档案名和本地指令内容不随界面语言翻译。
- 原型内嵌 fixture 保持不变，所有原型“写入”仍只改变虚构内存；原型不是生产实现。
- 原生只消费 `SessionTransferController` 的公开契约。本轮未修改控制器、Core、入口开关、测试、Package 或构建脚本，原生可编译不等于真实会话迁移已验收。

## 1. 清单是唯一主角

产品框内只保留完成复制所需的内容：

1. 标题栏：正确的网页返回入口、窗口标题和语言切换。
2. 来源与目标选择器；仅多空间一侧需要时再出现空间选择器。
3. 搜索与“更新已有会话”开关。
4. 当前结果全选、重新检查、已选/显示数量。
5. 具体会话清单。
6. 底部已选摘要与复制按钮；只有操作后才在两者之间出现一条紧凑结果。

移除了常驻产品说明、步骤条、证明/轮数字段、收据编号、内部状态和逐项折叠。不可复制的原因只在目标领先、分支冲突、原文缺失、身份变化或证据不足等相关行直接显示一句，不用折叠代替信息架构。

### 会话识别与选中反馈

每一行固定优先展示：

- 完整会话标题，使用列表中最高文字层级；
- 项目名，紧跟标题但不抢视觉；
- 完整项目路径，允许换行，不靠省略隐藏身份；
- 更新时间，独立右对齐，窄屏移到信息下方。

有效行可整行点击，也可用复选框选择。选中行同时使用陶土橙左侧标记、浅色底和勾选状态，不能只靠复选框的小变化辨认。底部继续复述“已选：具体标题”或“已选：首个标题等 N 项”，搜索、取消确认和查看备份后仍保留合理选择。

复制完成后清空本次选择，目标行按最新状态重新判定，避免返回或重复点击造成意外重复复制。失败但没有留下更改时保留有效选择，便于用户明确重试；不会自动重试。

## 2. 入口与返回不是复制动作

### 网页原型

标题栏的“功能说明”链接指向真实宿主入口：

`../功能对比说明.html#features`

它不是“返回账号”，不调用 `window.close`，也不依赖普通标签页允许脚本关闭窗口。无论当前是选择、复制结果还是撤销/恢复结果，返回都只是宿主导航，本身不执行复制、撤销、恢复或结束记录。

浏览器回返统一在 `pageshow` 处理，不能以浏览器恢复的下拉框值作为状态：

- 普通首次加载、重新加载及非 bfcache 回返（`event.persisted === false`）明确重建 `normal` 初始内存，再重绘来源、目标、空间和框外情形控件。旧演示情形不跨文档恢复，因此不会出现内存为 Personal、界面却显示 API 的混合状态。
- bfcache 回返（`event.persisted === true`）保留原 JavaScript 内存，不调用 `resetDemo`，只按唯一 `state` 重绘全部控件。原有选择、语言、复制结果和 `needsRecovery` 锁定继续有效。
- 两条路径都只同步界面，不调用复制、撤销、恢复或结束记录；不使用浏览器存储，也不增加持久化。

### 原生窗口与控制器生命周期

原生从现有账号主面板的 `doc.on.doc` 进入同一复制子窗口，不重做账号切换或保护界面：

- `CopyThreadsView` 使用 `@ObservedObject` 注入控制器，同时保留 `init(store:)`；`CopyWindow` 以 `ObjectIdentifier(store)` 缓存同一 Store 对应的控制器，避免重进窗口丢失选择、结果或未完成日志。
- 空闲时，“返回账号”和窗口红点都隐藏子窗口并调用 `store.returnToAccounts()`，不销毁窗口或控制器。红点由 `NSWindowDelegate.windowShouldClose` 统一接管。
- `isWorking` 时两种返回都阻止，只在窗口标题栏短暂显示“正在处理，请等待完成后再返回”；关闭不被解释为取消已执行动作，也不终止任何进程。
- 再次从主入口进入时刷新控制器数据，保留仍然合理的选择、语言和操作状态；后端仍为 `needsRecovery` 时继续锁定对应目标，返回不能解锁。
- 窗口标题保留正常/演示标识，语言切换只更新对应标题，不把生产窗口标成演示。

网页中的相对链接只承担说明页导航，不用网页导航模拟原生引擎或收据生命周期。

## 3. 默认只新增，更新显式开启

- `updateExistingDefault` 保持 `false`，默认只允许新增。
- 用户显式开启“更新已有会话”后，才解锁后端已判定可更新的行；开关不自动勾选任何会话。
- 关闭开关会取消不再有效的更新选择，保留有效新增选择。
- 目标领先、分支冲突、原文缺失、目标身份变化和接续证据不足始终禁选。
- 搜索匹配标题、项目和路径，不清除筛选外选择。全选/取消全选只影响当前筛选中可处理的行。
- 切换账号或空间会清空旧绑定下的选择；单空间自动选定，多空间必须显式选择，不猜测默认空间。

视觉简化不减少这些安全判断，但不把判断过程、证明字段或轮数对比变成产品主内容。

## 4. 复制、覆盖确认与结果返回

### 只新增

点击底部“复制 N 项到目标”直接执行，不增加预览步骤。执行前重新核对来源、目标、空间和选择；目标已变化则整批不写入，并保留其他仍有效的选择。

### 包含已有会话更新

只有实际包含更新时才出现确认框：

- 明确新增与更新数量；
- 列出将被更新的具体会话标题、项目和路径，而不只给一个总数；
- 说明覆盖前自动备份；
- “备份并复制”才执行，“取消”、Escape 或点击遮罩均零写入并返回原清单，保留全部有效选择和开关状态。

### 完成与失败

结果不替换清单，也不自动跳转：

- 复制完成：显示备份已保存、复制到哪个目标，以及本次具体会话名称；提供查看备份和撤销。
- 备份失败：明确未开始复制、目标未改，保留有效选择。
- 写入失败但回滚完成：明确已恢复复制前状态，不冒称复制成功。
- 撤销：确认框列出本次涉及的具体会话；只有所有项目都没有后续变化时才恢复。任一冲突则整批不写入，保留外部新进展。
- 撤销完成或冲突后仍回到同一清单与紧凑结果，不出现独立结果页。

## 5. 查看备份只读

“查看备份”打开按需摘要，列出本次具体会话的标题、项目、路径，以及“新增前不存在”或“已保留覆盖前版本”。不显示收据编号、内部状态码、CLI 段、证明或轮数。

关闭备份只返回触发前的清单/结果，焦点回到触发控件；不恢复、不撤销、不复制，也不改变 `needsRecovery` 锁定。备份失败时只说明备份不可用及目标未修改。

## 6. 未完成恢复与明确异常出口

### 常态恢复

只有 `needsRecovery` 时出现“处理未完成”。此时清单仍可见，但新复制暂停。

处理框列出涉及的具体会话，并提供：

- 查看备份后返回，仍保持锁定；
- 取消恢复，仍保持锁定；
- 确认恢复，只按备份恢复本次操作前状态，不自动重试复制；
- 恢复完成后才解除锁定，回到同一清单，仍需用户主动发起下一次复制。

恢复前和确认时都把目标当前内容与未完成时的现场快照逐项比较。若外部已有新进展，停止整批恢复，不覆盖任何外部内容，并保持 `needsRecovery`。

### 保留现状并结束记录

仅在 `needsRecovery` 的处理框内，以低强调三级入口提供“保留现状并结束记录”；主界面和其他操作不增加此动作。

该入口还需一次明确确认，说明：

- 不恢复会话；
- 不覆盖目标的新进展；
- 保留当前数据，不主动删除已有备份，但不承诺缺失或损坏的备份仍可用；
- 只结束这条未完成记录。

从异常确认返回时回到恢复处理框，而不是直接解锁。确认结束后结果显示“已结束未完成记录”和“未恢复或覆盖任何内容”，不能使用“恢复完成”或成功语义。目标内容不作写入；若后端明确返回“备份缺失或无法核对”，结果保留该异常原文，不被通用保留文案遮盖。仅清理已经无效的选择，之后的新复制必须由用户重新主动执行。

## 7. 演示控件与产品界面分离

窗口外只保留一组低强调演示控件，并统一标注为“产品框外控件、虚构内存、不是产品界面”。产品框内不再重复虚构数据或离线声明。

除 fixture 既有情形外，在以下情况显示对应框外动作：

- 目标桌面运行中：模拟用户自行退出 Claude；之后仍需点击产品内“重新检查”。
- `needsRecovery`：模拟目标出现外部新进展，用于验证恢复不会覆盖它，以及异常结束路径。

切换演示情形会重置内存，但保留语言选择。该重置是演示工具，不属于产品返回或恢复流程。

## 8. 原生统一模态与本地指令

原生确认、备份和指令共用一个可控 `.sheet`，不使用两个互相覆盖的 `.alert`：

- `SessionTransferConfirmation.kind` 决定本地化标题、说明和按钮；`items` 直接列出具体标题与完整路径。普通新增仍由底部按钮直接复制，只有涉及更新才确认。
- 显式取消普通确认调用 `cancelConfirmation()`；SwiftUI 自动 dismiss 只调用 `dismissConfirmation()`，避免把待执行动作误清或误执行。确认按钮是唯一 `confirmAction()` 调用入口，不设默认写入快捷键，初始焦点位于取消/关闭。
- 异常保留的“返回”调用 `requestRecovery()` 回恢复处理框；只有确认才走 `confirmAction()`。备份关闭只调用 `dismissBackup()`，不触发恢复或打开 Finder/shell。
- 底部次级“复制给 Claude”仅在 `canExport` 时可用，调用 `exportInstructions()`。`handoffInformation` 在统一 sheet 中以只读、可选择文本显示；用户明确点击后才写入系统剪贴板，不自动执行、不发送消息，取消只调用 `dismissHandoff()`。
- 原生正常结果按 `SessionTransferOperation.state/items` 本地化。已知备份核对状态与空间提示可靠翻译；未知后端/Core 错误保留真实原文，不猜测替换。

## 9. 键盘、焦点与窄窗口

- 使用原生按钮、链接、复选框、下拉框和搜索框，支持 Tab、Enter/Space 与清晰焦点样式。
- 模态打开后焦点进入模态，Tab/Shift+Tab 在模态内循环；Escape 执行该模态的取消/返回，不执行确认动作。
- 覆盖确认取消、备份关闭返回原触发位置；异常确认取消返回恢复处理框；替换模态时保留最初触发控件作为最终返回焦点。
- 搜索重绘保留焦点和插入点。窄屏下来源与目标纵向排列，路径可换行，结果和底部动作不造成固定宽度横向溢出。
- 语言切换只改变界面文案，不改会话标题、项目、路径、选择或操作状态。

## 10. 本轮验证与未覆盖范围

Kimi 在不启动浏览器、App 或服务的前提下执行并记录以下检查：

- 原型 fixture 精确一致、JavaScript 语法、离线限制、宿主返回链接及 `pageshow` 生命周期模拟检查。
- 原生 `swiftc -parse App/SessionTransferView.swift App/SessionTransferLocalization.swift` 通过。
- 原生 `swift build --target ClaudeSwitcher` 通过。
- 静态核对 74 个中英文键完全一致；视图只有一个 `.sheet`，没有默认写入快捷键，`confirmAction()` 只有一个调用入口，取消/自动 dismiss/异常返回分别接到约定方法。
- 静态核对同一 Store 控制器缓存与 `NSWindowDelegate` 红点路径存在，视图层无 shell、Finder、网络或 Keychain 调用。

Codex 独立执行并反馈假数据原生窗口运行检查通过，覆盖勾选、备用导出、复制/备份/撤销、增量确认与 Escape、返回重进、红点恢复锁、恢复冲突和保留现状流程。这些运行结果属于 Codex 的检查，不记作 Kimi 亲自运行；Kimi 未安装或启动任何应用。

上述结果不替代真实会话端到端验收。Codex 后续补齐备份缺失分支和打包命令验证，154 项单元测试与 62 项控制器检查通过；local.6 本地构建已开放已适配的迁移入口，未替换现用安装。真实会话仍未读写，更多索引格式另行适配。详见[实现进度](会话迁移实现进度.md)与[原生验证](prototypes/native-session-transfer-validation.json)。网页、原生点击和文件引擎的证据分别记录。
