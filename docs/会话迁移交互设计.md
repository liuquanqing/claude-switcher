# 会话迁移交互设计

## 本轮交付与边界

- 可点击稿：`docs/prototypes/session-transfer.html`。单文件、离线、无外部资源；直接打开即可体验，不需要构建。
- 数据：HTML 内嵌的 JSON 与 `docs/prototypes/session-transfer-fixtures.json` 一致；原 fixture 只读。
- 沿用原复制窗口的来源、目标、搜索、勾选列表和底部动作，不增加仪表盘或大型向导。视觉沿用深灰、陶土橙和系统字体。
- 只演示虚构内存状态，不读取或修改真实会话、Claude 目录、Keychain、账号配置、API 凭据或聊天原文；不启动应用、服务或进程。
- “写入”“备份”“恢复”“退出目标”均为界面语义模拟。除目标内存索引外，来源索引和 transcript 内存数据不被迁移逻辑改写。
- 本文件不是实现完成或真实格式兼容的证明。浏览器交互与截图验收由父任务另行执行。

## 1. 窗口结构

原型窗口宽约 760px，窗口外下方另有低强调的“演示情形”选择器。该选择器只重置虚构状态，不属于产品 UI。

窗口内始终只有一套复制流程：

1. **选择会话**：来源 → 目标 → 空间 → 搜索/筛选 → 勾选 → “预览复制 N 项”。
2. **预览复制**：同一窗口列出新增、更新、跳过和内联备份说明 → “复制 N 项” → 演示结果。

“返回修改”保留选择并回到列表；“取消”明确显示未执行复制、未生成备份。正常流程不自动写入。目标桌面运行时会增加“退出并重新预览”的必要复核，不省略退出后的确认。

窗口标题下持续标注“离线交互原型 · 不操作真实数据”，结果页标注“演示结果 · 非真实操作回执”，避免让人误以为已经完成真实复制。

## 2. 来源、目标与空间

下拉项来自 fixture：

- `Personal · 订阅档案`
- `Business · 订阅档案`
- `API 工作区 · 配置匹配 Magpie`

空间规则：

- 只有一个空间时自动选择，同时显示空间名称、短标识和“唯一空间，已自动选择”。
- API 工作区有多个空间时显示“请选择来源空间”或“请选择目标空间”，不按目录顺序、条目数或名称猜测。
- 来源或目标端点变化会清空旧选择和旧预览；空间变化也清空，因为预览绑定完整空间标识。
- 来源和目标解析为同一空间时显示阻止原因，不能预览。
- API 可以作为来源或目标。界面明确说明不会自动切换 Magpie 模式、读取凭据或更改 provider。
- 目标未初始化时显示简短空状态：先在目标的 Code 页完成初始化；不提供创建目录、登录或切模式动作。

默认绑定为：

```text
Business · 订阅档案 / 团队空间（business-main）
→ Personal · 订阅档案 / 个人空间（personal-main）
```

## 3. 选择列表

### 默认只新增

“更新已有会话”沿用 fixture 的默认值 **关闭**。此时只有可新增项能勾选，已有会话保持原版的默认跳过语义。

开启后，只解锁同段进度更新和具有充分合成接续证据的续接更新，不自动选中它们。关闭开关时：

- 取消已经选择的更新项；
- 保留新增项；
- 提示实际取消的更新项数量；
- 清除旧预览，之后必须重新预览。

### 复制后的当前目标状态

列表分类以**当前目标空间的内存索引**为准，不只看 fixture 的初始 `kind`：

- 新增完成后，相同逻辑记录显示“已新增 · 无需重复”并禁选；同名不同身份仍显示目标冲突。
- 同段更新完成后，进度一致时显示“已同步 · 无需更新”；目标后来领先时仍保留目标。
- 接续更新完成后显示“接续已同步”，不重复更新；目标在续接段继续后视为目标领先。
- 同段更新只改已核实的进度和演示修订信息，不改写 `cliSegment`，并保留目标标题和未知字段；只有续接更新才切换续接段引用。
- 关闭结果不会重置目标或历史收据。成功撤销后恢复复制前分类；切换空间时使用该空间独立的目标状态。

### 搜索、项目筛选与全选

- 搜索匹配会话标题或项目；项目下拉可进一步筛选。
- 搜索和筛选不清除选择。
- 计数始终包含隐藏选择，并额外显示“筛选外仍选 N 项”。
- “全选当前结果”只处理当前筛选中、当前规则下可处理的项。
- 当前可处理项全选后，动作变为“取消全选当前结果”；取消也只影响当前结果，不影响筛选外选择。
- 目标领先、分支冲突、原文缺失、接续未证实等行不可勾选；“详情与原因”仍可展开。

### 六个 fixture 案例

| 会话 | 默认关闭更新 | 开启更新 | 关键说明 |
|---|---|---|---|
| 接口重构 | 可新增 | 可新增 | 目标无索引，原文可用；18 轮。 |
| 测试覆盖整理 | 默认跳过 | 可更新 | 同一 CLI 段、同一原文；目标 12 → 来源 28，只更新已核实进度字段。 |
| 长任务续接 | 默认跳过 | 有证明时可更新 | 来源新段 2 轮、目标旧段 120 轮；跨段轮数不能直接比较。 |
| 发布脚本 | 不可选 | 不可选 | 目标 13 轮，领先来源 5 轮，保留目标。 |
| 分支实验 | 不可选 | 不可选 | 来源 40 轮、目标 15 轮，但没有可确认续接关系，不能按数值覆盖。 |
| 旧项目记录 | 不可选 | 不可选 | 原文缺失，不创建空壳索引。 |

### 接续证明的特别约束

正常 fixture 中 `fixtureProof` 仅表示：

1. 接续点已确认；
2. 目标未在接续点之后继续。

它是**合成 UI 证据，不是官方 Claude 索引字段**。不能据此声称真实格式已受支持。

“续接无接续证明”情形中，“长任务续接”始终禁选。行详情明确写出：仅 `priorCliSessionIds` 包含目标 ID 不构成安全续接；缺少可验证接续点和目标未越过该点的证据，禁止更新。

## 4. 预览与备份

预览页顶部保留完整来源、目标及空间名称，并分别显示：

- 已选 M 项；
- 实际变更 N 项，严格等于实际新增 + 更新；
- 新增、更新、已选但跳过数量。

主清单只按“新增”“更新”“已选但本次不执行”分组。“跳过”仅表示已选但本次不执行的项，不包括未选项。

未选择或不可用的其他项目归入“其他未纳入 X 项”，默认折叠，展开后才显示原因；它们既不计入已选跳过，也不计入实际变更。结果与收据沿用同一组新增、更新、已选跳过、其他未纳入计数。实际新增与更新均为零时，不出现可执行的复制按钮。

跨账号或跨模式时只保留一行说明：本次只改本机列表，后续续聊由目标账号/服务处理，不在复制中发送原文。

### 内联备份说明

“查看备份内容”在当前预览页展开，不另开向导，也不要求用户勾选备份。

- 有更新项：说明将自动备份多少条**会覆盖的旧索引**及本次收据，并逐项列出。
- 只有新增项：明确“零覆盖：没有旧索引需备份”。新增项只记录“原先不存在”。
- 两种情况都明确“不复制聊天原文”。

结果页的“查看本次备份”是只读模态信息，不触发恢复或退出。原型中的备份位置标为“演示内存（未创建文件）”，不伪造真实目录或回执。

## 5. 目标桌面运行中

只读生成预览不要求退出来源或目标。预览页检测到目标正在使用待写索引时，主按钮先是：

> 退出目标并重新预览

不会显示可直接复制的按钮。点击后，模态确认说明：

- 退出可能刷新索引，也可能影响桌面内的 Code 任务；
- 本工具不主动停止外部终端/IDE 的 CLI；
- **不保证桌面子任务继续运行**；
- 不会自动重新打开目标、切号或切换 API 模式；
- 退出动作本身不执行复制。

用户可取消。确认后只模拟正常退出并重新读取本批已选项，随后显示：

> 桌面已退出，请确认更新后的预览。

演示会注入“测试覆盖整理”的目标进度从 12 回写为 24，用来展示退出后计划重算；若该项未被选择，不把它列作本批受影响项。更新后的预览仍需用户再次点击“复制 N 项”，才会进入模拟执行。

## 6. 执行结果与恢复

| 状态 | 主文案与颜色 | 写入语义 | 可用动作 |
|---|---|---|---|
| 演示复制完成 | 陶土流程后显示绿色“演示复制完成”，同时注明未真实复制 | 仅目标内存索引变更 | 查看本次备份、撤销本次、关闭结果 |
| 预览已失效 | 红色“预览已失效，零写入” | 不创建操作收据，不执行复制 | 重新预览、返回修改、取消 |
| 备份失败 | 红色“备份失败，复制未开始” | 目标写入 0 项 | 返回预览、返回选择 |
| 写失败、恢复完成 | 黄色“写入失败，已完整恢复”，不是绿色成功 | 新增撤回，旧索引恢复 | 查看本次备份、关闭结果 |
| 写失败、恢复未确认 | 红色，暂停新复制 | 保留现场与备份，不自动重试 | 只能查看恢复信息、重置演示 |
| 上次操作未完成 | 红色中断收据 | 不自动恢复、重试或开始新复制 | 只能查看恢复信息、重置演示 |
| 撤销冲突 | 红色“撤销冲突，零写入” | 保留全部新进展，不部分恢复 | 查看备份、关闭结果 |
| 演示撤销完成 | 明确“演示” | 整批撤回本次新增并恢复覆盖项 | 查看备份、关闭结果 |

“恢复完成”和“恢复未确认”不会都呈现为绿色成功。恢复未确认或中断状态下没有返回新复制、修改选择或执行复制的入口。“重置演示”只是丢弃虚构现场并回到正常情形，不表示实际恢复。

只有存在历史收据时，窗口右上角才显示轻量“上次复制”入口。关闭普通结果后仍可找回收据和恢复信息。

## 7. 撤销：整批预检

“撤销本次”先进入同窗口的恢复预览，列出每项将如何处理：

- 新增项：撤回本次新建索引；
- 更新项：恢复本次覆盖前的旧索引演示快照。

点击“检查并撤销 N 项”后才模拟整批预检：

1. 重新使用收据绑定的原目标空间，而不是盲用当前路径。
2. 核对每一项是否仍等于本次写后状态。
3. **任一项冲突即整批零写入**，列出冲突项，保留所有新进展。
4. 不做自动部分撤销，不提供强制恢复。
5. 全部一致才模拟整批还原，并保留“已撤销”收据和只读备份。

“撤销冲突”情形会在预检前注入复制后的目标新进展，用来验证冲突分类；该注入不是撤销写入。

## 8. 演示情形与验收路径

窗口外的“演示情形”对应 fixture 中的全部 11 个 ID。

### 正常 `normal`

1. 默认只选“接口重构”，点击“预览复制 1 项”。
2. 核对已选 1、实际变更 1、新增 1、更新 0、已选跳过 0；“其他未纳入 5 项”默认折叠。展开备份，确认“没有旧索引需备份”。
3. 点击“复制 1 项”，结果必须标明演示、未真实复制，收据计数与预览定义一致。
4. 关闭结果但不重置演示，“接口重构”显示“已新增 · 无需重复”并禁选，历史收据仍在；其他目标空间不继承这条记录。
5. 通过“上次复制”找回结果，点击“撤销本次”，再点击“检查并撤销 1 项”。整批预检通过，显示演示撤销完成。
6. 关闭撤销结果后，“接口重构”恢复为可新增。

### 目标未初始化 `target-uninitialized`

- 默认目标显示未初始化空状态。
- 不出现创建目录动作，主按钮不可执行。

### 多空间 `multi-space`

- 默认目标为 API 工作区，目标空间为空，必须显式选择。
- 来源单空间仍自动选中并显示名称。
- 未选目标空间时不能选择或预览；选择空间后旧选择与预览保持清空。

### 桌面运行中 `desktop-running`

1. 选择会话并预览。
2. 主按钮为“退出目标并重新预览”，不是“复制”。
3. 取消模态不会退出或写入；确认后只生成更新后的预览。
4. 再点“复制 N 项”才出现演示结果。

### 预览后变化 `stale-plan`

1. 选择“接口重构”并预览。
2. 第一次点击执行时注入目标外部变化并停止，显示零写入。
3. 旧预览不会自动执行剩余项。
4. 点击“重新预览”后，该项转为“目标冲突”并取消选择；若没有其他选择，不出现复制按钮。

### 备份失败 `backup-failed`

- 选择任一项、预览并执行。
- 显示备份失败、复制未开始、目标写入 0 项；没有绕过备份的路径。

### 写失败、恢复完成 `write-failed-rollback-ok`

- 执行后显示黄色恢复完成，不是复制成功。
- 文案明确新增已撤回、旧索引已恢复，保留收据和备份查看。

### 写失败、恢复未确认 `write-failed-rollback-incomplete`

- 执行后显示红色恢复未确认并锁定新复制。
- 只能查看恢复信息或重置演示。

### 撤销冲突 `undo-conflict`

1. 完成一次内存复制。
2. 点击“撤销本次”并确认整批检查。
3. 显示冲突、整批零写入和保留新进展；无部分撤销结果。

### 续接无接续证明 `continuation-without-join-proof`

- 即使开启“更新已有会话”，“长任务续接”仍禁选。
- 详情说明仅历史 ID 包含不足以证明安全续接。

### 中断收据 `interrupted-operation`

- 载入即显示“上次操作未完成”和阻止状态。
- 不自动恢复或重试；只能查看恢复信息或重置演示。

## 9. 键盘、焦点与窄窗口

- 所有主要动作使用原生按钮、复选框、下拉框和搜索框，支持 Tab 与 Enter/Space 的原生键盘行为。
- 行详情、了解复制、备份内容使用原生折叠控件。
- 模态打开后焦点进入模态，Tab/Shift+Tab 在模态内循环；Escape 关闭并返回触发控件。
- 预览页 Escape 等同返回修改；撤销预览 Escape 返回结果；普通结果 Escape 关闭结果。恢复未确认/中断状态不能用 Escape 绕过阻止。
- 重新渲染后尽量恢复搜索、筛选、开关和列表复选框焦点；视图切换仍程序聚焦本页标题供屏幕阅读器使用，但标题不绘制整行焦点框。按钮、输入框、下拉框和折叠控件保留清晰的键盘焦点样式。
- 约 560px 以下来源与目标改为纵向排列，行状态换行，底部动作可换行；使用可收缩列宽，避免固定宽度造成横向溢出。

## 10. 文案原则

- 主按钮始终说明下一动作：“预览复制 N 项”“复制 N 项”“退出目标并重新预览”“检查并撤销 N 项”。
- 失败不笼统写“成功”或“已完成”；分别说明未开始、恢复完成、恢复未确认、中断或撤销冲突。
- 技术规则收在“了解复制”和行详情，不在主界面常驻大段说明。
- 不把演示收据数、退出码或内存计数解释为目标账号已经能续聊。
- 不承诺跨文件事务、桌面子任务存活、自动切号或真实格式兼容。

## 父任务验收附记

Kimi完成原型后，主会话通过内置浏览器执行29项有效交互/响应式检查，控制台错误0、无自动资源加载，fixture精确一致、JS语法通过。首次发现重复导入仍显示新增、未选项误计为跳过、程序聚焦标题框三处问题，均由Kimi修正后复验。取消与逐字输入的测试工具断言限制另行记录，未冒充产品缺陷。

详见[QA报告](../design-qa.md)及[检查记录](prototypes/session-transfer-validation.json)。真实迁移引擎、文件恢复和官方格式兼容仍未实现/验收，不能据此启用生产入口。普通逐字搜索已验；中文输入法组合、完整VoiceOver及目标后来重开后的真实进程检查不在本次证明范围。
