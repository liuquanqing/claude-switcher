# “复制会话”交互评估

## 结论

当前界面用于在来源与目标账号/组织之间批量同步会话索引，不是“只带当前这一条聊天”。主要问题仍在方向、选择状态和结果预告，不在配色，也不能再以假定的单条意图为由取消默认全选。

建议保留一个“来源 → 目标”的主流程，用清晰的当前账号标识和交换方向兼容切换前后，不增加“带出 / 带入”模式。这里的“复制”仅指 Code 页会话索引；聊天原文继续共享，不随此操作迁移。续接关系、目标较新、归档、原文缺失等现有后端限制均不放宽。

我的取舍是：**在来源、目标以及新增/更新数量都清楚可见的前提下，保留默认选中可执行新增项；更新仍默认关闭，只有用户显式开启后才选择安全更新项。** blocked/skip 项不为简化操作而选中。主按钮保留“开始”，避免在顶部方向句、结果摘要之后第三次重复完整目标；“复制指令”继续一键直接复制并提示成功，不重加 handoff 预览弹层。

## 1. 当前流程最影响理解的三个问题

### 1）进入页面时，默认方向与主要习惯相反

- 刷新时默认把**当前账号设为目标**，把另一个非 API 账号设为来源：`App/SessionTransferController.swift:234`、`App/SessionTransferController.swift:235`。
- 顶部只有抽象的“来源 / 目标”和箭头，没有“当前桌面”“已保存”的身份锚点：`App/SessionTransferView.swift:191`、`App/SessionTransferView.swift:200`，文案见 `App/SessionTransferLocalization.swift:11`。
- 主按钮目前为“开始”：`App/SessionTransferLocalization.swift:31`。它不能独自纠正不清楚的方向，但方向句和结果摘要补足后，无需再在按钮上重复目标。

因此，用户在切换前想执行“当前 → Work”，看到的却是“Work/其他账号 → 当前”。反向复制仍是有效操作，现有安全检查不会替用户识别意图错误。多空间时，“账号 xxxxxxxx · 组织 xxxxxxxx”又增加了辨认成本：`Sources/SwitcherCore/SessionTransferModels.swift:22`。

### 2）列表的选中状态与“将会发生什么”不一致

- 用户提供的脚本命令没有 `--cwd` 或单条会话筛选，会批量同步所选账号/组织范围内所有满足规则的会话；用户也明确偏好“默认全选、增量避免重复”。因此，当前默认全选新增项符合批量场景，不应再以“只带当前聊天”为由取消：`App/SessionTransferController.swift:253`。
- `updateExisting` 默认关闭：`App/SessionTransferController.swift:114`。开启后只刷新候选状态，并不会选中更新项；关闭才会移除更新项选择：`App/SessionTransferController.swift:209`。
- 更严重的是，只要行类型为 `.update`，右侧就显示“将更新”，没有检查该行是否被选中：`App/SessionTransferView.swift:284`、`App/SessionTransferView.swift:448`。所以“开启更新但未勾选”的行也会被描述成“将更新”。
- “全选可复制项”实际作用于当前筛选结果中的所有可选行：`App/SessionTransferController.swift:219`。底部却只报告“已选 N 项”，不区分新增和更新：`App/SessionTransferView.swift:133`。

问题不是默认选中了批量新增，而是范围、开关、选择和结果没有一致表达。用户仍无法稳定判断：开启更新是否等于选择更新、全选包含哪些类型，以及点击开始后究竟新增多少、更新多少。

### 3）“已有”掩盖了不同结果，提交前缺少可信预告

后端对 `.skip` 有多种完全不同的判断：目标已有同一会话但保留目标条目、目标进度较新、已经同步、尚未开启更新，见 `Sources/SwitcherCore/SessionTransferService.swift:134`、`Sources/SwitcherCore/SessionTransferService.swift:139`、`Sources/SwitcherCore/SessionTransferService.swift:140`、`Sources/SwitcherCore/SessionTransferService.swift:141`。UI 却统一显示“已有”：`App/SessionTransferView.swift:452`。

只有 blocked 行会直接展示原因，skip 的具体原因主要藏在悬停提示里：`App/SessionTransferView.swift:271`、`App/SessionTransferView.swift:295`。这会把“无需操作”“默认不更新”“目标较新所以保留”压成同一个模糊状态。仅新增时不必追加确认弹层，但提交前必须有常驻、明确的新增/更新数量与范围摘要；现有更新确认逻辑见 `App/SessionTransferController.swift:275`。

## 2. 建议的唯一主流程

不设置“切换前带出 / 切换后带入”两个模式，也不增加说明折叠层。始终使用同一组来源、目标和会话列表。

1. **先看清方向。** 顶部写成一句操作：“把〔Personal · 当前桌面〕的会话带到〔Work〕”，保留下方必要的空间选择，并提供就近的“交换方向”按钮。
   - 切换前：默认来源为当前桌面账号，用户选择 Work 为目标，即“当前 → Work”。
   - 切换后：在同一个页面交换方向或调整两个选择器，即“Personal · 已保存 → Work · 当前桌面”。不需要学习另一套流程。
   - 已明确选择的方向在刷新和重开页面时应优先保留；无法可靠判断目标时让用户选，不猜测哪个账号是 Work。

2. **明确批量范围，保留新增项的默认选择。** 刷新后默认选中当前来源/目标范围内所有可执行新增项，以符合批量同步和增量去重场景；用户可逐项取消，也可用“全选当前结果”补选。更新默认关闭，不选中更新项；blocked/skip 一律不默认选中。现有模型没有足够信息自动认定哪一条是桌面当前打开的聊天，因此既不把“最近一条”冒充为“当前聊天”，也不把主流程收窄成单条迁移。

3. **持续预告结果，再执行。** 选择区下方固定显示：“从 Personal 复制到 Work：将新增 N 项、将更新 M 项；未选项和保留项不变。”主按钮保留“开始”；顶部完整方向句与这段摘要已经说明目标，不再第三次写“复制到 Work”。顶部始终保留一句短范围说明：“复制 Code 页会话索引；聊天原文保持共享，不随此操作迁移。”含更新时继续沿用现有逐条确认和旧索引备份提示。

4. **完成后给用户下一步，不串联自动切换。** 切换前的完成态可写“已复制 1 个会话索引到 Work。返回账号后可切换到 Work”，按钮仍只执行“返回账号”；不要在未实现前写成“复制并切换”，也不要自动结束桌面进程。切换后的完成态只需提示到 Work 的 Code 页查看。目标桌面未退出、恢复记录未解决或关系无法确认时，仍按现有规则停止。

## 3. 方向、已有项、全选与更新的表达规则

### 顶部方向

- 用“把〔来源〕的会话带到〔目标〕”替代孤立的“来源 / 目标”作为页面主标题；两个选择器仍可保留原有小标签。
- 给当前桌面账号加“当前桌面”，另一侧必要时加“已保存”；“交换方向”只交换来源和目标，不形成一种新模式。
- 主按钮保留“开始”。顶部方向句和执行前结果摘要已两次说明目标，按钮再写完整目标会增加冗余；不为形式上的“动作 + 对象”而回退此前产品取舍。如果未来省略其中任一方向提示，则需重新评估按钮文案，不能让“开始”独自承担方向表达。
- 空间需要消歧时保留短 ID，但把它降为次级信息；只有在已有可靠显示名时才显示别名，不编造账号或组织名称。

### 行状态必须同时反映“后端判断”和“用户选择”

- 新增候选：选中显示“将新增”，未选显示“可新增 · 未选”。
- 更新候选：更新关闭时显示“已有 · 默认不更新”；更新开启且选中时显示“将更新”；开启但未选时显示“可更新 · 未选”。不能仅凭 `.update` 类型显示“将更新”。
- 保留项：至少区分“已同步 · 无需复制”“目标较新 · 保留目标”“目标已有同会话 · 保留目标”。具体原因应直接可见，不只依赖 tooltip。
- 不可自动处理：显示“无法自动复制”及现有具体原因。续接/分支关系未确认的 blocked 项、目标较新的 skip 项都不能因为开启更新而变成可选；后端依据见 `Sources/SwitcherCore/SessionTransferService.swift:131`、`Sources/SwitcherCore/SessionTransferService.swift:139`。

### 全选与更新选择

- 将“全选可复制项”改为“全选当前结果”，继续只影响当前筛选结果中的可执行项，并保留混合选中态；筛选外已选数量继续单独提示。
- 将“更新已有会话”改为更明确的“同时更新已有会话”，**默认关闭**。只有用户显式开启时，才把所有已被后端判定为 `.update` 的安全候选项加入选择；关闭时移除全部更新项选择。用户之后仍可单独取消某一项。
- 底部计数改成“将新增 N · 将更新 M”，而不是只有“已选 N”。若筛选外仍有选择，继续追加“含筛选外 K 项”。含更新时，确认弹层必须列出全部将被更新的会话，包括当前筛选之外的项。
- 默认全选和“全选当前结果”都只选择可执行行：新增项，以及更新已开启时的安全更新项；不会把 blocked、skip、“已有”“目标较新”或“需核对”变成可复制项。

## 4. 命令式入口保留为低频备用

当前“复制指令”与主按钮同处底部操作区，并且只要主操作可用就可用：`App/SessionTransferView.swift:321`、`App/SessionTransferView.swift:332`、`App/SessionTransferController.swift:173`。但它已经是低强调文字按钮，实际行为也不是弹出预览：按钮直接调用 `copyInstructions()`，后者异步取得 `generateInstructions()` 的文本，写入 `NSPasteboard.general`，随后短暂显示“已复制”：`App/SessionTransferView.swift:332`、`App/SessionTransferView.swift:389`、`App/SessionTransferView.swift:397`、`App/SessionTransferView.swift:402`。`generateInstructions()` 本身只生成并返回文本：`App/SessionTransferController.swift:394`。

代码虽然仍保留 `exportInstructions()` 和 `handoffSheet()`，当前底部按钮并未调用这条弹层路径：`App/SessionTransferController.swift:390`、`App/SessionTransferView.swift:653`。因此，指令入口应**保持用户已确认的“点一下直接复制、显示成功提示、不再弹预览”**。主操作区只保留一个高强调“开始”，命令式入口继续作为低强调备用；如需补充手动终端流程说明，可用入口附近的低干扰帮助，不重加 handoff 预览或额外确认步骤。

备用的复杂性不能靠删减安全检查来换取。现有文本包含请求文件、只读预检、指纹、退出写入入口、apply、undo/recover 等步骤：`Sources/SwitcherCore/SessionTransferCommand.swift:70`。这些应继续留在备用流程内，不应为了接近用户原来的单命令习惯而简化协议，也不宣称与原脚本等价。界面层要做的是降低入口优先级，而不是降低执行约束。

## 5. 最小改动清单

以下均为后续实现建议，本轮不修改产品代码：

1. **Controller 默认方向与选择：** 首次进入默认当前桌面为来源；保留用户明确选择；增加交换方向。保留默认全选可执行新增项，不改成默认全不选；更新继续默认关闭。
2. **View 与文案：** 顶部改为完整方向句，增加当前身份和交换按钮；常驻索引范围短说明；主按钮保留“开始”；底部拆分新增/更新计数。
3. **更新与全选：** 显式开启更新时选中安全更新候选，关闭时移除更新选择；全选明确限定当前结果；blocked/skip 不可选；行状态同时依据 `kind` 和 `picked`，消除“未选却将更新”。
4. **已有项原因：** 只为现有 skip 原因增加短状态映射并直接展示，不改判定逻辑。空间短 ID 降为次级信息；没有可靠别名时仍保留它用于消歧。
5. **备用入口保持直接复制：** “复制指令”继续使用低强调入口，直接写剪贴板并显示成功提示，不恢复 handoff 预览；保留现有请求、预检、指纹、退出检查、备份和恢复协议。

不需要为实现上述交互而修改 `SessionTransferService` 的复制决策，也不需要修改 `SessionTransferCommand` 的命令协议。后续交互测试应覆盖默认方向、交换、默认仅选新增、筛选后的全选、更新开关及选中计数，并确认 blocked/skip 始终未被选中；现有目标较新和续接不可覆盖测试仍是必须保留的边界，见 `Tests/SwitcherCoreTests/SessionTransferTests.swift:74`、`Tests/SwitcherCoreTests/SessionTransferTests.swift:80`。

### 已有功能对照依据（非真实账号数据）

- Codex 已使用**独立临时 HOME 和 7 组虚构索引**对照实际脚本及当前引擎：脚本新增 2、覆盖 3；App 默认仅新增 1，显式开启更新并全选后新增 1、更新 1。
- 续接 CLI 不同、历史原文缺失的项被 blocked，目标时间较新的项被 skip；App 更新保留目标自改标题。两边源索引和共享原文均未修改。
- 这些结果可以作为功能差异依据：默认新增、显式更新和安全拦截会改变最终执行数量，App 也有自己的目标标题保留行为。不能据此要求 App 追平脚本的覆盖数量或放宽 blocked/skip。该对照**不等于完整 native 点击验收**。

### 本轮未验证范围

- 本次修订仅静态核对报告与相关 Swift 调用，未启动 App、未执行脚本或备用命令、未联网、未运行测试，也未读取真实脚本、HOME 配置、截图、账号目录、钥匙串或会话。
- 上述功能对照由 Codex 在虚构数据上完成；本次没有复跑，也不把它表述为真实账号或完整 native UI 验收。中英文布局、长账号名、多空间、小窗口、键盘与辅助功能表现仍尚未渲染验证。
- 未验证桌面当前打开会话与列表条目的自动对应关系，因此方案不承诺自动识别“当前聊天”；主流程按用户已明确的批量同步场景设计。
- 未验证完成复制后 Code 页的实际续接表现，也不承诺功能与外部脚本完全等价；本文明确限定为索引复制设计评估。
