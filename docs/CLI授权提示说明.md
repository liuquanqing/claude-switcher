# CLI 授权提示：已确认事实与边界

核查日期：2026-10-31。本文记录排查结果，不宣称重复密码问题已经彻底解决。

## 两种提示不能混为一谈

- `Claude Switcher` 请求自己的备份或其他登录存储：本项目当前为 ad-hoc 签名，新构建的签名指纹变化，可能需要逐项重新授权。
- 系统 `security` 请求 `Claude Code-credentials`：这是系统工具在访问默认 CLI 的共享凭据。官方 CLI、桌面中的 CLI 或其他管理工具均可能调用它，不能仅凭对话框断定调用者是切换器，也不能全部归因于切换器升级。

本轮截图对应第二类。只读元数据检查显示相关项目已经包含当前切换器及 Apple `security` 的授权；两个可比较快照的权限集合相同。读取进程链时，该请求已经结束，因此实际父进程未确认。没有为诊断额外读取该项目的令牌，也未更改 ACL。

[Claude Code #62361](https://github.com/anthropics/claude-code/issues/62361)、[#62213](https://github.com/anthropics/claude-code/issues/62213)、[#67315](https://github.com/anthropics/claude-code/issues/67315) 有共享凭据权限变化及重复授权的用户报告。这些报告描述其他版本/环境，不足以证明本机本次弹窗由同一缺陷触发。

## 本轮优化

- 自动普通刷新只观察本地元数据与额度缓存，不主动解密备份。
- 联合切换和同步成功后，复用事务已经完成的身份核验与回读结果，不为刷新 UI 再读取一次凭据。
- 同一账号/组织的较弱观察保留较强的已完成结果和原时间；账号、模式变化或实际失败会撤销旧结果。
- 手动状态刷新集中到底部；切换完成后自动补查额度。系统确实要求访问授权时仍需用户确认，不能承诺官方 CLI 永不弹窗。
- 不修改第三方凭据权限，不设置“允许所有应用”，不把真实 token 放入命令行参数、日志或 Git。

## Touch ID

[Apple 的用户在场保护](https://developer.apple.com/documentation/security/restricting-keychain-item-accessibility)允许应用为其管理的钥匙串条目配置生物识别或密码验证。但这和[传统 macOS 钥匙串的应用访问 ACL](https://developer.apple.com/documentation/security/access-control-lists)是不同的授权环节。

因此不能承诺把当前 `security` 访问共享凭据的系统弹窗直接换成 Touch ID。若对自有备份改用生物识别，需要单独设计存储迁移、恢复与兼容，并验证不会破坏原版或官方 CLI 的访问；本轮未执行该迁移。

## 出口检查

运行中的守卫仍持续检测；任一必要出口无法确认时，不放行已纳入保护的桌面，关闭后也继续按原计划检查，不自动重新启动 Claude。本版不改变这些判断及动作。

原回执会被后续检查覆盖，无法据当前通过的结果还原此前哪一域名请求失败。新增的界面优化会展示操作中实际完成的检查及所用保存配置；这不是历史故障日志，也不代表已经实现网络层断流。
