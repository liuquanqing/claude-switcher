# 头部与结果收起优化（基于 20261028.6.4）

作者：Claude CLI（前端与全部产品文案，含下述后端提示字符串）。评估、后端接线与 QA：Codex（只核验真实性与编译，不改措辞）。
改动文件：`App/Views.swift`（Header）、`App/ProtectionView.swift`（TerminalProtectionCard）。未改 Store / ProtectionController / Core / main.swift / build.sh。
**状态：代码已写好，未构建，未做原生 QA。**

## 1. 头部：账号做唯一主标题

- 删去常驻的 “Claude Switcher” 小字。菜单栏弹层没有窗口标题，产品识别改由 App 图标承担：
  - 悬停图标：tooltip “Claude Switcher · 版本 x（build）”；
  - 点击图标：小 popover（产品名、版本、一句用途），按需查看，不常驻。
  - 版本号读 `CFBundleShortVersionString` / `CFBundleVersion`，两者都缺时只显示产品名。
- 账号名 19pt 粗体成为第一行；“当前账号”标签保留但略弱化（0.85 不透明度），与名字同基线。第二行仍是邮箱 · 套餐。
- 取舍：没有把产品名挪到底栏或副标题，避免只是换个位置继续占地方。

## 2. 运行状态 + 动作二合一

一个分段胶囊按钮（高 30pt，整块都是热区）：

| 状态 | 左半（状态） | 右半（动作） |
|---|---|---|
| 未运行 | ○ 桌面未运行（灰） | ▶ 打开 |
| 运行中 | ● 桌面运行中（绿点，文字中性色） | ▭ 显示 |

- 点击始终调用原 `openClaude` 回调 → `Store.openProtectedClaude()`，**先过网络门禁**；“显示”只是标签，没有任何绕过门禁或绕过纳入确认的分支。
- 运行中只用绿点表示“进程存在”，文字不用绿色，避免被读成“已登录/网络可用/已保护”。悬停说明里写明这一点。
- 悬停说明按情况区分：
  - 未运行：先检查门禁，通过后打开当前账号；
  - 运行中且已纳入：门禁通过后切到前台；
  - 运行中但订阅桌面未纳入：会提示先在保护卡片确认纳入，不会自动接管或关闭；
  - 非订阅（API/未知）：门禁会拦下。
- 禁用条件不变：`store.busy != nil || protection.working`。检查进行中的文字由底栏 busy 区显示，没在按钮里另加 spinner（避免靠匹配 busy 文案判断）。
- 未纳入时仍允许点击（走门禁后由后端拒绝并给提示），而不是禁用按钮：禁用会把原因藏起来。

### 后端提示字符串（Claude 定稿，只改字符串，条件与行为未动）

1. `ManagedDesktop.swift` `launchProtectedDesktop` 未受管被拒：“当前桌面未保护，未切到前台。可在保护卡片点“纳入…”确认，无需退出；确认前不接管、不关闭。”（只在门禁已放行后出现，此时纳入控件可用；明说未切到前台，不冒充成功。）
2. `Protection.swift` `refreshScope()` 订阅且未纳入：“订阅配置已识别；当前桌面未保护，确认纳入前不接管。”（常驻悬停说明，守卫未就绪时也会显示，所以不指向可能不存在的按钮。）
3. `--demo-unmanaged`：“演示：当前桌面未保护，确认纳入前不接管。”（与真实文案一致，保留“演示”前缀。）
4. 演示代理未连接：“演示：模拟代理未连接。”（加“模拟”，避免被读成真实网络结论。）
3. **可选，不要求**：若想让“显示”在未纳入时不必先跑一遍网络探测再被拒，可提供只读属性（如 `Store.desktopShowable`），前端据此改标签；当前前端只用已有的 `protection.desktopScope` / `desktopManaged` 调整说明文字，不改行为。是否允许“未过门禁也能聚焦已运行窗口”属于策略决定，前端不自行实现。

## 3. 网络结果单独收起

- 结果块的首行（结论 + 时间 + 箭头）本身就是展开/收起按钮，整行宽、最小高 28pt，不只是小三角。
- 收起后只剩这一行摘要，保留结论颜色/图标与检查时间；展开时显示三项结果、上下文提示、“仅诊断…”与 IP/WebRTC 参考链接（链接仍只作参考）。
- 每完成一轮新检查（通过 / 未通过 / 输入无效，均以 `lastCheckReport.checkedAt` 变化为准）自动展开；之后只由用户收起。收起状态与“设置”展开状态互相独立。
- 检查中：首行是 spinner + “正在检查…”，边框中性色，三项为“检查中…”，不显示上一轮绿勾（展开或收起都一样）。
- 输入修改后（国家草稿 ≠ 本轮目标，或代理模式 ≠ 本轮模式）：
  - 首行改为黄色 “输入已修改，请重新检查”，不再显示绿勾/“网络通过”，**收起时同样如此**；
  - 展开时三项结果降为 45% 不透明度，下方注明 “以下是上次输入（目标 XX）的结果，不代表当前输入。”
- 未改：结果仍放在设置区内、紧挨“仅检查网络”按钮。

## 4. 保护状态与“纳入”二合一

- 删除横跨整卡的 `desktopTakeoverOffer` 说明行（含“运行中的桌面可交给后台守卫管理，不会重启”），卡片上不再有单独的纳入行。
- 可纳入时，右侧保护列第一行（状态行）本身变成纳入按钮：`[盾] 未保护 ········ 纳入…`。
  - 状态词缩为“未保护”（黄），动作词“纳入…”（Claude 色）；省略号按 macOS 惯例表示“还需确认”。不再另写“当前未保护”之类的同义说明。
  - 该行有淡 Claude 色底 + 细描边，悬停加深，整行都是热区，最小高 22pt；只打开确认弹窗。
- “设置”仍是独立按钮，热区为下方两行（范围 / 目标 · 设置⌄），与纳入按钮是**兄弟视图，不嵌套 Button**；点“设置”只展开/收起设置，不会纳入。
- 不可纳入时（含正常已保护、API、未知、网络未通过、守卫未就绪、未启用、working）布局与以前完全相同：整列是单个设置按钮，没有任何纳入入口。
- 列宽仍为 154pt，左侧终端区宽度不变；可纳入时列高估计多约 6pt（按钮底色的边距，未实测），由 `fixedSize(vertical:)` 整行吸收。
- busy / working 时纳入按钮禁用，只淡化“纳入…”与底色，“未保护”状态词保持可读。
- VoiceOver：纳入按钮读“当前桌面未保护，纳入保护”，提示“会先弹出确认”；设置按钮此时读“保护设置：范围…，目标…”，不重复状态。
- 门禁未改：显示条件仍是 `offerDesktopProtection`（订阅范围 + 守卫在线 + 当前决策放行 + 桌面运行 + 未纳入 + 已启用 + 非 working）；确认对话框、确认时复核 `guard offerDesktopProtection, !busy`、弹窗文案（仅限订阅桌面；网络不符可能关闭此桌面；不切账号、不停止 CLI）均原样。确认前不调用 `protectCurrentDesktop`，没有自动接管。
- 检查说明 popover 中对应条目标题改为“未保护 · 纳入…”，与控件一致；“检查并打开”一条已是“顶部 打开 / 显示”。
- 取舍：没有在状态行里塞一个独立小胶囊按钮（状态文字 + 小按钮两块热区挤在 134pt 内易误点），而是让整行只有一种含义；也没有把纳入放进设置展开区，以免藏起来。

## 保留未动

正常卡片不重复更新时间；底部“最近刷新”只表示动作时间与部分失败；正常 CLI 不常驻大检查按钮；同步确认冻结目标；IP/WebRTC 只参考；历史操作错误不因网络通过自动清除（`operationErrorFeedback` 未改）。
