# UI 局部回归与审美复核

范围：只动账号网格末尾的添加入口、当前账号卡样式、头部第二张卡右侧的保护栏。
文件：`App/Views.swift`、`App/ProtectionView.swift`；`App/ManagedDesktop.swift` 只改一条错误提示文字。Store / Controller / Core / main.swift / build.sh 未改。

## 问题与取舍

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 添加账号跑到“账号 3 个”标题旁 | 为了给它腾位置多加了一行标题 | 去掉标题行，入口回到网格末尾（与原版相同的动线） |
| 账号数为偶数时空卡单独占一行 | 空卡独占一行，左侧留白 | 曾按奇偶切换成通栏细条，但多一个账号入口就换形态、换位置，用户反馈“改多了”。已撤回：入口始终是网格最后一格，形态与原版一致，只保留现在的紧凑卡高。偶数个账号时那半行留白接受为代价 |
| 4 个账号时网格铺满 3 行，到 5 个账号反而变矮 | 滚动判断仍是 `profiles.count > 4`，只数账号卡，没算回到网格里的添加入口：4 账号 + 入口 = 5 格时完整展开 3 行，5 账号时才切成“两行 + 第三行露头”的固定高度滚动区 | 按实际格子总数判断：`profiles.count + 1 > 2 * cols.count`（双列即超过 4 格就滚动）。现在 3 个账号 + 入口 = 4 格正好两行不滚动；4 个账号起进入滚动区，高度与之后一致，不再突变。滚动区高度、第三行露头提示、入口形态均未改 |
| 左侧短橙条像多了一层选择 | 当前卡同时有橙色名字、“当前”胶囊、橙色描边、短橙条，同一信号重复四次 | 去掉短橙条与橙色名字；描边降到 0.42 不透明度；“当前”改成右上角无底色的“● 当前”，与其他卡的“切换”同一槽位，一看就是状态，不是按钮 |
| 保护栏“未保护 \| 纳入…”难看、省略号奇怪 | 状态和动作挤进同一个按钮 | 状态固定在上方（图标 + 状态词，下一行“订阅桌面 · 目标 SG  设置⌄”）；只有满足条件时，下方才出现独立的“纳入保护”按钮，文字不带省略号 |
| “保护未启用”还多占一整行解释 | 整行解释重复了状态词 | 状态词已足够；说明移到设置按钮的悬停提示里。守卫离线 / 已拦截这类真实问题仍保留整行提示 |

## 文案

- 添加入口：`添加账号`；编辑时标题为 `新账号`，占位文字 `账号名称，如 客户 A`，按钮为 `取消` / `添加`
- 当前卡：`● 当前`
- 保护栏范围短词：`订阅桌面` / `API 桌面` / `范围待确认`
- 纳入动作：`纳入保护`（确认框标题、正文不变）
- 检查说明里对应的条目改为 `纳入保护`
- 打开 / 显示时桌面未保护的错误提示：`当前桌面未保护，未切到前台。可在保护卡片点“纳入保护”，无需退出重开；确认前不接管、不关闭。`（只改文字，抛错条件与行为不变）

## 保持不变

- 所有打开 / 显示仍走 `openClaude` → `store.openProtectedClaude()`
- `offerDesktopProtection` 的条件未改（订阅桌面、守卫在线、门禁通过、桌面运行中、未纳入管理、已启用、不在处理中）；点击只打开确认框，确认时重新校验后才调用 `protectCurrentDesktop()`；取消不写入；忙时禁用
- 设置按钮与纳入按钮是同级兄弟视图，没有嵌套；点设置只会展开或收起设置区
- 账号顺序、双列布局、点“切换”才切号（卡片本身不可点）、真实 current 判定
- 头部图标 About、运行 / 打开合一控件、网络结果独立折叠且新一轮检查后自动展开、卡片时间去重、底部统一刷新、同步确认冻结目标、只读检查不保存、未知不当作通过、历史错误不自动清除

## 保护卡片信息架构收尾（第二轮，仅 `App/ProtectionView.swift`）

用户反馈：右栏“设置/收起”与下方展开内容割裂；“订阅桌面保护”、保护范围行、右栏状态/目标三处重复。

分工：右栏 = 状态 + 当前唯一动作；展开区 = 只放控件（开关、国家、代理模式、保存、仅检查网络）。范围只在悬停/说明里按需出现，不再常驻一行。

| 状态 | 右栏第一行 | 右栏第二行 | 动作 |
| --- | --- | --- | --- |
| 未启用 | 保护未启用 | 收起时 `点此设置并开启`，展开时 `在下方打开开关` | 点右栏展开，开关在展开区第一行 |
| 处理中 | 正在更新设置 | 目标（已保存） | — |
| 守卫离线 / 回执过期 | 保护状态待确认 | 目标（已保存） | 卡片下方整行显示具体原因与下一步（`controller.status`） |
| 急停失败 | 急停失败 | 目标 | 同上 |
| API 桌面 | API 桌面未纳入 | 守卫只管订阅桌面 | 不再重复 `unsupportedMode` 的整行通用提示 |
| 范围未知 | 桌面范围待确认 | 确认前不算受保护 | — |
| 服务在线、当前桌面未纳入 | 当前桌面未纳入 | 守卫在线 · 目标 SG | 独立“纳入保护”按钮 → 确认框（不变） |
| 已拦截 | 已拦截 | 目标 | 整行原因 |
| 守卫就绪、无桌面运行 | 守护已就绪 | 目标 SG · 桌面未运行 | — |
| 已纳入且通过 | 桌面保护中 | 目标 SG | — |

- “保护中”只写成“桌面保护中”：右栏紧挨终端区，单写“保护中”会被读成终端/账号也受保护。其余状态不再反复写“订阅桌面”。
- 终端认证一致/不同/未核验仍只在左侧终端区，不进入右栏。
- 展开/收起：唯一入口是右栏状态块（整块可点，标题右侧 chevron 翻转），去掉“设置/收起”文字。展开时右栏与展开区共用同一浅底色，终端区下方单独一条分隔线，右栏与展开区之间不画线，读起来是同一个标签页；整卡按 12pt 圆角裁切。
- 展开区第一行改为“后台保护 + 开关”；删除“保护范围：…”常驻行和“首次使用”行；未启用时开关下一行说明怎么开。范围说明放在开关悬停提示（附终端只核验默认登录、不停止运行中的 CLI）。
- 草稿与已生效：去掉国家字段旁的“未保存”小标签，改为字段行下方一行 `未保存 · 已保存为 SG · Shadowrocket`（启用且有改动时才出现；无已保存配置时为 `未保存 · 尚无已保存设置`）。这一行只陈述已保存配置，不宣称守卫正在运行：`enabled` 只代表已保存的开关，守卫可能离线或回执过期，运行状态以右栏为准。右栏目标永远是已保存值。
- 异常原因与“上次操作未完成”：收起时在头部下方；展开时移到展开区顶部，保证右栏与展开区相连。旧错误仍只能手动关闭。
- 网络检查结果、检查说明、代理说明、API 工具行、所有确认框文字与条件均未改。

## 待 Codex 原生验收（第二轮）

1. 编译：`settingsButton` → `statusButton`；删除 `shortStatus`、`desktopScopeShort`、`desktopScopeSummary`、`desktopScopeColor`；新增 `statusDetail`、`issueText`、`notices`、`hasNotices`、`unsavedNote`、`modeName`、`panelTint`；`operationErrorFeedback` 去掉外层 padding
2. 上表每个状态的右栏两行在 164pt 列宽下不截断、无“…”；无桌面运行 / API / 范围未知时都不出现“保护中”
3. 展开：右栏与展开区底色一致、两者之间无分隔线、终端区下方有分隔线；圆角处无溢出；悬停高亮只在收起时出现
4. 草稿：启用状态下把国家改成 JP → 右栏仍 `目标 SG`，出现“未保存 · 已保存为 SG · …”（守卫离线/回执过期时文字相同，不出现“运行”）；保存后该行消失、右栏变 JP；未启用时改草稿不出现该行
5. 仅检查网络：不保存、不启用、不纳入；新结果自动展开、可独立收起；未知不当通过；“上次操作未完成”通过检查后仍在
6. 停止保护仍弹确认；纳入保护仍弹确认并在确认时重新校验；未确认不接管、不关闭桌面
7. 异常整行：守卫离线 / 回执过期 / 已拦截 / 急停失败在收起时位于头部下方，展开时位于展开区顶部；API 桌面不再出现通用整行
8. VoiceOver：右栏朗读“保护：标题，第二行”，提示展开/收起；开关朗读“后台保护”
