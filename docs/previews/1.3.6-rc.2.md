# 1.3.6 RC2：刷新闭环与检查更新

日期：2026-11-02。实现分支：`codex/refresh-closure-updater`。这是源码候选与隔离验证记录，**不是正式发布、真实续期验收或本机安装完成说明**。

## 实现内容

- 底部刷新和切换后补查共用同一条生产编排，测试可注入完整依赖，不再靠 Demo 分支替代生产路径。
- 健康默认 CLI 登录可静默完成身份核验，不必为了识别状态再启动 `auth status`。同账号新凭据仍由既有每分钟观察发现，随后接续核验、备份和额度。
- 正常手动刷新不无条件启动原生恢复；确实临期、失效待确认、备份／核验待续办时才处理。服务器拒绝但本地到期时间仍在未来，也不会因此跳过用户主动的官方 CLI 确认。
- 一个官方恢复回合的结果直接复用；未取得新额度缓存时，补一次受身份、网络和限流约束的只读额度请求。不再用“命令成功”代替“额度采样成功”。授权耗时后的缓存新鲜度使用收尾时钟判断。
- 新的有效登录解除旧普通认证失败的等待；服务端 Retry-After 在手动、自动、新登录与恢复后补查之间共同保留。
- 自然续期后遇到临时网络故障，会保留待核验／备份步骤，之后接着完成，不再次旋转 token。明确原生失效不会被元数据观察清除；新的原生成功加在线身份核验则能清除过时错误，即使凭据字节没有改变。锁屏后恢复可读的健康登录也能静默核验并清除过时授权提醒，不需要为这个状态额外启动 CLI。
- 登录已在线核验而只是备份保存待授权时，仍保留可用登录的匹配结果。额度可以使用**同一完整身份、同一已验证凭据代次**的 CLI 凭据，不受桌面旧 token 尚未跟进影响；元数据或邮箱不够形成这条信任链。
- 一次 NativeCLIStorage 操作中，同一对象最多允许首个读取请求弹系统 UI，必要的最终读回仍读取新值，但禁止重复交互请求；取消／拒绝后的刷新回合不追着请求另一个凭据对象。
- 默认 CLI 状态、额度及当前登录恢复辅助命令共用有界输出／软终止加硬截止处理。只处理本次新建的辅助进程，不按进程名处理既有任务。额度子进程不会继承可能让 `/usage` 只读缓存的流量抑制开关；遥测、错误上报和 CLI 自动升级仍分别关闭。
- 手动回合交接期间，底部持续显示既有刷新反馈，相关账号操作不能同时开启另一轮认证。账号卡布局、导入入口与刷新位置保留。

## 授权与持久使用

密码窗口属于 macOS 钥匙串访问，不等于 OAuth 登录本身。不同的原生 CLI 凭据、桌面 Safe Storage、自有备份条目具有各自的访问控制；提示窗口即使显示同一个服务名，也可能是不同账号备份条目。

本轮没有缓存系统密码、修改真实条目 ACL、改成“任何应用可读”、删除重建凭据或把自有备份迁为明文。后续分发继续固定 Developer ID 团队与 Bundle ID，避免再用每次变化的 ad-hoc 构建替换真实客户端。**项目 build 目录中的 ad-hoc 包仅供开发验证，不能当成解决权限继承问题的分发包。**

首次由旧 ad-hoc 迁移、首次访问不同条目或官方 CLI 自己请求系统权限仍可能分别确认。稳定签名和同轮交互去重能减少重复访问，但真实“始终允许”跨重启／跨版本是否持续生效，本轮未用真实钥匙串做验收，不能宣称已经根治所有密码弹窗。

## 本地诊断摘要

真实版本仅在用户主动刷新后，尝试保存 `~/Library/Caches/dev.claudeswitcher.candidate/Diagnostics/last-refresh-summary.json`。内容仅含动作结果、时间、逻辑原生恢复调用次数、额度补查／缓存采纳及 NativeCLIStorage 读取类别计数。文件是应用自有缓存、权限 0600；保存失败不改变业务结果。Demo 测试不写这个真实路径。

不含 token、密码、邮箱、档案名、会话、原始 CLI 输出或 HTTP 响应。`interactiveRequestsAllowed` 表示该读取允许系统询问，**不是实际弹窗次数**；`actualSystemDialogsObserved=false`。范围仅是本次刷新回合，不把它冒充所有切号准备阶段或官方 CLI 子进程的完整审计。

## 更新与工具栏

- 面板设置齿轮收纳检查更新、登录时启动切换器、语言。保留普通应用菜单入口作为补充，但生产 `.accessory` 模式没有普通应用菜单栏，不能依赖它作为唯一入口。Apple SDK 的 `NSRunningApplication.h` 对此有明确说明。
- 使用平台标准 Menu 呈现，退出仍是单独的“退出 / Quit”。说明仅放在 help，退出不会调用守卫停止逻辑；登录项指切换器 GUI，不等于自动开启保护。
- GitHub Releases 公开接口，正式通道默认，预览版显式选择。后台每天最多一次检查，不自动显示菜单或窗口；显式菜单检查会重新检查，正在下载／校验或已有验证包就绪时保留该状态。
- 支持进度、取消、重试、返回与关闭。关闭更新窗口不退出切换器、不停止守卫。应用内下载完成后需要摘要、大小、固定签名团队、Bundle ID、语义版本与递增 build、本机架构及 Gatekeeper 公证验证；失败不提供打开动作。
- 安装包只读挂载验证，验证后卸载，不执行包内应用。仅在用户点击后打开 DMG，不静默安装、替换应用或重启守卫。文件已丢失时回到可重试状态。
- 下载归档没有 GitHub SHA256 digest 时读取同版 SHA256SUMS；没有唯一校验信息、错误平台、草稿或降级版本不作为可下载更新。正式更新不接受 Demo 或预览包冒充。

后续正式版若从 `1.3.6-rc.2` 转为 `1.3.6`，应保持语义版本正确并递增 `CFBundleVersion`，不能只删除 rc 标签却沿用同一个 build。现有 RC2 build 为 `20261102.2.0`。
