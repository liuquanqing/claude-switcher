# 账号缓存时间与全局底栏时间复核

## 结论

“账号缓存时间随账号卡”和“底栏保留最近成功采样时间”不是二选一。两者都应保留，但不得互相冒充：卡片说明**这个账号的数据状态与采样年龄**，底栏说明**面板最近一次被采纳的成功额度采样**。

因此，接受 Codex 关于补强账号卡时间的方向；反对把底栏时间搬走，也反对把缓存状态统一精简成“8 小时前更新 / Updated 8h ago”。缓存、未重新查询、重置待确认和失败必须是主界面可见信息，不能只藏在 help。

## 1. 账号卡与全局时间各自表达什么

### 账号卡：这个账号的快照

卡内时间应对应 `snapshot.fetchedAt`，回答的是：“这张卡当前显示的额度，上次成功采样离现在多久？”它必须和本卡的缓存、失败、重置待确认状态一起理解，不代表服务器此刻的额度，也不代表重置已经完成。

现有 `ProfileCard.usageFooter` 已经按卡片快照取时间，但分支并不完全一致（`App/Views.swift:614-643`）：

- live 且未到重置时间的 `.loaded` 不显示卡内 footer，可继续避免重复。
- `.cached` 和重置已到的 `.loaded` 已显示缓存文案。
- **非 live、未到重置时间的 `.loaded` 却落入 `usage.updated`，只显示“{age}更新 / Updated {age}”。** 这正是精简后会掩盖非活动缓存的现有缺口，应优先修正。

### 全局底栏：最近一次成功采样，不是全体账号体检时间

`lastRefresh` 只在成功结果被账号接受后赋值为该快照的 `fetchedAt`；失败保留原快照和时间（`App/main.swift:390-403`）。静默额度读取又只构造并核验当前账号的上下文，成功后也只接受该账号结果（`App/QuietUsageRefresh.swift:78-115`、`:118-145`）。

所以底栏时间的准确含义是：**最近一次被采纳的成功额度采样时间**。它不是点击刷新的时间、最近尝试时间、所有账号各自都成功的时间，也不是“全部数据新鲜”的保证。`Panel.refreshSummary` 的现有 help 已明确这一点，并要求以各账号卡片为准（`App/Views.swift:963-992`）。

底栏应继续保留现有时钟图标加相对时间，以及部分失败时的“相对时间 + 失败数量”。不要把它改成“全部已更新”，也不要用最近一次点击、最近一次失败或某张缓存卡的时间替代。

## 2. 卡内精确位置与建议文案

位置应沿用现有 `usageFooter`：**额度内容下方、卡片底部的现有单行状态区，左对齐**。不新增一行，不挪到账号名旁，不挪到全局底栏，也不改变卡片高度。这样时间与对应账号、旧百分比和重置状态在同一视觉单元内。

建议把缓存可见文案统一收紧为：

- 非活动/历史缓存：**`缓存 · 8 小时前`** / **`Cached · 8h ago`**
- 有缓存但刷新失败：**`刷新失败 · 8 小时前缓存`** / **`Refresh failed · cached 8h ago`**
- 有缓存但未发起刷新：**`未刷新 · 8 小时前缓存`** / **`Not refreshed · cached 8h ago`**

这里可删掉的是“更新 / Updated”以及“显示……的 / from”这类冗余结构，**不能删掉“缓存 / Cached”**。仅写“8 小时前更新”会让旧缓存看起来像本卡刚完成过一次更新。

help 只能补充，不能承担唯一的缓存提示。普通缓存 help 可保持简短，例如：

- 中：`该账号的上次成功采样时间；缓存不表示本轮已重新查询。`
- 英：`This account's last successful sample; cached data does not mean it was re-queried in this round.`

重置已到继续用现有 `usage.resetDueCachedHelp` 解释旧百分比不会自动归零或变成 100%；失败继续优先展示本卡真实错误 help，不能用通用缓存 help 覆盖错误原因。

## 3. 四类状态必须怎样区别

| 状态 | 卡内主界面表达 | 底栏表达与禁止误读 |
| --- | --- | --- |
| 正常新鲜 | live `.loaded` 且重置未到，维持现状，不额外增加卡内 footer | 保留最近成功采样的相对时间；只说明最近一次成功，不扩张为所有账号新鲜 |
| 非活动缓存 | 显示 `缓存 · {age}` / `Cached · {age}`；包括启动后载入的 `.cached`，也包括非 live 的 `.loaded`，后者不能再用裸“更新” | 若本轮没有成功数据，继续显示“用量未更新”，不要从缓存卡伪造一次全局成功刷新 |
| 重置已到 | 主标签保留 `待刷新 / Refresh pending`，footer 保留 `缓存 · {age}`；help 说明等待成功读取，旧百分比保持不变 | “重置时间已到”不等于已经重置，更不等于已经重新查询；不得改成“已刷新”或自动显示 0/100% |
| 失败 | warning 图标/颜色与 `刷新失败 · {age}缓存` 同时保留；年龄仍属于旧快照，不是失败发生时间 | 部分成功时保留 `{age} · {count} 个失败`；本轮无成功数据时用“用量未更新 · 失败数”。失败分支不得被精简成普通缓存 |

另外，blocked 应继续与失败区分：`未刷新` 表示没有请求，`刷新失败` 表示请求或读取未成功。loading 也继续显示“正在更新…”，不能提前把旧缓存时间写成新成功时间。

## 4. 对 Codex 建议的取舍

### 可取

- **单账号缓存时间跟对应账号卡。** 这是正确的信息归属，尤其能修复非 live `.loaded` 当前缺少缓存标记的问题。
- **压缩冗余文案。** `缓存 · {age}更新` 可以缩短为 `缓存 · {age}`；详细采样与重置说明留在 help。
- **不能用底栏唯一时间替代各账号时间。** 底栏只追踪最近一次成功快照，无法说明其他账号是否仍显示旧缓存。

### 应反对

- **反对移除底栏相对时间。** 用户已明确要求保留，且它仍能概括最近成功采样；正确做法是限定语义，不是删除。
- **反对把缓存统一写成“8 小时前更新 / Updated 8h ago”。** 这会掩盖非活动账号未在本轮重新查询的事实，也会与正常新鲜数据混淆。
- **反对把缓存含义只放进 help。** 触屏、键盘浏览和快速扫视时，主文本必须自明；help 是补充说明，不是状态标记。
- **反对重置与失败共用普通缓存文案。** 重置已到需要“待刷新”，失败需要 warning 和失败原因；两者都不是一次成功更新。
- **反对把底栏时间理解成所有账号都新鲜。** 现有 quiet refresh 和 `lastRefresh` 更新路径均不支持这种承诺。

## 5. 推荐的最小修改范围

后续若实施，范围应只包括：

1. `ProfileCard.usageFooter`：让非 live、重置未到的 `.loaded` 也走可见缓存文案；保留正常新鲜的空 footer、重置专用 help、失败/blocked 优先级与图标颜色。
2. 相关中英 localization：精简 `usage.cachedUpdated`，并同步精简失败、blocked 的缓存文案；普通缓存 help 补上“不表示本轮已重新查询”。无需新增时间字段或新 UI 组件。
3. **不改** `lastRefresh` 的更新条件、`refreshQuietUsage` 的当前账号范围、底栏位置及 `refreshSummary` 的正常/空数据/部分失败/全失败分支。现有 `refresh.summaryHelp` 与失败 help 已能限定全局时间语义。

以上为最初的只读评审阶段，后续用户确认后的实施记录见文末。
