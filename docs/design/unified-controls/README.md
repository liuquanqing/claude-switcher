## CLI 的真实边界

运行官方 Claude Code、使用官方登录、由第三方移动登录资料，是不同的行为。RC6 使用未修改的官方 CLI；普通桌面切换不再搬动默认 CLI 登录，复制命令仅指定配置目录，不会让新目录自动获得桌面账号的授权。显式的兼容同步仍会备份和替换默认登录，不能把它描述为官方文档推荐的多账号流程。

关联目标应是「桌面档案 → 已核验的 CLI 目录」，不以一次切号创建一个新目录：

1. 第一次打开该档案的 CLI，先核验已有默认 CLI。若实际账号和组织与桌面匹配，可以沿用原目录和原历史；不需要额外登录或复制凭据。
2. 已经存在该档案的关联目录，核对该目录的官方登录状态。已登录且账号匹配时直接打开。
3. 没有可复用的登录时，默认目录明确未登录且没有其他账号记录，就在默认目录完成官方登录。有其他账号或状态未确认时，提供独立终端等选项，不自动覆盖默认登录。
4. 权限、网络或命令异常表示「检查未完成」，不直接转换为「请重新登录」；账号不同需要选择正确账号，不静默替换。
5. 日后打开时仍优先核验默认目录；核验不符则沿用已核验的独立登录。正在运行的其他账号终端不由切换器改写。

登录方式不会因为按了一次登录按钮而变成另一套 CLI 程序。重要的是官方 CLI 在所选目录里管理登录及续期，切换器之后保留该存储，不把别处的凭据覆盖回来。两种模式使用相同 CLI 程序，并不意味着复制旧凭据与重新通过官方登录的状态和生命周期完全相同。

启动、打开面板、全局刷新与既有 15 秒观察读取本地账号记录和官方已写入的缓存，不启动 CLI、不会请求钥匙串授权或改写登录。已保存关联或身份相符的本地目录决定额度缓存来源；只有账号与组织都相符才采纳，保持官方原采样时间。读不到记录保持未确认，不推断退出登录。

首页展示终端账号摘要，详情提供「在终端打开」。从切换器打开的默认、独立终端，以及切换器发起的 CLI 登录续期，使用 macOS 已启用的本机 HTTP 代理。现有守卫与 TUN 检查照常进行；启动前还通过该代理检查 Claude 登录及 API 域名的出口。失败时不启动 CLI，不回退到无应用代理的路径。复制启动命令也包含该代理和已关联目录，但手动粘贴运行时不会重新核验出口；浏览器和普通终端仍由各自的配置决定。

「恢复旧备份」先核验并备份当前默认 CLI 登录，再替换其订阅凭据和账号记录；不会迁移历史或改独立目录。原版切桌面时会尝试自动替换默认登录，目标没有备份还可能清空当前登录；Preview 仅在用户确认且有可核对备份时替换。

发现旧备份不隐藏官方登录入口。默认 CLI 明确未登录时，设置页仍提供「在默认终端登录」；恢复失败时带原因返回选择页，用户可改选登录方式。

### 两个账号需要几个目录

不是预先复制两个登录。假如账号 A 已在默认目录登录并核对匹配，A 沿用默认目录；账号 B 首次需要时才准备自己的独立目录。以后 A、B 分别复用这两个位置。已经有独立登录的旧候选目录也会先核对，匹配就继续用，不搬动它的内容。

软件保存的关联记录只有账号、组织和目录，不包含令牌。尚未完成登录的目录是待核对的打开位置，不能显示「与桌面一致」。普通终端里的 `claude` 仍使用原默认配置；通过切换器「打开 CLI」才选择当前桌面账号的关联目录，已运行的终端不换号。

沿用默认目录时历史仍在原处；独立目录有自己的历史列表。旧会话不会被删除，也不会在这一步自动复制到新列表。如需带过去，使用现有的会话导入流程。本轮未对任何真实目录做准备或迁移。

## 保护与升级

用户只需「开启保护／暂停保护」。启用、组件更新后的重新连接、等待首份有效回报应由一个流程完成；进行中显示检查进度，真正失败才给原因和重试。不能把待启动误报为已保护，也不要求用户先手动检查、再关闭、再开启。

软件更新主操作为「更新并重启」。下载验证、应用替换、必要的守卫版本协调及失败恢复应有一致状态。已核对 Sparkle 的标准流程；本候选沿用现有 GitHub 下载、公证与签名校验，增加受限安装助手。安装目标限定为当前候选 App，必须是同一开发者身份、更新的构建和受支持的安装协议。守卫已绑定当前 App 时，原子交换完整 bundle 保留注册路径；旧路径在用户主动更新任务中先通过保护重试完成衔接。安装助手不调用守卫停用命令，也不关闭 Claude/CLI。不得用真实断网、真实登录或真实会话作为验收夹具。

## 依据

- [官方多账号配置目录](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)：每个目录保存自己的设置、历史和订阅登录；首次使用新目录需要完成登录。
- [官方 CLI 状态命令](https://code.claude.com/docs/en/cli-reference)：可查询认证方式和实际配置目录。无法确认不能当作匹配成功。
- [CC Switch v4.0.21](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.21-en.md)：区分独立目录启动与搬动默认登录，并说明后者不在官方文档覆盖范围。
- [Apple 设置原则](https://developer.apple.com/design/human-interface-guidelines/settings)、[反馈原则](https://developer.apple.com/design/human-interface-guidelines/feedback)：减少用户必须理解的配置，提供符合任务重要性的状态反馈。
- [Sparkle 程序化集成](https://sparkle-project.org/documentation/programmatic-setup/)：已评估的标准更新方案；本候选没有引入 Sparkle 依赖。

## 安装与回退边界

安装助手先验证两个完整 App，再等切换器正常退出；不能退出就保留旧版。交换后打开新版，只有新进程核对目标构建并完成保护回报确认，才写入完成信号。没有启动信号则正常请求新版退出后回退；若新版拒绝退出，保留两个版本并记录需恢复，不强杀。请求和阶段写在本应用的私有缓存中，恢复时仍要验证签名和版本。旧包保留作回退，未自动清理用户数据。

RC6 本身没有安装助手，首次进入支持一键更新的版本仍需一次完整安装。后续包必须包含并签名 ClaudeUpdater，同时通过公证；缺少协议或助手的包仍不能自动安装。真实 Developer ID 包的跨版本安装、系统权限和原生鼠标验收是候选进入发布前的独立门，不能由临时文件夹测试代替。

### 底部更新入口（同日）

底栏保持三组：目录/复制会话与采样时间在左，刷新、检查更新、设置与退出在右。检查更新从齿轮菜单移为独立下载图标；点击仍复用原检查流程，只有发现可用更新或已有下载任务才打开原更新窗口。检查中显示进度并禁用重复点击；已最新或失败在采样位置短暂反馈，详细原因保留在悬停帮助。设置菜单只保留包含预览版、开机自启动与语言。虚构回归 482 项通过，完整中英文面板截图已复核；未触发真实更新请求。

### 身份与行高最终复核（同日晚间）

本地记录与已核验摘要不混用身份：本地记录一行显示桌面档案名，弹层明确「来自本地记录，登录尚未在线核验」并可直接核验；已核验一致才显示「与桌面一致」及脱敏邮箱。终端不一致时显示默认 CLI 的实际资料或待确认，不能继续显示桌面档案名冒充一致。弹层提供对应核验、设置、登录或切换操作，原默认 CLI、官方额度与手动命令留在高级。

左右摘要以同一 `showsSecondaryLine` 展示结果对齐：本地记录时左右均一行，右侧显示「桌面保护中 · SG」；确有第二行时，右侧才显示出口/目标及检查时间。父卡片保存布局布尔值，首帧直接计算，后续通过 Binding 同步，不再依赖 PreferenceKey 的通知时序。保护卡片不读取 CLI 后端状态。482 项虚构控制器回归通过；单行、双行及核验弹层的最新中英文虚构截图已复核。较早高级展开补图缺少核验按钮属于按钮加入前的旧产物，未作为本版验收证据。


### RC11 精简保护设置（2026-11-09）

保护摘要保持「保护中 · SG」，展开区以网络结果为中心。弱标题与低强调的「暂停保护」不再抢占注意力；目标国家使用短输入框，代理模式与保存状态保持同一行，未修改仅显示勾，修改后才显示「保存更改」。结果首屏使用「网络通过 · SG」或明确失败原因，手动诊断的只读边界收进结果行和问号帮助，不再常驻重复说明。IP / WebRTC 体检与网络诊断同组展示，不影响门禁。中英文通过与失败截图已复核。

RC12 将诊断操作与结果合并为一个组件：未检查时为「网络诊断」，检查后就地显示通过或失败摘要；点击摘要展开代理、TUN 和出口详情，详情内提供「重新诊断」。IP / WebRTC 位于详情的辅助操作右侧，不与主诊断入口并列。未保存草稿时右侧提供「保存更改」，正常保护状态则以低强调「暂停保护」替代无信息量的「已保存」对勾。手动诊断继续只读，不能改变保护开关、桌面绑定、守卫判断或守卫回执时间。

发布前复核再移除无信息量的「保护设置」标题：诊断与右侧的启停操作同一行，避免整行留白。代理配置行继续保留国家、代理、保存勾；暂停只在诊断行出现一次。

RC12 后续界面调整：有结果时，刷新图标紧挨结果行，详情收起时也可重查；结果行只负责展开和收起。诊断说明和第三方 IP / WebRTC 体检都在详情内。底部代理选择框按内容收紧，设置有改动时才显示「保存更改」。

最终保留原版清晰的任务布局：诊断结果与刷新在左，保护启停在右，不为压缩一行改变用户已有操作习惯。检查时间收进帮助与悬停信息，过期状态仍明确提示。详情的「诊断说明」缩为问号图标，与 IP / WebRTC 同行；底部代理问号移除，代理兼容性并入同一说明层。代理选择保留系统菜单的展开、键盘操作和选中勾，触发器与国家输入框使用一致的深色底与边框。保护启停沿用同一按钮按真实 `enabled` 状态切换；「暂停后台保护」管理守卫服务，与顶部桌面纳入是不同动作。API 桌面不适用订阅保护，因此不再显示无效的暂停按钮。
登录核对成功与本地记录一致时，首页终端摘要都保持一行。核对结果与脱敏邮箱在终端详情内展示。桌面保护正常时，右侧同行显示刚核验的出口；证据过期时标明「目标」，核验时间收进悬浮说明。异常状态仍保留原因和动作。

桌面退出排查：Claude Desktop 自己的退出保护和 Switcher 网络守卫是两条路径。Switcher 只在账号切换或网络保护确实请求退出时写 macOS 系统日志（`dev.claudeswitcher` / `desktop-lifecycle`），记录来源、结果和守卫判定，不写账号、会话或凭据。正常轮询仍只更新回执；网络守卫不会重启桌面。

后台守卫对已纳入保护的桌面，仅在一路探测超时、其余两路均确认目标地区且代理和 TUN 仍在线时，用 3 秒超时重测原域名一次。最终仍无法确认出口或本机连接状态时，保留当前桌面并继续检查；只有实际测到非目标出口（即便其他域名未响应）、出口不一致或确认代理/TUN 断开，才因网络判定关停。保护配置无效的原有处理不变。手动诊断、启动和切换仍要求三路全部确认目标地区且代理/TUN 在线，不把部分结果当成通过。
