# 首页与模式一致性复核（2026-11-06）

本轮由 Codex 直接实现；用户要求对照老版本、普通与 API 模式、展开区域和已有规范统一检查。已有 [UI 设计规范草案](../UI设计规范草案.md) 仍是后续修改的约束，不再只局部补颜色。

## 保持与差异

- 共用：暖灰底、Claude 暖橙当前标记、账号卡网格、额度数字、相同两行 CLI/保护摘要、卡片内切换、单个设置齿轮、28pt 图标入口、退出按钮。
- 普通模式：顶部显示当前订阅账号与桌面运行/显示；终端行显示当前档案关联；右侧显示实际订阅保护状态并可展开管理。不能把守卫保护中推广到 CLI 进程。
- API 模式：顶部显示 API 模式与已识别的管理器；左侧仍展示默认 CLI 的实际认证状态；右侧明确保护不适用于 API 桌面，展开的是订阅保护设置，不能暗示当前 API 被保护。已保存订阅档案不能标为桌面当前账号。
- 未知状态继续 UNKNOWN，不能根据桌面 API 来源推断 CLI 的认证管理方，也不能把本地身份记录称为在线有效性核验。

## 视觉与状态

1. 不透明 `sub` 用于必要辅助信息；重置文字提升到 10pt，普通信息不再用 opacity 降低可读性。`claude` 的“当前”也不做透明衰减。
2. 数据卡一张一行辅助状态：新鲜成功不显示；旧数据显示本账号更新时间；失败用中性图标与该时间，具体原因保留 help 和辅助功能标签；blocked/无数据/加载中保留原分支。
3. 窗口重置到期显示“重置时间已到 / Reset time passed”，不再另起“待刷新”与账号更新时间争夺注意力。
4. 底栏不再对同一失败叠加黄色告警；仅在存在全局未更新等摘要时使用中性信息图标。卡片详情仍保留，不能借美化隐藏失败或假装数据已更新。
5. 未登录与添加卡只保留小图标和短文案，不为填满高度增加解释；卡片高度、添加位置与网格不变。
6. 展开设置沿用服务控制 → 配置/保存 → 诊断/结果的层级；保存、开启和诊断各自独立动作，不能自动保存或默认放行。失败和 UNKNOWN 不能标为通过。
7. 认证说明只展示状态、最近观察与默认 CLI 范围；桌面模式及额度页提示不解释所有运行中终端。
8. API 的英文短状态改为“Not for API desktops”，中文为“保护不适用 / 订阅桌面专用”；普通终端标题保持简短，不用不一致的长短命名。

## 验证边界

普通与 API 首页、展开设置、旧额度失败、窗口重置到期使用新编译的虚构渲染器核对中英文；418 项控制器回归通过。没有使用真实账号、会话、网络故障或原生 VoiceOver/键盘验收。原生系统按钮的颜色以真实窗口为准，离屏图只验证布局与语义。
