### `MOVE TO PERSONAL` 具体做了什么

原版按钮出现在保存的 CLI 档案名与桌面档案名不同的时候。它调用 `moveTerminal` → `switchCLI`，不会移动桌面目录。它会先保存已有默认 CLI 的 OAuth 和身份块，再把目标备份写到默认 CLI 存储。没有目标备份时，目标 OAuth 为 `nil`，会移除当前默认 CLI 的订阅登录。原版绿色勾由保存的档案名是否相等决定，不等于官方 `claude auth status` 确认已登录。新版保留入口的可见性，按钮打开判断流程，只有确认过的恢复才允许写入默认存储。

正式版与当前共用同一备份事务和凭据路由：能处理钥匙串、凭据文件或一致的双份存储，不确定来源就拒绝写入；原版只改钥匙串的 Claude OAuth 字段。没有证据说明正式版或原版能替一个从未保存过 CLI 登录的桌面账号生成有效 CLI 登录。

### UI 取舍

原版底栏的排版易懂，但其 `lastRefresh` 在查询轮结束后就被设为当前时间，不能证明每个账号成功取得新额度。Preview 保留每个账号的采样时间，底栏只显示最新一次成功采样的相对时间；各账号的时刻和跳过原因在帮助里。卡片保留百分比及窗口实际记录的重置时刻。

原版 5 小时百分比是 46 pt、重字，放在独占的一行；正式版 1.3.5 和 Preview 的主百分比是 28 pt、粗字，与周额度并排。绿、黄、红色值相同。截图看起来更亮主要有字体面积和信息层级差异，本轮不更换配色或整套卡片布局。

原版和 Preview 过去写同一份 `Claude-Profiles/.cache`。原版的结构没有账号及组织身份；本机两张卡的共享缓存都出现了这种结构。Preview 改为只写自己的缓存，旧文件仍可兼容读取。旧缓存的邮箱和数值只作展示，不授予终端关联或备份恢复。显式使用终端且缺少完整桌面身份时，先走已有的桌面账号核验。

后续可借鉴原版的全档案刷新，建议只在用户手动刷新时尝试已保存且可独立核验的停放订阅档案，后台仍只采样当前桌面；每个档案单独检查身份、出口、凭据状态和限流。用户停放的旧会话与 CLI 登录都不是刷新前置条件。这一扩展不包含在本轮终端改动里。

对原生终端登录错误的边界：已确认默认 CLI 在检查时报告未登录。没有该次终端的具体报错，不能判断是网页登录、认证回调、组织选择还是本地保存失败。这轮不改官方登录流程，也不使用真实账号作为测试材料。

验收顺序：先用假数据证明可用目录复用优先、找到了备份也不会自动写入、取消及账号变化后无恢复动作、缺少备份时可以走官方登录、旧版缓存不会覆盖 Preview 身份。随后核对 Kimi 的前端差异，编译与测试通过后作为本地源码候选交付；本轮不替换已安装版本。
