# 用量刷新与重置时间

## 官方 CLI 缓存与账号匹配

- 后台只读取默认 `.claude.json` 中官方 CLI 自己写入的 `cachedUsageUtilization`，本程序不会为查询额度读取订阅 token，也不再执行直接 OAuth 跨账号查询。
- 只有与当前默认 CLI 账号的 UUID/组织唯一匹配的保存卡片可以更新；其他账号保留历史缓存，不切登录，也不临时启用其他账号。
- 采样时间使用官方缓存的原生 `fetchedAtMs`，不是命令完成时间或本程序读取时间。缺少新数据时保留各卡原时间。
- API 模式下这些仍是订阅额度，不是 API 额度。菜单栏在 API 模式只显示 `API`，未知模式不拼接缓存百分比；模式变化会立即更新标题。

## 手动官方 CLI 与账号边界

- 只有手动全局刷新按钮传入原 `allowInteraction: true`（现表示手动），在门禁通过后运行官方 `claude -p /usage` 并读回官方缓存。启动和定时刷新保持 `false`，只读缓存。
- 官方 CLI 可能正常处理自己的认证或续期，因此不承诺它完全不写原生凭据；本程序不会切换账号或临时启用其他账号。
- 手动查询仍需有效的网络、地区和守卫门禁；unknown 不通过，桌面 API 启动仍不放行，API 管理器配置不变。

## 风险与隔离验证状态

用户已选择官方 CLI 路径。直接 OAuth 跨账号查询保持隔离、未部署；当前官方 CLI 实现也仍处隔离验证，未安装、未发布。见 [USAGE-QUERY-RISK.md](USAGE-QUERY-RISK.md)。构建和测试通过不代表平台授权。

## 底部刷新摘要与通知

- `lastRefresh` 只来自采纳的新官方采样，并使用其原生采样时间。只有本轮存在成功数据时，摘要才显示对应更新时间；无新数据时保留原时间，不显示“最近刷新刚刚”。
- `usageNotice` 在底部摘要的帮助中说明无法读取、未唯一匹配或缓存较旧等原因，不作为“上次切号错误”展示，也不覆盖 `banner`。`banner` 继续优先保留切换等操作失败原因。
- 每张卡片始终使用自己的快照时间与状态；读取失败、门禁不通过或尚未读取时保留已有缓存和对应说明。

## 重置字段与时间语义

- “5 小时剩余”使用 `snapshot.session.resetsAt`，对应服务端 `five_hour` 窗口。
- “每周剩余”使用 `snapshot.weekly.resetsAt`，对应服务端 `seven_day` 窗口，不使用 `seven_day_opus`。
- 上述技术字段映射只保留在本文；产品帮助使用“订阅账号的 5 小时窗口 / 每周总额度”等自然语言，不展示 Swift 或 API 字段。
- 未来的 5 小时重置时间显示倒计时；未来的每周重置时间显示星期和时分。`DateFormatter` 使用本机时区。
- 帮助提供服务器实际重置时刻和缓存采样时间，均为本机时区的完整日期与时间；缺少时间时明确显示未知。卡片底部仍保留相对缓存年龄。
- `resetsAt <= now` 时，两列主标签显示“待刷新 / Refresh pending”，详细含义放在帮助中。旧百分比保持不变并标注缓存；不自动改成 0% 或 100%，也不编造下一次服务端重置时间。
- 缓存年龄与采样时间来自 `snapshot.fetchedAt`，不是底部刷新轮次时间，也不是后台守卫检查时间。

## 纯显示更新

用量卡片的时间区域和底部刷新摘要各由 60 秒 `TimelineView` 驱动。时钟只重新计算倒计时、到期状态和缓存年龄，不调用 `Store.refresh`，不发起网络请求，也不重建整个面板。新增账号的未保存输入和原生语言菜单不受这些局部时钟驱动。

`countdown`、`weekdayTime`、`weeklyReset` 和 `ago` 都支持 trailing `now: Date = Date()`，旧调用保持可用。确定性测试可全部使用虚构时间，例如：

- 取样 `2026-01-01T00:00:00Z`、现在 `2026-01-03T00:00:00Z`：`ago` 在中英文分别返回“2 天前”和“2d ago”。
- `resetsAt` 为 `2026-01-02T00:00:00Z`：两个窗口都返回到期待刷新文案。
- 未来时间仍按原格式返回倒计时或本机时区的星期时分。

## 地球图标与原生复核

底部普通图标和地球现在共用同一个 `FooterIcon`，都由普通 SwiftUI `Button` 承载。地球点击后才在 28×28 按钮下方锚定原生 `NSMenu`；菜单只有中文、English 两项，保留选中勾、原生方向键/回车操作、Escape 取消和全局语言设置。同步 `popUp` 返回后释放本次选择回调，并清除语言按钮 hover，避免菜单跟踪期间缺少 `mouseExited` 造成残留。

旧代码的证据是普通 `Button` 与原生 `Menu` 两条不同渲染路径；这能解释为什么相同颜色常量不足以保证原生状态一致，但不是用户机器上的像素级成因证明。构建不代表视觉通过。仍需用 `CSPreviewPopover=true` 的真正 `NSPopover` 复核静止、hover、菜单开启和关闭后的颜色与位置、键盘选择、Escape 及关闭后无高亮残留；普通 Demo 窗口和离屏渲染不能替代这些检查。
