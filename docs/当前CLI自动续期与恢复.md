# 当前 CLI 自动续期与恢复

日期：2026-11-02。基线：1.3.5 后的 `a8aa25c`；实现分支：`codex/current-cli-renewal`。这是候选后端，不是已安装或已发布版本。

## 范围与触发

1.3.5 的自动任务主要查额度，旧 `CLIBackupRecovery` 负责切换目标的备份恢复，优先保留当前原生登录，不处理当前登录的日常续期。本轮新增独立的 `CLICurrentRecovery`，不移除这个保护规则，也不拿旧备份覆盖当前默认登录。

- 后台每分钟最多观察一次默认 CLI 登录；保存凭据进入到期前五分钟或已经到期时准备恢复。正常额度更新仍按原有节奏执行。
- 底部手动刷新可执行一次原生检查。即使本地时间戳还没到期，官方 CLI 明确要求重新登录时，也不能继续显示成本地登录正常。
- 联合切换、CLI 同步成功后的刷新复用恢复结果；已经执行了原生恢复时不紧接着再跑一遍原生额度命令。
- 发现同一账号的原生凭据已被其他 CLI 更新，核验并备份新版本，不恢复旧快照。默认保存身份的恢复不代表运行中所有任务已经切换身份。

## 官方 CLI 路径

只运行本机未修改的 `claude`，先读取版本，再在临时空工作目录调用既有官方 `/usage` 命令：

```text
claude -p /usage --output-format json --tools "" --strict-mcp-config
  --mcp-config '{"mcpServers":{}}' --setting-sources ""
  --no-session-persistence --permission-prompts none
```

CLI 的 HOME 仍是默认 HOME，不设置另一个 `CLAUDE_CONFIG_DIR`，不把当前 refresh token 复制到第二目录。续期交给官方 CLI 及其原生协调机制，切换器不请求 OAuth token 交换接口，不把 token 放进参数或日志。身份复核沿用已有的只读 profile 接口，须通过网络门禁并匹配完整账号 UUID、组织 UUID。

当前适配器要求 CLI 2.1.268 或更新版本。旧版本、未知版本或不支持的命令参数显示不受支持，不冒充“账号失效”。本机 2.1.314 的帮助参数已在空 HOME 下只读核对；**没有执行真实登录续期**。

依据：[官方认证目录说明](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts)、[CLI 参数](https://code.claude.com/docs/en/cli-reference)、[官方关于同目录并行会话协调续期的说明](https://code.claude.com/docs/en/troubleshoot-install#not-logged-in-or-token-expired)。既有 `/usage` 调用的第三方参考为 [Magpie 固定版本实现](https://github.com/yetone/magpie/blob/79f83798fd4b587c1f916496c60cef97222fc73f/internal/provider/claude_usage_cli.go)；第三方实现不作为平台授权或真实账号兼容性证明。

## 提交与失败处理

| 结果 | 行为 |
| --- | --- |
| 未到期且不需要显式检查 | 不启动 CLI，不改变已完成的验证时间 |
| 官方 CLI 更新了登录 | 读回当前登录，重查网络、档案、模式、身份和凭据版本；匹配后更新自有备份并回读 |
| CLI 已写入新登录，但命令超时或失败 | 优先读回新版本，不因退出码回滚凭据；能够核验时继续完成备份 |
| 在线核验暂时失败 | 保留原生新登录，标为待核验；后续只续办核验和备份，不重复消耗刷新凭据 |
| 读回或备份被系统授权拦住 | 提示主动刷新；保留待处理步骤，不回填旧登录 |
| 明确无刷新凭据且已到期，或官方 CLI 明确拒绝恢复 | 提示在官方 CLI 执行 `/login`，不要求先 `/logout`，不循环重试 |
| 网络失败、超时、限流、单独出现 HTTP 401/403 | 不直接判定刷新凭据撤销；保留现状，稍后重试 |
| API／第三方认证、自定义目录、身份不一致或来源不明 | 不处理原生登录，不改 Magpie、CC Switch 的配置或密钥 |
| 期间换号、换组织或凭据再次变化 | 停止提交，保留外部新版本，不按旧观察更新备份 |

旧错误不会被每十五秒的元数据观察改成“正常”，用户关闭的提示也不会每次刷新都重新出现。真实换号后清除上一账号的恢复提示。临时失败默认等待五分钟；已确认需登录、需授权或命令不支持时，对同一凭据版本暂停自动尝试，显式刷新或新凭据版本才能继续。

切换器不写当前 CLI OAuth 字段、身份文档或关联标记；原生 CLI 是唯一执行这些认证写入的程序。自有备份写入禁止后台授权 UI，失败不删除或回滚原生新登录。CLI 的输出只在内存中保留最后 64 KiB，返回固定错误分类，不保存原始输出。只终止本次新建的恢复辅助 CLI，不终止已有终端、Claude 桌面或守卫。

## 后台授权策略

用户已选择“先静默尝试；需要授权时先由切换器提醒，再由用户主动交给官方 CLI／系统授权”。不把一次手动确认当作以后都可以在后台弹系统窗口。

`--permission-prompts none` 只管 CLI 的模型／工具权限，不能保证禁止 macOS 钥匙串弹窗。后台启动原生恢复必须同时满足“后台恢复已启用”和“适配器能保证无系统弹窗”。已授权读取某个条目不等于原生子进程不会再询问授权；不确定时不启动原生子进程，先显示需手动恢复的提示。

当前未修改的官方 CLI 适配器尚无可验证的系统弹窗禁止契约，因此 `guaranteesNoSystemPrompt = false`，不会仅凭后台开关就放开原生执行。假 CLI 的无弹窗能力只用于测试，不能拿来当成真实官方 CLI 的保证。已有官方 CLI 自己续期后，切换器仍可静默核验并更新备份。

用户主动恢复时先经过实时网络／地区门禁，再读取可能需要系统授权的凭据；授权耗时后，在启动官方 CLI 前重新过门禁，核验身份前再检查。错误网络或 unknown 不请求系统授权，也不解释为登录被撤销。

当前候选复用软件内提示和底部刷新入口；前端交互建议只在需要时提供“授权并恢复”动作，不常驻大段说明、不自动弹出下拉面板。本轮不自行改变前端布局，也不修改真实设备偏好设置。

## 验证及真实环境边界

测试全部使用虚构账号、临时 HOME、假 CLI 可执行文件、模拟钥匙串调用和注入的网络门禁／身份响应。覆盖当前账号恢复、原生已续期时保留新版本、身份变化、读回受阻、备份失败后续办、明确登录失效、网络故障、冷启动、提示去重、无后台同意不启动、兼容版本、大量输出及超时。

本轮不调用真实账号的 `/usage` 或 `/login`，不读取真实 token，不创建或写入真实钥匙串，不安装、重启或停止本机／MBP16 应用、现有 CLI、守卫或代理。假数据通过不等于真实认证、钥匙串系统弹窗和多工具协作已验收。Magpie 等第三方写入者是否遵守官方 CLI 锁，不能由本项目强制保证；检测到变化只停止提交，不强制回滚。


交付仅同步 GitHub、GitLab 的 `codex/current-cli-renewal` 分支，不更新公开主分支、不创建发布标签、不替换安装包或两台设备上的 1.3.5。后台偏好已明确为静默优先；当前原生适配器没有禁止系统弹窗的可验证能力，保持先提醒、用户主动恢复的回退。

## 网络保护的实际边界

恢复流程包含现有代理、TUN、目标国家、守卫状态门禁；用户确认不能绕过它，授权后也不复用授权前的检查结果。本轮没有改变正在运行的守卫。

这是操作前后放行检查，不是 CLI 网络层即时断流。现有守卫不会因本功能而全局接管普通 CLI 任务，也不能保证原生恢复进程运行中任意时刻都已被包级阻断；网络层保护仍属独立方案。不能把“开始时检查通过”写成“全程绝不直连”，未在真实网络上做故障测试。



## 最新验证结果

精确候选提交 `d6cb36ffc14e994a1ac6a3b89fe0773bac0fb02f` 的[云端 CI](https://github.com/liuquanqing/claude-switcher/actions/runs/41375345713)全部通过：223 项核心测试、276 项控制器／进程隔离检查、发布构建和签名校验。对应本地回归同样通过。

临近到期但当前凭据仍可用、且不能保证无系统弹窗时，安静等待现有官方 CLI 自行刷新，不制造授权告警。官方 CLI 已明确要求重新登录的同一凭据版本，也不能被未来的本地到期时间抹掉。

这些结果只覆盖虚构身份、假 CLI 及模拟钥匙串／网络；不作为真实账号、真实系统弹窗或网络层断流的验收。仍只同步候选分支，不安装、不发版、不改变两台设备的登录、会话、网络或守卫。

## RC2 后续
