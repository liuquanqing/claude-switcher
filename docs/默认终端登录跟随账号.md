# 默认终端登录跟随账号

日期：2026-11-19。候选工作副本 `_qa/cli-account-follow-up`，基于 `f1f7f2e`。未安装、未发版；真实登录、钥匙串备份和运行中的会话未被读取或修改。

## 目标

切到哪个桌面账号，普通终端里的 `claude` 就用哪个账号；每个账号保留自己的独立目录作为原件，默认目录只是当前账号的视图。切换保留上下文；旧终端只提示，不终止。这与 CC Switch 的“一次一个当前账号”一致，多了一层独立目录，避免 Personal 切换覆盖 design 的独立登录。

## 实现

核心：`Sources/SwitcherCore/CLIDefaultMirror.swift`

| 步骤 | 行为 |
| --- | --- |
| 找原件 | 已保存的独立目录绑定 → 身份键目录 → 旧的档案名目录；默认目录永远不作为来源 |
| 同步备份 | 原件里的登录比备份新才覆盖；已核验且更新的备份不被过期原件降级；账号或组织不符拒绝 |
| 写入默认 | 复用 `CLITransaction`：先备份切出账号的默认登录，在线核验目标，只替换 `claudeAiOauth` 和 `oauthAccount`，回读，失败按既有事务回滚 |
| 共享上下文 | `history.jsonl` 和 `projects/**/*.jsonl` 用硬链接补到默认目录；同名但内容不同的文件不动；不做符号链接 |
| 旧终端 | 切换前后各做一次只读 `ps`，本应用自己启动的辅助 CLI 不计入；仍存活的旧终端数量写进提示，不发送任何终止信号 |
| 目标没有登录 | 默认登录保持上一个账号，提示“请在终端里登录该账号”，不清空 |

接线：`App/DesktopOnlySwitch.swift`。桌面目录先按既有 `DesktopOnlyFlow` 移动，随后调用 `CLIDefaultMirror.follow`；CLI 跟随失败只提示，不回滚桌面、不清空终端。跟随期间刷新 `cliConnection.defaultLoginDidChange()`、清除旧的恢复提示并安排额度补查。

反向同步：`App/CurrentCLIBackup.swift` 的被动备份前，若当前账号有独立目录，先把默认目录里同账号的新登录写回独立目录（`CLIDefaultMirror.refreshOwnDirectory`），只写两个自有字段，过期的默认登录不覆盖仍可用的原件。这样官方 CLI 在默认目录续期后，下次切换恢复的是新凭据。

`App/BoundedCLICommand.swift` 记录本应用启动的辅助进程 PID，供终端计数排除。

## 边界

- 默认目录使用 API key、自定义目录或其他认证配置时不写入，只提示。
- 不替用户终止旧终端；旧进程继续用它启动时的登录，新终端用新账号。
- 硬链接只共享已有文件；运行中的 CLI 原子替换文件后自然断开链接，后续写入各自独立。
- 桌面切换后 CLI 跟随需要一次在线核验，走既有 CLI 网络门禁；核验失败默认登录保持原样并提示。
