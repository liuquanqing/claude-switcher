# 旧预览版一键升级与紧凑窗口复核

日期：2026-11-07。范围为 RC9 之后的本地修复，尚未形成新版本、公开附件或本机安装。

## 实际原因

本机为 RC8 build `20261106.8.10`，具有有效 Developer ID 签名，但没有加贴公证票据，Gatekeeper 返回 `Unnotarized Developer ID`。RC9 包则为 `Notarized Developer ID`。

更新助手此前同时要求已安装旧包和待安装新包通过 Gatekeeper，因此合法的旧预览版无法升级。现在旧包继续验证 Bundle ID、构建号、Team 和嵌套签名完整性；仅待安装的新包额外要求 Gatekeeper 公证通过。下载阶段的 DMG/App 公证验证保持原样。

## 界面

更新窗口不再重复产品名和多余解释，使用版本、当前阶段和一个操作区。安装中为“正在安装并重启…”，关闭入口改为“稍后”；失败仍显示真实原因和重试，不将错误简化成成功。

中英文安装中与失败窗口使用当前 SwiftUI 视图及虚构更新状态离屏复核。未声称原生键盘、VoiceOver 或真实窗口交互已验收。

## 隔离验证

- 250 项核心测试、418 项控制器检查通过。
- 生产签名验证代码直接证明：未公证旧包通过身份校验，未公证待安装新包被拒绝。
- 虚构新 App 经 Apple 提交 `2c5f6b1c-39fd-4440-b695-3096807a9919` 接受、加票和 Gatekeeper 验证；它不含账号、会话或凭据。
- 在虚构 HOME/Applications 中使用当前生产 `ClaudeUpdater`，由正常退出配合完成未公证旧版到已公证新版的替换与启动确认，`state=complete`。回退包保留。

完整发布包、全部失败回退案例、云端 CI 和本机安装均为 `NOT_RUN`。RC9 发布附件未修改。
