# 网络检查呈现优化（前端）

改动文件：`App/ProtectionView.swift`、`App/Views.swift`（只改了 TerminalStrip、ProfileCard 页脚和 Panel 页脚）。
未改 Store / ProtectionController / Core / main.swift / build.sh，也没有新增后端接口。

> **未构建，也未做原生 QA。** 本轮没有 Bash，代码只经过静态阅读，编译和真机验收由 Codex 负责。

## 三种动作各自触发什么

| 动作 | 位置 | 触发 | 不会做 |
|---|---|---|---|
| 普通刷新 | 页脚 ↻ | `Store.refresh()`：先过网络门禁；通过后读各账号用量并核验默认 CLI 登录，未通过则只读本地 CLI 状态，不请求用量 | 不改保护设置，不启用保护，不纳入桌面 |
| 仅检查网络 | 保护设置内 | `controller.checkNow()`：按**当前草稿**探测代理、TUN 和出口国家 | 不保存，不启用保护，不打开 Claude；不改变 `lastDecision`，也不清除 `operationError` |
| 纳入保护 | 状态行下方（不必先展开设置） | 弹出确认框，确认后才调用 `controller.protectCurrentDesktop()`，把正在运行的订阅桌面记录为受管 | 不切换账号，不重启或停止桌面，不停止 CLI；刷新 UI 或打开开关都不会自动触发 |

“检查并打开”沿用原逻辑：按已保存配置走原门禁。

## 取舍

### 网络检查结果直接显示
- 删掉了“检测详情 / 了解检查 / 高级信息”三层折叠。点“仅检查网络”后，按钮下方直接出现结果块，内容依次是：
  1. 结论一行：通过 / 未通过的具体原因（代理未连接、未检测到 TUN、各域名不一致、无法确认、出口 JP 而目标 SG），再加上检查时间。
  2. 三格结果：代理、TUN、出口国家。状态有：通过（绿）、未通过（红）、未知/未确认（黄，按不放行处理）、未检查（灰，仅限还没有任何报告或自动模式的代理格）。
  3. 一行脚注：“仅诊断，不改变设置与保护状态。”只描述本次动作，不写“未启用保护”之类的否定状态，避免和上方“后台保护中”冲突；开启保护与纳入桌面的区别由状态区和确认框说明，这里不重复。脚注右侧放第三方 IP / WebRTC 链接，悬停提示写明“仅供参考，不作为门禁”。
- 检查进行中，结论行显示进度，三格全部换成灰色“检查中…”占位（`ellipsis.circle`），不再显示上一轮的绿勾/红叉；时间戳和“输入已修改”提示也先隐藏，完成后再显示本轮结果。
- 两处如实呈现：
  - 自动模式下代理就是 TUN 的结果（`NetworkProbe` 里 `vpn = tun`），所以显示“随 TUN 判定”并用灰色，不算作一项独立的通过。
  - 出口国家为空时一律显示“未确认”（黄）。`NetworkProbe.observe` 在 HTTP 前后都会检查代理/TUN，所以“代理或 TUN 为 false 且国家为空”既可能是没发请求，也可能是请求后被丢弃，前端无法区分，不显示成灰色“未探测”。悬停提示按代理/TUN 是否通过给出不同原因，都写明按未通过处理。
- `ManualNetworkCheck` 没有记录代理模式，所以视图在检查完成时记下当前 mode（检查期间 picker 是禁用的）。如果检查后改了国家或模式，结果块会提示“输入已修改”；如果按未保存的草稿检查，会提示“保存前顶部目标不变”。

### 说明
- 只保留一个“检查说明”按钮：整块 28pt 高，图标和文字都能点，点开是 popover。里面写了三种动作的区别、后台约每 `SafetyConfig.interval` 秒复查一次（非实时）、只保护订阅桌面 / API 不纳入 / CLI 只核验不保护（各一句）。`desktopScopeDetail` 不再放进这里，只在设置里“保护范围”一行和状态列的悬停提示（`desktopScopeHelp`）中出现一次，避免与通用范围句重复。设置区不再常驻边界说明文字。
- 代理模式的“?”改成 22pt 热区的 popover，不再在页面内展开。

### 历史错误
- `operationError` 移到卡片层（设置收起时也能看到），标题改为“上次操作未完成”，下面一行灰色显示原文。关闭按钮热区 26pt，悬停提示写明“当前状态以上方为准，关闭不改变保护”。任何检查都不会自动清除这条错误。

### 当前桌面未保护
- 当订阅桌面正在运行、守卫在线、当前门禁通过、保护已启用、桌面未受管、且没有其他操作进行中时，状态行下方会常驻单行“当前桌面未纳入保护”，旁边是“纳入保护”按钮。常驻区只放状态和操作，不再写解释；按钮悬停提示只写“需先确认”。
- 模式与后果只在确认框里说一次：标题“将当前桌面纳入保护？”，正文“仅限订阅桌面（非 API）。纳入后若网络不符，守卫可能关闭此桌面；不会切换账号，也不会停止 CLI。”，确认按钮“纳入保护”。不承诺已运行的任务不受影响。点击确认时会重新校验上述条件（`offerDesktopProtection` 且非 `busy`），不满足就什么都不做。
- 以下情况不出现这一行：网络未通过、守卫离线、API 或未知范围。这些情况下状态继续显示“已拦截”“待确认”“未纳入”，不会冒充保护中。原来设置里重复的那一行已删除。

### 新鲜度去重
- 卡片：只有在本轮成功拿到、且不超过 10 分钟的数据（`p.live`）时不显示时间，其余情况照常显示：正在更新、刷新失败加缓存、未刷新加缓存、缓存时间，以及超过 10 分钟的“X 前更新”。
- 页脚：显示这一轮的实际结果，而不只是一个时间：
  - 任一卡片被门禁拦截时显示“用量未刷新”（黄）。拦截的那轮不会更新 `lastRefresh`，所以不能显示“刚刚”。
  - 有失败时显示“最近刷新：X 前 · N 个失败”（黄）。
  - 其余情况显示“最近刷新：X 前”（或“刚刚”）。悬停提示写明这是最近一次刷新动作的完成时间，各账号是否成功以卡片为准，也不是后台守卫的检查时间。
  - 卡片不再显示“刚刚更新”；缓存、失败、被拦截等异常在对应卡片上就地显示。
  - 刷新进行中显示“刷新中…”。
- 刷新按钮的悬停提示写明：先过门禁，再读用量并核验 CLI；不改保护设置，不启用保护，不纳入桌面。

### 终端区
- 状态为“已一致”或“暂未核验（存储不支持）”时，不再常驻“重新检查”这一行，由页脚刷新统一核验。ⓘ popover 底部仍保留“立即核验”（`verifyDefaultCLI`），加了一句“底部刷新会一并核验”。
- 未核验、不同、需要登录、其他认证这几种状态，仍然显示“核验登录 / 重新检查”，状态为“不同”且桌面是订阅时另有“同步到 X”。同步的确认流程没有改。

## 待 Codex QA 清单
1. 编译：`ProtectionView.swift` 用到了 `onChange(of:)` 单参数闭包、`Text(date, style: .time)`、`Link`、`SafetyConfig.interval`，需要确认在当前部署目标上能编译通过；`Views.swift` 中 TimelineView 闭包内用了 `let`。
2. 头部 HStack 加了 `.fixedSize(vertical)`，状态列加了 `maxHeight: .infinity`。需要确认状态列整列都能点击，终端区在没有操作行时垂直居中，ⓘ popover 的位置也正常。
3. 演示模式下逐一核对：通过、`--demo-blocked`（JP≠SG）、自动模式（显示“随 TUN 判定”）、输入非法国家（显示“输入无效”且不出三格结果）、检查后修改国家（显示“输入已修改”）、代理未连接（国家格显示黄色“未确认”，不是灰色）、通过后再点一次检查（检查期间三格都是灰色“检查中…”，不残留上一轮绿勾）。
4. `--demo-unmanaged`：设置收起时可以看到单行“当前桌面未纳入保护”和“纳入保护”按钮，没有第二行解释；确认框正文完整说明仅订阅、网络不符可能关闭、不切账号、不停 CLI；确认后行消失，状态变为“后台保护中”；取消后什么都不改变。
5. `--demo-blocked --demo-unmanaged`、`--demo-guard-unknown`、`--demo-api`、`--demo-unprotected`：都**不应**出现“纳入保护”行。
6. `--demo-operation-error`：保存失败后，卡片层显示“上次操作未完成”；再点仅检查网络通过后，这条提示仍然在；点 ✕ 可以关闭。
7. 页脚：演示中 `CSPreviewUsageState=blocked` 时显示“用量未刷新”，`failed` 时显示“最近刷新：… · 1 个失败”，正常时显示“最近刷新：刚刚”。卡片在 live 状态下不显示“刚刚更新”。
8. `--demo-cli-mismatch` 时出现“重新检查”和“同步到 X”；状态为一致时没有操作行，ⓘ 里的“立即核验”可用，`busy` 时禁用。
9. 可访问性：VoiceOver 读三格结果时应读成“代理：已连接，通过”这样的完整句；状态列和各按钮的 label 和 hint 都存在。
10. 真机（只读观察）：外部已运行的订阅桌面要显示接管行，而且 UI 刷新或开关保护都不能自动接管。
