# 界面状态与密度调整

本轮由官方 Claude CLI 接手前端。以下区分「已完成的静态修改」与「待 Codex 原生验证」。没有 Bash，未构建、未运行 App。

## 诊断

对照 `reference/main-cards-reference.png` 与现状：

- **整体偏大，主要来自卡片本身与“占格”的空卡**，不是主账号区单独偏大。原数据卡 188pt（30pt 大数字 + 额外留白），空态 / 添加卡 132pt 且在网格行内居中，于是同一行出现两种高度、空卡悬浮。
- 取舍：**不等比缩小整页**（会让切换、添加按钮变小难点）。保留 5 小时 / 每周两个大数字与进度条（易扫的核心），只收紧垂直留白，并让所有账号卡**统一高度**。
- “读取中”类文案原本凭 `signedIn && 无快照` 推断，导致永久显示；现按后端 `usageState` 区分。

## 静态修改（均在 App/ 内）

### 密度与结构（Views.swift）
- 账号卡统一高度 156pt（原 188 / 132）；内边距 14→12，主数字 30→28、副数字 23→22，分隔线 73→58。Header 图标 42→38，纵向内边距 12→10。
- 网格列 `alignment: .top`；所有卡同高，不再出现空卡悬浮。
- “添加账号”不再占一个网格格子：改为“账号 N 个”标题行右侧的小按钮（`AccountsHeader`），点击后在标题下内联展开名称输入（回车 / 添加 / 取消）。目标仍是低频入口，但保持可发现。
- 账号多于 4 个时滚动区高度为两行 + 一点露出的第三行（提示可滚动）；不再把添加卡计入数量。

### 空态与用量状态（按 `Profile.usageState`）
| 状态 | 无快照时 | 有快照时（底部一行） |
|---|---|---|
| loading | 小转圈 + “正在读取用量…” | “正在更新…” |
| notRequested / cached / loaded | “暂无用量数据” | 缓存 / “刚刚更新”（仅 `live`） |
| blocked | “未请求用量 · 保护检查通过后再读取”（中性色，不重复全局原因；悬停说明） | “未刷新 · X 前的缓存” |
| failed | “用量读取失败” + 简短原因（警示色） | “刷新失败 · 显示 X 前的缓存”（警示色，悬停显示原因） |
| 未登录 | “切换后，在 Claude 中登录” | — |

- 账号行：已登录但无邮箱时仅 loading 显示“正在读取账号信息…”，否则“暂无账号信息”；未登录仍为“尚未登录”。Header 复用同一函数 `accountLine`。
- 仅有缓存快照时不把缓存年龄冒充实时：“live”文案只在 `usageState == .loaded && live` 时出现。

### 语言入口
- 删除导入页右上角 EN 按钮（SessionTransferView.swift），不再直接赋值 `controller.language`。
- 新入口：主界面页脚新增“偏好”`…` 菜单，内含“会话导入页语言（仅导入页）”：中文 / English，绑定 `store.importLanguage` / `setImportLanguage`；控制器已订阅 Store，无需额外代码。
- 诚实命名：菜单标题和悬停说明都写明仅导入页；其余界面仍仅中文，没有“全 App 英文”暗示。默认中文。选在页脚是因为它低频、不新增常驻条、与既有页脚图标同级。

### CLI 卡（TerminalStrip）
- “存储暂不支持”→“暂未核验”，中性色（不再黄色警示），副文案“切换器暂无法核验；不代表终端有问题”（若后端已读到邮箱 / 档案则优先显示账号信息）。
- 新增 ⓘ 按钮，点击弹出 popover 显示完整技术原因（`detailHelp`），不再只靠悬停。说明文字明确不是终端损坏、无需注销 / 重新登录。
- 2026 QA 后压缩 popover：行内已显示的 `detail` 不再重复；只保留后端 `cliStatusDetail`（身份/组织未知、文件自动同步未适配等由后端给出，原样透传）、一句按状态区分的范围说明（订阅 / API 范围），以及末尾唯一一句“不代表已运行的 CLI 任务、不保护 CLI 进程”。相同行去重。不改后端状态；matched 仍只来自后端核验，不因账户 ID 相同而显示已核验。
- 三个账号时最后一行单卡可接受，不为填满添加装饰卡。
- 不把它显示为已同步 / 已登录；状态枚举与后端语义未改。

### Edit 菜单（新文件 App/ApplicationMenus.swift）
- 检查确认：AppDelegate 主菜单只有“打开 / 退出”，没有 Edit 菜单，因此 ⌘V / ⌘C / ⌘A / ⌘Z 的 key equivalent 无法走 responder chain 到文本框，这与 Codex 在假数据 App 中粘贴失败一致。
- 提供 `@MainActor ApplicationMenus.addEditMenu(to: NSMenu)`，仅添加标准撤销 / 重做 / 剪切 / 拷贝 / 粘贴 / 全选（responder-chain action，无自定义处理），重复调用不会重复添加。
- **未改 main.swift。Codex 需在 AppDelegate 主菜单构建处（`NSApp.mainMenu = applicationMenu` 之前）调用 `ApplicationMenus.addEditMenu(to: applicationMenu)`。**

5. 接入 Edit 菜单后，在搜索框与添加账号输入框验证 ⌘V / ⌘C / ⌘A / ⌘Z。
