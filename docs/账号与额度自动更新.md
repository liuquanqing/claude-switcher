# 账号与额度自动更新

日期：2026-11-01。基线：1.3.4，`d4721542548a69674ddea8fa546c2797d63f68b6`。本轮作为 1.3.5 发布，构建 `20261101.18.0`。设备安装与守卫连续性以独立更新回执记录为准。

## 问题与选择

1.3.4 每 300 秒自动重读官方 CLI 缓存。缓存没有新采样时，刷新动作不会更新额度，因此当前账号会长期显示“12 分钟前更新”。这是数据源未主动更新，不是界面倒计时没走。

用户选择：自动检查静默进行；主动刷新需要授权时可以授权。后台不能调用一个可能再次弹钥匙串授权的 CLI 命令来冒充“静默”。本轮保留手动官方 CLI 路径，后台改为已授权凭据的当前订阅只读查询；不刷新其他账号，不续期、不更改登录。

## 触发与频率

| 事件 | 本地身份与缓存 | 主动额度请求 |
| --- | --- | --- |
| 启动切换器 | 立即观察 | 缺少或过期时静默补查 |
| 后台时钟 | 每 15 秒观察当前档案、Desktop 登录标识、默认 CLI 身份及官方额度缓存 | Desktop 运行或面板打开：采样至少间隔 5 分钟；两者均无：15 分钟 |
| 打开面板、系统唤醒、Desktop 启停 | 立即观察 | 只补旧数据；连续事件合并，单档案自动请求至少间隔 60 秒 |
| 外部登录或配置模式变化 | 本地观察发现后重新确认身份，撤下不再匹配的旧“当前账号”和 CLI 一致结论 | 尽早查询新身份，仍遵守请求间隔与失败退避 |
| 本软件联合切换/同步成功 | 继续采用事务已经核验的身份 | 保留 1.3.3 的官方 CLI 即时补查，并记录请求时刻避免自动重复 |
| 底部手动刷新 | 现有官方 CLI 登录报告与网络门禁 | 仍调用官方 CLI；必要时系统授权，使用官方缓存原采样时间 |
| 额度窗口到期 | 不自动补成 100%，不编造重置时间 | 下一次观察补查；刚成功采样的已过期窗口不会每 15 秒重复查询 |

本地轮询只选取相关身份字段；额度缓存或主题等其他配置写入不会误判为换号。15 秒是调度目标，不是休眠期间、繁忙切换期间的实时保证。UI 相对时间仍由原有分钟时钟负责。

## 请求与失败边界

- 自动路径不启动 CLI 子进程。读取 Desktop Safe Storage 或默认 CLI 凭据时使用 `allowInteraction: false` / `LAContext.interactionNotAllowed`；权限不足保留缓存，不弹授权。
- 订阅 Desktop 使用其自身已确认的完整账号 UUID/组织 UUID 及对应有效 token。API 模式只允许默认 CLI 订阅身份与当前卡片完整匹配时查询该订阅，不读取 API 提供商密钥，不查询 API 余额。
- 请求固定为 `https://api.anthropic.com/api/oauth/usage` 的只读 GET。会向服务端呈现代理出口 IP；不承诺官方许可、零风控或代理切换时零泄露。直接 OAuth 与官方 CLI 的区别见 [风险记录](USAGE-QUERY-RISK.md)。
- 查询必须通过现有订阅额度网络/地区门禁。权限读取及门禁耗时后再次绑定 token；返回后再核对当前档案、模式、完整身份和 token。中途换号或轮换 token，旧结果不提交。
- 临时 URLSession 不保存 cookies 或网络缓存，不接受 HTTP 重定向。15 秒请求、20 秒资源超时。
- 429 尊重 Retry-After 数值秒或 HTTP 日期；缺省等待 15 分钟。其他失败至少等待 5 分钟，无快速重试。
- 失败只更新额度查询说明，不覆盖切号错误提示，不清空旧额度，不修改其采样时间。后台不自动授权、不自动续期、不自动同步 CLI，也不结束任何真实任务。
- 周额度独立解析，兼容没有五小时窗口的方案；缺失或无效数据保持未知，0% 是有效数据。

## 验证与交付

所有新增测试使用虚构账号、内存 HTTP 回应和临时目录。重点覆盖：5/15 分钟调度、打开/唤醒合并、外部原地换号、限流停等、网络未知不发送、请求前后登录变化、仅周窗口、坏响应保留旧采样、不同账号不串数据。

用户已授权将本机和 MBP16 的切换器更新至 1.3.5，并只重启切换器界面。安装器保留守卫文件与配置，不操作 Claude、CLI 登录、真实会话或代理网络。设备更新另行记录，不能用单元测试通过代替真实账号网络验收。
