# CLI 文件凭据备份与同步

2026-10-28。本轮不使用真实登录、会话、钥匙串或守卫做执行验收。

## 行为

- 软件内主动切桌面：沿用先确认身份、备份并回读、退出桌面、轮换目录、恢复CLI并回读的顺序。文件来源接入同一事务，不另写一套切号逻辑。
- 日常刷新及手动“重新检查”：只核验默认保存登录，不写认证。需要网络身份核验时仍先过原有网络与地区门禁。
- 与当前订阅桌面不同才提供同步，用户确认后执行；同步前备份原CLI，目标没有CLI备份则保留原登录并提示。确认的目标名固定，状态变化就停止。
- 只换自有`claudeAiOauth`和`.claude.json`的`oauthAccount`；MCP、API、项目和其他字段保留。既有终端进程不被终止，何时采用新凭据由CLI决定。

## 存储选择

| 观察到的材料 | 处理 |
| --- | --- |
| Keychain有订阅登录，文件无订阅字段 | 更新Keychain，文件其他字段不动 |
| Keychain条目不存在，默认文件有订阅登录 | 在文件原位置恢复，文件创建即0600；不擅自搬进Keychain |
| 两处订阅字段完全相同 | 同时更新两处；失败时只回退本次写入，不覆盖外部新登录 |
| 两处不同，或Keychain含现存条目而订阅仅在文件 | 来源冲突/不明，停止自动写入 |
| Keychain被锁定或拒读 | 不当作空条目，不猜测选文件 |
| 两处均无订阅字段 | 有Keychain条目时优先Keychain，否则保持文件来源；没有材料时沿用默认Keychain |
| 自定义目录、其他认证配置、不可读/损坏配置 | 不改写，留给官方CLI或原管理器 |

按账号的备份继续使用本工具已有的独立Keychain条目，兼容旧备份；没有新增明文备份库。备份拒绝或回读失败发生在退出/移动桌面之前。文件临时内容在0600文件中写入、刷新后原子替换；符号链接、非普通文件或不安全权限拒绝处理。

## 已验证范围

176项核心测试通过，使用临时目录、虚构OAuth字段、假远端身份和注入密钥仓库；覆盖文件往返、镜像一致更新、冲突拒绝、备份失败、双存储部分提交失败恢复、标记失败恢复、核验期间外部刷新、目标无备份、权限和符号链接等。真实Keychain ACL、用户真实A→B→A和真实会话均未用于验收。

独立官方Claude CLI只读审查发现两项P2：空订阅字段时的主存储选择，以及官方CLI目录不一致仍继续核验。已修正并回核；外部审查没有运行测试，不把其代码阅读当作实际验收。

官方依据：[凭据管理](https://code.claude.com/docs/en/authentication#credential-management)、[CLI状态命令](https://code.claude.com/docs/en/cli-reference)。官方文档说明macOS可回退到0600的凭据文件；两处材料冲突时，本实现选择停止，不声称仅凭文件存在即可判定CLI的实际来源。

本地默认材料一致不证明每个已运行CLI任务正在用同一账号，也不提供跨文件/Keychain的断电原子性。
