# 终端 OAuth 条：静默刷新交互

范围：`App/Views.swift` 中的 `TerminalStrip`，以及 `App/CLILoginController.swift` 中 API/未知模式分支的一句 `detail` 文案。不涉及账号网格、头部、保护设置等其他布局。

## 问题

每次打开面板都会触发整轮刷新，刷新开始时状态被清成 `unverified`，于是终端条反复闪成“登录待核验”，还多出一行灰色“核验登录”按钮，卡片高度跟着跳。

## 原则

1. 正常的后台检查用户不应察觉；只有真实结论变化才改变卡片。
2. 卡片显示的是**最近一次完成检查的结论**，检查进行中不替换。
3. 卡片上不常驻检查按钮；手动检查放进 ⓘ，需要时再用。
4. 不隐瞒真实错误，也不把未知说成通过；绿色只来自订阅桌面下的真实比较 `matched`。

## 卡片（常驻）

结构固定为：图标 ·「终端 OAuth」· 状态短词 · ⓘ，下面一行明细。只有在可以同步时才多出一行操作。

| 状态 | 状态短词 | 颜色 | 明细行 | 操作行 |
|---|---|---|---|---|
| unverified | 未核验 | 灰 | 档案·邮箱；无则“尚未完成检查”（`cliStatusCheckedAt == nil`）或“上次检查未能核验，原因见 ⓘ” | 无 |
| unverified + `cliStandaloneVerified`，桌面非订阅 | 身份已核验 | 灰 | 邮箱；无则“桌面无订阅账号可比较” | 无 |
| matched，桌面为订阅 | 已与桌面一致 | 绿 | 档案·邮箱 | 无 |
| matched，桌面非订阅（陈旧值） | 未核验 | 灰 | 桌面不是订阅模式，待重新检查 | 无 |
| different | 与桌面不同 | 橙 | 档案·邮箱 | 订阅桌面时：「同步到 X」 |
| needsLogin | 需要登录 | 灰 | 未检测到订阅登录 | 无 |
| otherAuthentication | 其他认证配置 | 橙 | 可能覆盖订阅 | 无 |
| unsupportedStorage | 暂未核验 | 灰 | 切换器暂无法核验；不代表终端有问题 | 无 |

- 所有状态都不显示“核验登录 / 重新检查”按钮。
- `cliStatusRefreshing == true` 时卡片内容不变，不显示“检查中”；「同步到 X」保持可见但禁用，避免整行出现又消失。
- 只有结论真的变成或离开 `different`（且桌面为订阅）时，操作行才出现或消失，高度变化是真实状态变化。

### 「身份已核验」

- 只读 `store.cliStandaloneVerified`（后端仅在远端完整核验默认 CLI 身份、且桌面不是订阅时置 true）。不根据邮箱、缓存或 `cliStatusDetail` 文本推断。
- 它表示“默认 CLI 订阅身份已核验，但没有可比较的桌面”，**不是**与桌面一致，也**不是**进程受保护；因此用中性灰，不用绿色，也不提供同步。
- 前端再加一道条件：仅在 `cliStatus == .unverified` 且 `desktopScope != .subscription` 时采用，桌面已回到订阅时不沿用。

### 陈旧 `matched`

后端在 profile 或 scope 变化时清零结论；前端仍防御：`matched` 只在 `desktopScope == .subscription` 时显示为“已与桌面一致”绿色，否则按未核验显示，不说与桌面一致。

## ⓘ 弹窗（按需）

依次显示：

1. 后端原因 `cliStatusDetail` + 该状态的范围说明（去重）+“仅针对默认保存的登录……”免责。
   - 身份已核验时：后端原因说明“已经远端核验、未检测 shell 环境和项目设置”，范围说明补充“桌面为 API 或模式未知，没有可比较的订阅账号；这不表示与桌面一致”，两句不重复。
2. 检查时间：
   - 有 `cliStatusCheckedAt`：“最近一次检查完成于 今天 14:32，以上为该次结论，不是实时状态。”；进行中再加一行“新的检查进行中，完成后更新。”
   - 没有：进行中为“首次检查进行中，完成后更新。”，否则“尚未完成过检查。”
   - 这里的时间只表示检查跑完，不表示认证成功；措辞不带“成功/通过”。
3. 底栏：“后台会定期检查，底部刷新也会检查。”+「立即检查」按钮。
   - 调用 `store.verifyDefaultCLI()`（只读，先走门禁）。
   - `controlsLocked`（`busy` 或 `refreshing`）或 `checking`（`cliStatusRefreshing`）时禁用；检查中文字为“检查中…”。

## 同步

只在 `different` 且桌面为订阅时提供。点击时冻结 `syncTarget = store.current`，确认框显示该目标；确认时重新校验 `canSync`、未锁定、**未在检查中**、当前账号仍等于冻结目标，否则提示“状态已变化，未同步”。调用 `store.moveTerminal(to:)`。

## 依赖的 Store 字段（均已在后端落地）

- `cliStatus`、`cliProfile`、`cliEmail`、`cliStatusDetail`、`busy`、`refreshing`、`current`。
- `cliStatusRefreshing`、`cliStatusCheckedAt`：`updateCLIStatus` 运行期间置 `cliStatusRefreshing`，结束时一次性发布结论与时间，不中途降级。
- `cliStandaloneVerified`：与其他结论同轮原子发布；`invalidateCLIStatus()` 清零，核验失败为 false。
- 失效机制：`cliStatusGeneration` + 开始时的 `current`；profile 变化或 `observeCLIStatusScope()` 观察到 `desktopScope` 变化时作废进行中的结果并清空结论。

## 后端与验证（Codex 提供）
