# 账号存储、3P 模式与会话迁移分析

日期：2026-10-27。状态：只读核查后的设计分析；不是迁移执行记录，不代表第三方项目或真实账号已经验收。本轮未运行历史迁移脚本，未改 API 配置。

local.5 后续更新：已实现生效 API profile 标记的只读匹配与白名单工具导航；仅识别配置来源，不代表实时代理或最后写入者证明。CLI 核验与恢复也已按后续外审补齐。本文其余章节保留研究当时的比较和取舍，当前实现状态见 [功能对比说明](功能对比说明.html)。会话迁移仍未启用。

## 优先级与当前决定

1. 最高优先：完成守护、订阅账号切换、前端收口与文档，保留真实验收边界。
2. API 模式只做轻量识别与工具跳转的设计，不在本轮复刻 Magpie 或 CC Switch，不自动接管模型、凭据或模式切换。
3. 会话迁移先核对历史脚本和数据边界，继续关闭产品入口。

当前订阅账号以整份桌面目录轮换为基线，不因本次研究立即改成身份文件快照。备份和历史恢复应作为独立设计，不能把目录轮换称为历史备份。用户常用 `Claude-3p` 和 Magpie 是必须保留的约束；API 路径不是应清理的重复安装。

## 不是“文件夹”与“快照”的简单二选一

两款已核对工具都把每个身份保存在文件夹里。区别是如何产生运行态：

| 方式 | 切换操作 | 优点 | 主要限制 |
|---|---|---|---|
| 整份桌面目录轮换 | 完全退出后把当前目录停放，再把目标目录移到活动路径 | 同卷主要是目录重命名；不必猜哪些桌面文件属于账号 | 默认没有活动目录的额外历史副本；桌面运行环境可能重复，各账号侧栏分别保存 |
| 整目录存档恢复 | 保存离开账号，从目标存档 clone/复制出活动副本 | 可以保留切入前的恢复副本；APFS clone 初始避免全量复制文件数据 | 多了捕获、恢复与提交步骤；不支持 clone 时要复制；需要正确处理过期登录状态 |
| 身份文件快照、共享工作状态 | 交换登录状态，保留机器、工作区和缓存 | 避免反复搬大运行环境，便于保持工作区 | 认证文件、机器状态和会话索引边界必须随版本维护，漏分新字段可能串身份 |
| 多目录并行启动 | 给不同实例指定不同 user-data-dir | 可以同时使用不同身份 | 不是当前的单活动账号轮换；实例、回调、VM 和更新兼容要另测 |

因此，独立身份配置是共同思路，**不能据此断言主流方案都在轮换整份文件夹**。目前没有统计采用率的证据。

YOURSJEYO 实现中的存档先移动当前目录，恢复用 `cp -cRp`，失败时回退 `ditto`；这是 clone/复制，不是 APFS 卷级只读快照。成功归档会移除临时 previous，不自动保留多个历史版本。当前目录轮换的异常回滚也不等于两次重命名、标记和钥匙串写入构成一个跨存储原子事务；断电恢复尚未验收。

## 本机已经存在的工作流

只读核对确认有两套数据根：

- `~/Library/Application Support/Claude/`：官方账号模式的数据。
- `~/Library/Application Support/Claude-3p/`：同一官方桌面应用的第三方/gateway 模式数据，用户经常使用。

目录存在、历史日志或安装了 Magpie，都不能证明当前运行会话正在走 API。配置状态和运行状态需要分开；配置只在启动时应用时，读回配置不能代替运行确认。

### 数据需要分层

| 层 | 典型位置或内容 | 处理原则 |
|---|---|---|
| 模式选择 | 两个数据根的 `claude_desktop_config.json` | 与 Magpie/CC Switch 的所有权协调；不能被旧账号档案无意覆盖 |
| 登录身份 | 官方模式的 OAuth、cookies 和相关存储 | 每个订阅账号独立保存；识别归属后再备份，不把读取失败当空登录 |
| API 提供方配置 | `Claude-3p/configLibrary/`、工具自己的配置 | 保留给 Magpie 或 CC Switch 管理，不复制密钥进本项目 |
| Code 会话侧栏 | `claude-code-sessions/<account>/<org>/local_*.json` | 是每账号/组织的索引，不是全部聊天原文 |
| Code 历史原文 | 当前脚本使用共享 `~/.claude/projects/.../*.jsonl` | 本机索引迁移一般只检查存在性，不复制或重写原文 |
| Cowork/VM/运行状态 | VM、worktree、缓存、连接器等 | 不能把 Code 索引规则无差别用于 Cowork；保持未识别数据不动 |

这不是全盘或进程安全隔离。桌面目录、CLI 配置、钥匙串、项目文件和远端服务状态不在同一个目录中。

## 找回的现存迁移脚本

没有执行，以下仅为源码核查：

- `~/.claude/tools/sync-desktop-sessions.py`：支持源/目标数据根、账号/组织前缀和项目过滤；默认 dry-run，`--apply` 才复制索引并记录备份和收据。
- `~/.claude/tools/import-into-3p-*.sh`：订阅侧到 3P 的一次性封装，有历史分支另存处理；不改 JSONL 原文。
- `~/.claude/tools/import-3p-to-*.sh`：3P 回订阅侧的一次性封装，包含更新轮数、延续链和目标分支保护。

旧收据说明曾处理过一些条目，不足以证明所有会话都完整迁移。脚本内的真实账号/组织标识与会话名称不复制进本仓库。

### 可以复用的思路

- 原文与索引分开；先确认目标引用的 transcript 存在。
- 区分新增、更新、延续链和目标领先，避免简单按文件时间覆盖。
- 尊重归档、删除标记；覆盖前备份；保留源文件；输出可回溯收据。
- 目标桌面应用完全退出后再写索引，完成后重新打开确认。

### 不能原样产品化的地方

- 一次性封装硬编码了历史账号、组织和特定分支；不能作为当前身份的权威来源。
- 通用脚本在未指定组织时偏向条目最多的目录；产品中有歧义就必须明确选择。
- 通用脚本与反向封装的分支判定不完全一致。通用的“源轮数更大即可覆盖”需要补同链验证，不能覆盖无关 fork。
- 旧脚本的直接 `copy2`、异常处理和目标存活检查需要重审；不能仅因曾使用就认定能安全处理新版本。
- 新版索引可能含账号专属连接器、远程控制、计划任务等字段；哪些保留、剥离或重建必须用新格式夹具验证。
- 当前仓库的索引原型只通过 10 项隔离测试，没有覆盖以上完整跨模式流程，仍不启用。

## 新增的一次性索引重置案例

用户另提供了“等待桌面退出 → 备份并移走目标索引 → 从停放档案重建列表”的脚本。本轮只读核查，未执行用户的后台命令或 apply。它仍只处理侧栏索引，不复制 JSONL 原文；与追加复制的区别是会先移走目标列表。

在虚构目录的计划复现中，确认了三项边界：省略组织时可能选中与重置目录不同的组织；源轮数更多时可覆盖缺乏延续链证据的条目；清理前的 dry-run 不等于清理后的重建计划。退出后等待期间重开桌面、源/目标档案路径变化、清理后导入失败的恢复也需要产品级设计。

完整案例与独立审查见 [审查综合稿](../research/R-20261027-003-improvement-review.md)。Claude CLI 在用户完成登录后恢复并完成静态外审，Runner 校验为 complete；外审不替代真实迁移验收。该次实际收据目标与脚本指定目标相符，不能把多组织风险写成该次已发生的故障。迁移产品入口继续关闭。

## Magpie/CC Switch 的最小接入契约

用户需要的是状态识别和入口，不是新一套 API 模型管理器。

### 读取与显示

- 只读模式字段和当前 applied profile，确认“用户配置是否为 3P”。
- 只在当前应用的 profile 有可信工具标记时识别来源；不能因为工具已安装、目录存在或端口恰好相同就判接管。
- 显示“配置：API · Magpie”“配置：API · CC Switch”或“配置：来源未确认”；官方模式和冲突/缺失状态分别呈现。
- 这里识别的是当前配置匹配哪个工具，不能证明最后是谁写的、网关健康或运行进程已经应用。无法确认就保留未知。
- 不展示、保存或日志输出 API key、私有网关地址、真实账号标识。

### 点击行为

仅从固定工具白名单打开已安装的 Magpie 或 CC Switch。不存在就提示，不从配置文件执行命令或任意 URL。不切模式、不改模型、不重启 Claude、不动原文与索引。

本机 Magpie CLI 帮助已确认能查看 `claude-desktop` 与 provider 字段；修改/default 命令本轮没有执行。公开 adapter 表明它会同时维护模式配置和 3P 的 configLibrary，因此不能在不了解所有权时替它直接写 JSON。

### 与守护主线的边界

本轮的新守护以 Claude 主要域名的出口检查及桌面进程急停为核心。**正式启用前仍需核对 1P/3P 的进程与策略范围，不能声称它已兼容用户的 Magpie/API 使用方式。** API 路径可能走其他上游，不能直接把 Claude 域名探测等同于 API 上游健康。

只读检测入口不会自动解决这个范围问题，也不会在本轮偷偷改变急停规则。新守护尚未部署，真实 1P/3P 混用验收为 NOT_RUN；现有 API 配置保持。
