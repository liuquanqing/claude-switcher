# 专用本地代理端口：隔离验证与接入边界

2026-11-01（Asia/Singapore）。本轮由 Codex 实现、审查；不调用 Claude 或 Kimi。用户范围：验证能否阻断 Claude/CLI 已有及新连接、保留其他软件联网；不动个人网络、守卫、账号或会话。

## 结论分层

**专用端口可以成为可撤销的数据通道，但单独配置一个代理端口不等于防直连。** 必须有另外一层持续约束，使目标无法绕过它。是否能覆盖现有的任意桌面/CLI 实例，取决于这层约束和首次迁移流程，不能从代理机制通过直接推出。

本轮仅在一次性 macOS runner 建立环回服务和新启动测试进程，不加载 PF、不改系统代理/路由、不安装 LuLu 或系统扩展。运行官方客户端时使用临时空白 profile 与虚构凭据；模型服务只在本地假端点。

```text
目标进程（若已被强制限定入口）
      ↓ 仅允许指定 loopback 端口
CONNECT 网关：默认拒绝、新鲜许可、数据转发前检查、撤销时关两端 socket
      ↓ 固定测试上游，无 DIRECT 回退逻辑
假上游转发器 → 环回服务

无关进程 ─────────────────→ 同一环回服务（旧/新连接正向对照）
```

## 分别验证什么

1. **数据通道。** `gateway.py` 为仅限假目标的 CONNECT 原型，不终止/解密业务 TLS。控制通过继承的私有 socketpair 传递假国家、隧道状态、路径版本和单调时钟采样。没有真实国家查询；测试 TTL 不是产品检测周期或阻断 SLA。
2. **撤销。** 代理端口仍可监听，但无许可不建立上游；撤销时关闭所有已登记的客户端/上游 socket。每次转发前再次查许可；过期执行器恢复时不能将排队旧数据继续转发。已交给网络的在途数据不能被撤回，测试用截点后的新标记和截点前的双向成功对照区分。
3. **故障。** 假 JP、未知国家、TUN 状态失效、真实测试上游停止、路径变化、许可过期、控制端 EOF、网关 SIGKILL、SIGSTOP/恢复，分别观察旧连接、新 CONNECT、服务器主动推送和无关程序旧/新连接。
4. **绕过反证。** 不设强制入口时，目标忽略代理直接访问同一服务的 IPv4/IPv6 TCP/UDP 能成功。这些预期漏洞不能计作保护能力通过。
5. **进程约束实验。** 一次性 Mac 用系统 `sandbox-exec` 给新启动的虚构进程加网络限制：只允许指定本地端口。它拒绝目标的直接 TCP/UDP 和子进程绕过，同 UID 的未受约束程序不受影响。该工具已被 Apple 标记 deprecated，不能据此直接选为公开产品稳定后端；更不能追溯约束此前已在外部运行的进程。
6. **官方 CLI。** 下载固定版本 2.1.314 并匹配官方 manifest 摘要，进程运行在上述实验约束下。临时 CA 只通过该子进程的 `NODE_EXTRA_CA_CERTS` 信任，系统信任库不变，TLS 校验不关闭。两个地址族分别建立真实 TLS/SSE、接收主动推送，再验证撤销、新请求拒绝和新证据恢复。API key 与模型内容全为虚构，不验证订阅登录。
7. **官方桌面。** 使用固定官方包 1.0.2768，校验包与应用签名，仅在临时目录展开，未安装到系统。以空白 profile 和 `--proxy-server` 检查 CONNECT 及后续 TLS ClientHello、撤销隧道、新 CONNECT 拒绝。不伪造 Claude 域名证书、不登录；完整 TLS/已认证 SSE/WebSocket 仍未验收。它不是最新版声明或当前个人版本的兼容保证。

## 为什么不能把旧 CLI 自动算进来

官方文档说明，shell 中的代理环境变量在 CLI 启动时读取，正在运行的会话不会因后来修改环境变量而更新。后台 supervisor 的环境继承及 `settings.json` 作用域也不同，不能只包装普通 `claude` 命令就声称覆盖后台代理。[官方网络配置](https://code.claude.com/docs/en/network-config)

因此启用完整方案需要两件事：

- 持续防绕过约束覆盖目标及其相关进程，既不能把整个 Terminal/Node/Python 都封锁，也不能漏掉用户直接启动的实例。
- 首次迁移时处置尚未经过网关的旧连接。新网关无法关闭一个从没经过它的旧 socket；不能只改环境变量或在界面显示已开启。用户未同意迁移时仍应显示这些实例未受保护。

这不是现在就要求用户关闭进程；本轮没有操作个人软件。实际接入方案还需明确原版 LuLu 静态规则、受支持过滤后端或受控启动如何承担该约束。不能靠被弃用的实验启动器跳过这道门。

## 上游约束同样必要

生产网关若接现有代理，必须确认它没有回退 DIRECT 的路径。网关应该通过同一上游核验出口，业务也使用同一路径；不能用主程序另一条出站探测代替。外部代理仍可能在两次核验之间改变出口国家，事件监听与短期许可不能使未知的服务端变化提前可知。

本轮的真实上游停止是环回转发器故障，不是 Shadowrocket 本体；没有读取节点配置或订阅。真实地理位置、上游协议、节点切换、DNS/系统代发流和第三方代理兼容仍 NOT_RUN。

## 产品状态

原型只实现固定假目标与有限 CONNECT，不支持作为实际通用 HTTP/SOCKS 代理交付。证据必须分别标记“代理内流量可撤销”“入口绕过已阻止”“客户端兼容”“任意既有实例覆盖”。实验 job 成功包含主动复现的绕过漏洞，产品接入保持 **HOLD**。

网络层确认阻断后提示；关闭桌面可选。关闭提示、取消退出都不恢复联网；任务进程可保留，但网络错误可能由客户端自身结束或重试任务，不能保证无损自动续跑。

没有改产品 App/Sources/build、发行标签、安装包、个人系统设置或守卫。实验代码和回执仅放独立研究分支。

### 当前可用结论

专用端口的数据通道设计具有实际可验证的撤销能力；受控 CLI 路径也取得了真实客户端证据。但**完整的“所有桌面与普通 CLI、包括之前已运行的实例，只断这些程序且无直连回退”尚未满足**。原型不能直接装进当前应用启用。下一门是桌面兼容的持续防绕过执行方式与首次迁移边界；不是继续缩短轮询或忽略启动失败。

### 2026-11-01 关于锁定 Shadowrocket/TUN 的补充

macOS 系统设置中的应用防火墙控制入站，不能据此阻止 Claude 发起 HTTPS。要求 Shadowrocket 和 TUN 在线只是一项启动检查，不等于在代理退出后仍存在出站拒绝规则。

若要建立“不走批准隧道就不能联网”的限制，需要持续有效的执行层，并验证它在 TUN 退出时不会跟着解除；还要处理代理建立外层连接的必要例外、IPv6、旧流和睡眠/重启。整机范围较易表达这种规则，但影响其他软件；按 Claude/CLI 限制仍需可靠应用归属。两种范围不能互相冒充。

Shadowrocket 的官方 2.2.93 发布说明提到 Enforce Routes，但这不足以证明其当前 macOS 配置具备退出/崩溃后仍阻断的语义。本轮未读取或修改个人 Shadowrocket 配置，也未借 iOS 或其他代理软件的行为推断它已通过。需要验证实际版本、开关与各类断开场景后才能声称只断网不直连。
