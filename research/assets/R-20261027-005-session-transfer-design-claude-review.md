# 会话迁移方案设计审查

范围:只读了 `REVIEW_SCOPE.md` 和 `会话迁移方案.md`。没有执行命令,没有访问真实账号或会话,也没有跑过任何测试。下面是对设计草案的静态判断,不表示产品可以启用。

## 总体判断

**设计可保留的部分:**
- 沿用原版窗口,默认只新增,更新由可见开关开启。
- 不碰 JSONL、认证、API 配置和 CLI。
- 先备份再逐文件替换,并明说不是跨文件原子事务。
- 恢复遇到外部修改时保留新数据,不强行覆盖。
- 「路径只是定位手段,不是身份」这一原则(L138)。

**需要修改的部分:** 见下面 6 条。

## 主要意见

### 1. P1:「续接链包含目标引用即更新」会把分叉当成续接(规则 L119–121,L125)
- **现实触发:**
  - 同一个会话在 A 空间先聊到第 50 轮。
  - 用户在 B 空间从该会话续接,B 的链包含 A 的引用。
  - 之后 A 又继续了。
  - L119 的条件只看「源链包含目标当前引用」。它分不出「源是 A 的后续」还是「源从 A 的旧点分出去」,于是会用 B 的引用覆盖 A 较新的进展。
- **同类问题:**
  - 默认只新增模式下,L116 的「目标无该索引」没写按什么判断。若按文件名,而目标已经有同一逻辑会话的另一个文件名(链上相关),新增就会造成重复项。L125 只在计划阶段提了一句,没进规则表。
  - 「列表进度更完整」(L118)没定义比较哪个字段、平局或互有领先怎么办。
- **跨 CLI 段轮数语义:**
  - 「新段 2 轮、旧段 120 轮」的结论(L168)方向对。
  - 但需要明写:轮数只在相同 `cliSessionId` 内比较,跨段只看链。
  - 链判断需要「目标当前段在分叉点之后没有推进」的证据,否则按分叉处理。
- **最小修订:**
  1. L119 加条件:目标当前引用必须是源链中的上一段,并且目标在该段没有超出源所记录的接续点。判断不了就归入「需处理」。
  2. 把「逻辑会话是否已存在于目标」的判定放进新增行,默认模式也适用。
  3. 同段比较只在字段可比时跳过或更新,互有领先、不可比一律不覆盖。
- **产品取舍:** 不需要。这是保守方向的规则收紧。

### 2. P1:订阅/API 空间与 namespace 的身份约束(L72–75,L108,L138,L125)
- **做得对的地方:** 「namespace 只能说明本地空间,不是已认证的云端账号」(L75),以及不按条目数猜(L74)。
- **缺口一:标签的来源**
  - `Personal · 订阅`、`Business · 订阅` 是本工具的档案名和本地目录。
  - 「配置匹配 Magpie」(L72)与 L108 的「匹配已确认」都来自本地配置。
  - 文档没说这些标签的依据是什么、不能证明什么。读者容易把它们当成登录证明。
- **缺口二:组织的选择**
  - L74 只规定「多个 Code 空间必须显式选」。
  - L125 却说一个端点下有多个组织。
  - 目标有多个组织 namespace 时由谁选、预览如何绑定,没有写。
  - 原版「选条目最多」的做法已在 L46 被否定,但没有替代规则。
- **缺口三:跨边界提示**
  - 订阅 A 到订阅 B,或订阅到 API,会把标题和工作目录带进另一个账号或网关的本地空间。预览没有提示这一点。
- **最小修订:**
  1. UI 和文档统一把这些标签写成「本地标签,未验证登录」。
  2. 多组织时,目标组织在第一步必选。预览里同时展示组织 namespace 的简短标识和「目标已有 N 条」,但不作为默认选择依据。
  3. 预览加一行:「将把标题和工作目录写入另一个账号/模式的本地列表」。
  4. 「匹配已确认」写明由什么确认,并声明它只决定能否打开原管理器,不决定能否复制。
- **产品取舍:** 提示文案需要。其余不需要。

### 3. P1:预览与退出桌面之后的复核不一致,且「CLI 保持运行」没有证据(L95,L140–141,L93)
- **现实触发(三处):**
  - **退出后的复核几乎必然不通过。**
    - 桌面退出时回写索引(L140 自己承认),所以退出前算好的计划大概率与退出后不同。
    - 用户已经点了「退出并复制」,结果却回到预览,而桌面已被关掉。
    - L93 的「取消不产生退出」只覆盖了退出前。
  - **失效范围前后矛盾。**
    - L141 写「使受影响计划失效」,L139 写「全量复核本批前提」。
    - 源桌面运行时源索引持续变化。若源索引任何变化都使整批失效,预览会频繁作废。
  - **「CLI 任务保持运行」(L95)是未证实的断言。**
    - 如果桌面 Code 页的 CLI 是桌面的子进程,正常退出可能会终止它。
    - 这与「不停止 CLI 长任务」(L65)直接冲突。
- **最小修订:**
  1. 复核只比较每个已选项的校验值和动作类别,不比较整个目录。
  2. 退出后的差异只显示变化项,并写明「桌面已退出,可直接重新预览」。
  3. 退出确认文案写明:退出后会重新核对,可能需要再确认一次。
  4. 退出需求只针对目标桌面;源只读,不应要求退出。
  5. 在有夹具证据前,把「CLI 保持运行」改成「不主动停止 CLI」。
  6. 若探测到桌面持有子 CLI,则禁止「退出并复制」,只提示用户自行处理。
- **产品取舍:** 第 6 点需要。
- **源与 JSONL 未触及:** 文档层面一致(L64,L141,L151)。这需要在隔离写入段用字节比对来证实。

### 4. P1:备份、提交与恢复的边界缺少「中断」状态和撤销时的桌面处理(L142–151,L98–106)
- **文档如实的地方:**
  - 「非跨文件、进程、掉电的原子」(L146)。
  - 恢复前检查「仍符合写后状态」。
  - 外部变更不强行覆盖(L144)。
- **缺口一:崩溃或掉电**
  - 收据状态只有成功、未开始、完整恢复、未确认恢复(L148)。
  - 进程在第 N 项写入中途被杀或断电后,没有任何标记告诉下次启动「上次没做完」。
  - 用户会看到既没有收据也没有恢复入口的半成品。
- **缺口二:撤销时桌面可能正在运行**
  - 桌面运行时,它缓存的索引会在退出时回写,可能把撤销再覆盖掉。
  - L151 只说「查看备份不退出」,没有说撤销是否走同样的退出确认。
- **缺口三:撤销的粒度**
  - L151 说「索引仍与写后状态一致才允许还原」,没说是整批还是逐项。
- **缺口四:X 的含义与保留期**
  - 默认只新增时覆盖项为 0。L91 的「自动备份 X 条旧索引」应处理 X=0 的情形。
  - 备份内含标题和路径,保留期、清理方式没有说明。
- **最小修订:**
  1. 首次修改前,在清单中写入「进行中」标记。完成后改为「已完成」。
  2. 下次打开时,发现「进行中」就显示「上次操作未完成」,并走同一个条件恢复。这只是一个标记文件,不是状态机。
  3. 撤销走和复制相同的退出确认。
  4. 撤销逐项判断,未改动的项还原,有新进展的项保留并列出。
  5. X=0 时文案改为「没有覆盖旧索引,新增项可撤销」。
  6. 备份保留策略待定。可以先写「不自动删除,提供查看位置」。
- **产品取舍:** 第 6 点需要。其余不需要。

### 5. P2:两步内的交互契约不完整(L82,L93,L95,L108,L151)
- **现状:** 步骤一是选择,步骤二是预览。但「退出并复制 / 取消」(L95)读起来是第三个对话框。恢复和撤销入口在窗口关闭后找不到。
- **按钮计数不一致:** 「预览复制 N 项」(L82)的 N 是已选数,预览页的「复制 N 项」(L93)是可执行数。两个 N 可能不同。
- **最小修订:**
  1. 把退出确认并入预览页的主按钮:需要退出时按钮就是「退出并复制 N 项」,旁边「返回修改」。不再单独弹窗。
  2. 备份预览是预览页内的折叠区,不是新页面。
  3. 结果页放「查看备份」和「撤销」。主窗口底部放一个常驻的「上次复制」链接,指向最近一次收据。
  4. 预览页的 N 明确写成「新增 a + 更新 b」,和已选数分开显示。
- **产品取舍:** 第 1、3 点需要。

### 6. P2:有些行为只有夹具能证明,文档却写成既定事实(L112,L129,L132,L179)
- **现状:** 文档在 L112 和 L132 已说明这一点,但字段处理一节(L129–131)仍把一批键名写成清理清单。
- **最小修订:** 在字段处理开头加一句:「以下键名是待夹具确认的候选,不是完整清单」。
- **产品取舍:** 不需要。
