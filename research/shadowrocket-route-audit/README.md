# Shadowrocket 强制路由与断开防直连核对

2026-11-01（Asia/Singapore）。Codex 自行核对，不调用其他审查模型。用户要求在隔离环境验证，个人网络、守卫、登录和会话保持不动。

## 当前结果

**单开“强制路由”不能据此宣称 VPN 断开后不会直连。“包括所有网络”是另一个选项，其平台语义更接近目标，但 Shadowrocket 本体尚未实测。**

| 选项 | 已确认的含义 | 当前不能推导出的结论 |
|---|---|---|
| 强制路由 / Enforce Routes | Apple 的 `enforceRoutes` 将包含路由约束到 VPN、排除路由约束到主网络，并优先于普通路由表和应用自身的接口选择 | 不是承诺整个 VPN 退出后仍有持久防火墙，也不保证代理内的 DIRECT 规则不会直连 |
| 包括所有网络 / Include All Networks | Apple 规定多数流量经隧道；文档说明 VPN 离开 connected 状态时丢弃流量，存在指定系统流量例外 | 不能直接替代具体 Shadowrocket 版本、手动关闭、配置禁用/移除及升级时的实测 |
| 始终开启 / Always On | 本机应用包有此 UI 选项；未核对实际生效配置 | 不能把自动连接/重连假定为重连期间没有出站空档，也不能当作受 MDM 管理的系统 always-on VPN |

Apple 同时说明：启用 `includeAllNetworks` 后会忽略 `enforceRoutes`。两个选项同时打开不等于两层独立保护。全设备路由约束也不等于“只影响 Claude 和 CLI”。

## 隔离本体验证的前提

需要一台独立 Mac，或已能运行授权 Shadowrocket 的 macOS 虚拟机。使用软件官方签名版本，不要求自建 Network Extension 的开发者证书，但仍需该隔离环境有正常安装、授权和 VPN 批准条件。本轮没有购买软件、上传已购 app 或创建虚拟机。

用户已明确确认暂时没有独立测试 Mac 或 macOS 虚拟机，本轮只完成官方语义核对和隔离测试方案；在具备环境前，运行验证保持 **NOT_RUN**。不把开源代理、人工 utun、PF 或逻辑模拟的结果代替 Shadowrocket 本体。

若使用当前 Mac 上的虚拟机，宿主仍开着 Shadowrocket 可能掩盖虚拟机的直连：只看服务端看到的公网 IP 会误判。必须在虚拟机自己的底层 vNIC 抓包，使用可区分的代理通道与直接通道，并确保实验不调整宿主代理或路由；无法保证这些条件时不使用该拓扑。

## 有环境后先跑的最小矩阵

### 配置对照

| 组 | 强制路由 | 包括所有网络 | 用途 |
|---|---|---|---|
| A | 关 | 关 | 记录普通路由基线，作为直连可达的负向对照 |
| B | 开 | 关 | 单独验证强制路由，不能用 C 组结果代替 |
| C | 关 | 开 | 验证 Apple 所述丢弃语义在该 Shadowrocket/系统版本是否成立 |
| D | 开 | 开 | 在 C 有效后才核对组合；不预先假设更强 |

测试必须记录 OS/CPU、Shadowrocket 精确版本、实验开关与排除项，不能仅看 VPN 图标。代理节点用本地可控假节点与虚构凭据，客户端向受控服务发送唯一标记，不登录 Claude。

### 故障必须分开

1. 节点失效，TUN 仍存在：停假节点后分别测旧流与新流；Claude 对应实验规则只能代理，不能悄悄回退 DIRECT。
2. 隧道扩展意外退出：仅终止隔离机里已确认的 tunnel provider；记录是否自动重启、重启间隔内是否有物理直连。
3. 主界面退出：确认 TUN 是否实际消失；关闭窗口不能冒充停止隧道。
4. 手动断开 VPN：与意外崩溃分开，记录普通断开是否等价于禁用/移除配置。
5. 禁用/移除实验 VPN 配置：如本轮确实覆盖该场景，应单独验证，不能把 reconnect 的文档语义自动套用。
6. 睡眠/唤醒、网络切换与重启：只在前面最小矩阵成立后扩大，所有操作仅在隔离设备内进行。

每种先做 IPv4/TCP 正向与故障对照；未观察到真实健康传输不能算通过。存在直连反例时先停止扩大并记录。最小矩阵通过后补 IPv6、UDP、主动服务端推送、已有连接与恢复。

## 判定方式

- 客户端回包、服务端收到的唯一标记和底层接口抓包一起核对。界面显示断开、请求报错或节点超时本身都不是“未发出去”的证据。
- 先证明已建立双向连接，再触发故障；观察故障截点之后的新标记与新连接尝试。已经发出的在途包不能被撤回，须与故障后继续发送区分。
- 排除本地网络、APNs 等配置例外，按预期分别测；不能用明确排除的本地服务可达来断言所有公网保护失效，也不能把例外当成所有流量已锁定。
- 若 C 组导致全设备业务流量断开，应如实记录影响其他软件。它可能满足整机防直连，却仍不满足用户优先的应用级选择性目标。
- 恢复要有正向对照；失败配置、隧道未就绪、抓包未启动或无法定位 provider 均不写通过。

当前不发布新保护能力，不合并进产品。下一门是确认隔离运行环境，随后用 Shadowrocket 本体取得矩阵证据。
