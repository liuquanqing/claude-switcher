## 新提供的迁移案例

这是一份一次性的**目标侧栏索引重置**：

1. 等待标准路径下的 Claude Desktop 主进程退出，再等待 8 秒。
2. 完整备份目标组织目录的 `local_*.json`。
3. 移走目标索引，只保留指定的当前会话索引。
4. 从另一份已停放的桌面档案调用通用同步 helper，按其规则选取条目并复制索引。
5. 输出收据与计数，之后由用户打开桌面检查。

脚本不复制 `~/.claude/projects` 下的 JSONL 原文；helper 只检查引用的原文是否能在约定路径匹配。重置侧栏与保留原文是不同的数据层。个人一次性脚本可以依赖已经人工确认的档案、账号、组织及保留条目；产品入口必须把这些前提显式化。

只读日志显示较早版本因变量展开出错而终止，后续修正版完成并返回 rc=0。当前副本的变量展开已经修正；不能把旧版本错误继续算作当前缺陷。退出码与条目数量不证明所有会话在桌面打开后均可用。

## 主会话已复现的计划边界

以下只使用脱敏 helper 和临时虚构目录，调用默认 dry-run 规划；没有 apply、真实进程操作或真实迁移。

两份 shell 原文件通过 `bash -n` 语法检查，Python helper 通过 AST 解析；这些检查不执行原脚本，也不能证明运行安全。

| 输入 | 实际规划结果 | 产品含义 |
|---|---|---|
| 目标账号有多个组织；预定重置组织只保留一条，另一组织条目更多 | 未指定组织时，helper 选择另一组织 | 清理目录与导入目录可能不同；先明确选择账号和组织并固定计划 |

| 目标同名索引确实存在，但 JSON 损坏不可解码 | helper 报不可读，同时将源条目规划为新增；虚构文件保持未改 | 外审指出后由主会话追加复现；新增/覆盖分类须保留物理存在及不可读状态，不能绕过覆盖备份 |

这些复现证实脚本当前的规则，不代表真实迁移安全测试通过，也不是 Claude 的审查意见。

## 待独立审查核验的设计问题

1. **重新打开的时序。** 等待退出后还有 8 秒空档，执行前未再次检查。用户在这段时间重开桌面，或者切换器退出后自动重启，都是现实触发；一次性脚本不宜原样接入切换事务。
2. **档案和组织绑定。** 当前活动目录与停放目录会随账号切换而移动；任务发起时与真正写入时要确认仍是同一来源/目标，不能只记一个会变化的路径和短前缀。
3. **先清理后的失败。** 原脚本有备份，但 helper 若解析失败、复制失败或无可复制条目，目标侧栏已被移走；没有自动恢复的完整提交过程。应清楚区分“可手动从备份恢复”和“操作已自动回滚”。
4. **两种产品动作。** 普通追加复制保持目标现有列表；重置则明确展示将移走的目标索引、保留项与重建计划。不能用同一个模糊的“复制会话”按钮承载两种意图。
5. **索引格式边界。** 当前过滤归档/删除、检查原文存在性的思路有价值，但仍要核对新版字段、会话链和账号专属连接器等数据，不能仅凭完整 JSON 复制就认定跨账号兼容。

是否采用预先规划、暂存与恢复、身份再次确认等改进，要基于这些具体失败输入确定最小范围；本轮没有增加锁、自动重试或后台迁移任务，也未修改用户脚本。

### 建议保留与升级的范围

保留目录轮换及普通异常回滚、原生 Keychain 更新、每档案独立备份、读写失败停止。CCSwitcher 的 CLI 生命周期细节值得选择性借鉴，无需改成其整库单条备份、先删后加或后台直接刷新方案。

优先升级三项：**切换前核验、身份与备份配对、恢复后确认**。预检可以把可发现的失败移到桌面变动前，但不会令目录、钥匙串、文件和其他运行进程变成一个原子事务。旧 CLI 会话回写、过期刷新、同邮箱不同组织、缺目标登录、授权被拒等仍需隔离与真实场景分别验证。

原版曾成功切换的用户经验已记录。新版当前没有覆盖安装，用户新完成的 CLI 登录只为本轮审查恢复了调用能力；没有因此自动验证原版各档案备份或新版 A→B→A 恢复。

### 未采纳为默认改动的建议

- 不自动放宽“失败/未知即拦截”的既有策略。连续两次失败的缓冲会改变保护时效，需明确取舍。
- 不用 `security` 子进程或先删后加来追求少弹窗。
- 不在来源不明时盲信 token 指纹、邮箱或上次选择标记。
- 不把 `auth status` 当成绝对只读本地检查，不在未过网络门禁时自动调用。
- 不恢复迁移产品入口，也不改动用户已在使用的真实脚本。

本轮完成的是外审与采纳分析，没有实施上述升级，也没有执行真实登录切换、守卫部署或真实迁移。正式部署仍需解决 1P/3P 范围、CLI 前置核验等阻塞并完成真机验收。
