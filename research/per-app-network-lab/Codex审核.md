日期：2026-11-01（Asia/Singapore）。审查由本聊天的 Codex 完成，**未调用 Claude、Kimi 或其他外部审查模型**。这是作者侧代码与证据复核，不冒充独立平台验收。

结论：**继续 HOLD，不接入产品。** 本轮可以确认 PF 用户级规则不满足选择性要求；仍不能确认“只断所有 Claude/CLI 的网络且不影响其他软件”已经实现。云端实验成功与保护需求通过分别记录。

## 本轮查到并修正的实验问题

## 接入前仍阻断的实质问题

1. **没有实际流量分类器。** `AuditTokenBridge` 取得的是代码签名元数据；`SecCodeCheckValidity` 成功、签名标识相同，都不等于已验证可信发布者、Claude 归属或子进程关系。不能凭名字、路径、同 UID 或全部 Node/Python 来宣称保护所有 CLI。macOS 真实 `NEFilterFlow` 的来源 app/process、代发流、DNS 与代理外层归属均未测。
2. **已有连接撤销只是 API 编译探针。** `update(flow, using: .drop(), for: .any)` 没有在本候选中真实执行，不存在“网络已断”的运行回执。需看实际双向数据、服务端计数与无关应用对照；调用返回本身不构成阻断确认。
3. **执行器故障语义未验证。** 本轮纯策略程序及自身身份程序不是已部署的 Network Extension。暂停、崩溃、重启、系统尚未启动过滤器时的行为仍未知；不能因界面/控制器失联策略正确就推导执行器自身失效也安全。
4. **策略模型未连接系统执行层。** 54 项断言包括重复的 9 类条件及虚构归属标签，不证明发现了真实桌面、CLI、helpers、已有连接。`unresolved` 是未解决状态，不是可以直接返回给系统的安全 verdict；真实产品不能静默把它映射为 allow 或把其他软件全部断网。
5. **实验的状态清理不是按应用执行。** PF 规则仅覆盖实验端口，但 `pfctl -k` 按环回地址清状态，不能作为“不影响其他连接”的实现。当前只在可销毁 runner 执行，不得把整段实验脚本搬入个人 Mac 或产品执行器。

这些问题已由产品接入 HOLD 阻挡。本轮没有添加未知流的生产兜底、自动整机断网、额外常驻服务或新的用户权限。

## 保留的产品约定

网络阻断是第一优先级。所有已识别的 Claude/Claude Code 实例，无论由普通终端还是切换器启动，都应受控；已有连接和新连接都要覆盖。任务可留存，但不能因保留任务就漏掉其危险连接。

流程为：发现异常 → 执行并核实阻断 → 提示“重新检查并恢复”或可选“关闭桌面”。关闭提示或取消桌面的退出确认不解除阻断。无法确认阻断时应显示未确认，不能显示已安全；关闭桌面不是主要断网机制。

## 未触碰范围

没有修改产品 App/Sources/build、发行标签或安装包；没有操作个人代理、路由、防火墙、守卫、登录、钥匙串或真实会话。下一项有效证据应来自可激活目标过滤扩展的隔离 macOS 环境，而非个人电脑或更多纯策略断言。
